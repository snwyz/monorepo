## 1. 产品概述

### 1.1 产品定位

本产品用于规划多日自驾环线。用户在地图上连续标记路线控制点，系统完成点位排序、闭环路线生成、每日路线拆分、路线策略比较以及海拔分析。

产品只解决“路线如何规划和拆分”的问题，不承担旅游攻略、景点推荐、住宿安排、电量预测或实时导航职责。

### 1.2 核心价值

- 将多个地图控制点组织为一条完整环线。
- 根据天数、驾驶时间或行驶里程拆分每日路线。
- 比较高速与非高速等不同路线策略的距离、时间和收费差异。
- 用海拔剖面、累计爬升和坡度着色帮助用户理解路线地形。
- 将最终路线交给高德地图执行实际导航。

### 1.3 产品边界

| 本产品负责                     | 本产品不负责                      |
| ------------------------------ | --------------------------------- |
| 地图连续选点                   | 城市、景点、酒店等 POI 搜索与推荐 |
| 多点排序与环线生成             | 旅游攻略与沿途内容推荐            |
| 按驾驶时间或里程拆分每日路线   | 游玩时间安排                      |
| 路线策略比较                   | 住宿地点选择与预订                |
| 距离、时间、收费及道路信息展示 | 电耗、续航和剩余电量预测          |
| 海拔剖面与坡度分析             | 充电站推荐及可用性判断            |
| 保存、分享路线方案             | 实时语音导航与偏航重算            |
| 调起高德地图导航               | 自建导航系统                      |

## 2. 目标用户与使用场景

### 2.1 目标用户

- 需要规划多日自驾环线的个人用户。
- 已经明确大致经过位置，只需要安排路线顺序的用户。
- 希望控制每天驾驶强度的长途自驾用户。
- 关注山路、高海拔和累计爬升情况的用户。

### 2.2 典型场景

用户计划用 6 天完成一条自驾环线。他在地图上标记出发点和若干必须经过的控制点，设置每天最多驾驶 6 小时。系统优化控制点顺序、生成闭合路线，并在用户标记的控制点之间拆分每日路线。用户可以比较高速方案与非高速参考方案，查看每天的里程、时间、通行费和海拔剖面，最后保存方案或调起高德地图导航。

## 3. 核心用户流程

1. 创建路线方案。
2. 设置总天数及每日驾驶约束。
3. 在地图上设置起点并连续添加控制点。
4. 选择是否返回起点形成环线。
5. 生成并优化完整路线。
6. 系统按时间或里程拆分每日路线。
7. 用户调整点位顺序或指定每日结束点。
8. 比较每日路线策略及关键数据。
9. 查看路线海拔剖面和坡度分布。
10. 保存、分享或调起高德地图。

## 4. 功能需求

### 4.1 路线方案管理

#### FR-PLAN-001 创建路线方案

用户可以创建一份新的多日路线方案，并设置：

- 方案名称。
- 总天数。
- 是否为闭合环线。
- 每日约束类型：驾驶时间或行驶里程。
- 每日最大驾驶时间或最大行驶里程。

#### FR-PLAN-002 环线设置

- 开启环线后，终点必须回到起点。
- 关闭环线后，用户可以将最后一个控制点作为终点。
- 起点调整后，系统需要重新计算完整路线。

#### FR-PLAN-003 保存方案

- 保存控制点、点位顺序、每日拆分结果和路线策略。
- 保存后再次打开，应恢复上次规划状态。
- 路线重新计算时，应保留用户已确认的设置。

### 4.2 地图控制点

#### FR-POINT-001 地图连续选点

- 用户通过点击地图添加起点和途经控制点。
- 控制点按照添加顺序自动编号。
- 不提供城市、景点、住宿等 POI 搜索。
- 控制点可以设置简短自定义名称，但不附带旅游业务属性。

#### FR-POINT-002 点位编辑

- 拖动控制点改变其地理位置。
- 在列表中拖动改变访问顺序。
- 删除已有控制点。
- 在两个已有控制点之间插入新控制点。
- 将某个控制点锁定，避免自动优化改变其相对位置。

#### FR-POINT-003 点位状态

每个控制点至少包含以下状态：

- 起点。
- 普通途经点。
- 每日结束点。
- 终点。
- 已锁定点。

### 4.3 环线生成与顺序优化

#### FR-ROUTE-001 完整路线生成

- 系统连接全部控制点并生成完整驾车路线。
- 环线模式下，最后一个控制点之后继续返回起点。
- 路线无法连通时，应明确标记失败路段，而不是隐藏或跳过。

#### FR-ROUTE-002 控制点顺序优化

- 支持按照总驾驶时间或总里程优化控制点顺序。
- 已锁定控制点的相对顺序不得改变。
- 优化前应保留原顺序，用户可以撤销优化结果。

#### FR-ROUTE-003 局部重新计算

以下操作发生后，只重新计算受影响的路段和日期：

- 拖动控制点。
- 调整控制点顺序。
- 新增或删除控制点。
- 更改某一天的路线策略。
- 调整每日结束点。

### 4.4 每日路线拆分

#### FR-DAY-001 自动拆分

系统仅依据路线数据拆分每日路线，不考虑游玩时间和住宿位置。

支持两种拆分方式：

- 按每日最大驾驶时间拆分。
- 按每日最大行驶里程拆分。

#### FR-DAY-002 拆分规则

- 每日结束位置必须是用户已经标记的控制点。
- 系统在控制点中选择最接近每日约束的位置作为结束点。
- 尽量平衡各天驾驶强度，避免个别日期明显超出其他日期。
- 如果现有控制点不足以形成合理拆分，应提示用户新增或调整控制点。
- 系统不得为了满足拆分条件自动创建酒店、城市或景点点位。

#### FR-DAY-003 手动拆分

- 用户可以将任意普通控制点设置为每日结束点。
- 手动设置后，系统重新计算相邻日期。
- 用户可以取消手动设置并恢复自动拆分。

#### FR-DAY-004 每日路线列表

每天展示：

- 日期序号，例如“第 1 天”。
- 当日起点和结束点。
- 当日途经控制点。
- 总里程。
- 预计驾驶时间。
- 预计通行费。
- 红绿灯数量。
- 收费道路及收费里程。

### 4.5 路线策略与方案比较

#### FR-STRATEGY-001 路线策略

每一天可以独立选择：

- 高德推荐。
- 高速优先。
- 不走高速。
- 少收费。
- 大路优先。

具体可用策略以高德当前接口能力为准。

#### FR-STRATEGY-002 方案比较

系统支持在相同起点、终点和控制点条件下，对比：

- 高速方案。
- 非高速／国道参考方案。

每个方案展示：

- 总里程和预计驾驶时间。
- 预计通行费。
- 收费道路和收费里程。
- 红绿灯数量。
- 与另一方案相比增加或减少的里程、时间和费用。

#### FR-STRATEGY-003 表述约束

- 产品不得把“不走高速”表述为“全程国道”。
- 非高速方案统一使用“非高速／国道参考方案”名称。
- 应提示该方案可能包含省道、县道和城市道路。

### 4.6 路线数据汇总

#### FR-METRIC-001 全程汇总

整条路线展示：

- 总天数。
- 总里程。
- 总预计驾驶时间。
- 总预计通行费。
- 总红绿灯数量。
- 总收费里程。
- 每日里程和驾驶时间分布。

#### FR-METRIC-002 每日汇总

- 每天的数据独立计算和展示。
- 用户切换路线策略后，立即更新该日及全程汇总数据。
- 所有预估值均标注数据来源及“以实际道路情况为准”。

### 4.7 海拔与坡度分析

#### FR-ELEVATION-001 海拔剖面

每条每日路线生成距离—海拔剖面图：

- 横轴表示从当日起点开始的累计里程。
- 纵轴表示估算海拔。
- 标记起点、途经控制点、每日结束点和最高点。
- 全程视图可以汇总各日剖面，但每日剖面是主要展示方式。

#### FR-ELEVATION-002 地形指标

每天至少展示：

- 累计爬升。
- 累计下降。
- 最高海拔。
- 最低海拔。
- 最长连续爬坡里程。
- 分路段平均坡度。

#### FR-ELEVATION-003 路线着色

地图路线支持两种着色模式：

- 海拔模式：颜色表示路线所在海拔区间。
- 坡度模式：颜色表示下坡、平缓、一般爬坡、较陡爬坡和陡坡。

坡度模式作为默认模式，并必须提供清晰图例。颜色不能成为唯一的信息表达方式，应同时使用文字、数值或线型辅助区分。

#### FR-ELEVATION-004 地图与曲线联动

- 鼠标移动到剖面图某处，地图高亮对应路段。
- 点击地图路段，剖面图定位到对应距离。
- 联动提示展示累计里程、海拔、平均坡度和所属日期。
- 切换日期时，地图和剖面图同步切换。

#### FR-ELEVATION-005 用户教育

界面使用简短说明解释：

- 累计爬升是全部上坡高度之和，不等于终点减起点的海拔差。
- 坡度 5% 表示水平前进约 100 米、上升约 5 米。
- 连续爬坡表示路线在较长距离内总体持续上升。
- 高程结果可能受桥梁、隧道、高架和数据分辨率影响。

#### FR-ELEVATION-006 数据处理

- 海拔采样必须进行合理平滑，避免噪声夸大累计爬升。
- 桥梁、隧道和高架路段不能把地表高程直接表述为精确路面高程。
- 所有海拔和坡度结果统一标注为估算数据。
- 海拔数据缺失时，路线规划仍可使用，只隐藏相关地形指标并提示原因。

### 4.8 方案编辑与交互反馈

#### FR-EDIT-001 编辑反馈

- 用户编辑点位后，地图立即反映位置或顺序变化。
- 路线重新计算期间展示明确的加载状态。
- 计算完成前保留旧路线，避免界面突然清空。
- 计算失败时指出具体失败日期或路段。

#### FR-EDIT-002 撤销与恢复

至少支持撤销以下操作：

- 点位拖动。
- 点位排序。
- 自动优化。
- 每日结束点调整。

### 4.9 分享与导航衔接

#### FR-SHARE-001 分享路线

- 生成只读分享链接。
- 分享页面展示完整环线、每日路线、路线数据和海拔剖面。
- 分享访问者不能修改原方案。

#### FR-NAV-001 调起高德地图

- 每天提供“在高德中打开”入口。
- 当一天包含过多控制点或受高德 URI 能力限制时，按路段分别调起。
- 调起高德后，实时路况、语音导航和偏航重算由高德负责。
- 本产品不在页面内提供实时导航。

## 5. 页面与信息结构

### 5.1 路线规划主页面

建议使用单页面工作台结构：

- 顶部：方案名称、总天数、环线开关、每日约束和保存操作。
- 左侧：控制点列表及每日路线列表。
- 中部：高德地图、控制点和分段路线。
- 右侧：路线策略、方案比较和路线数据。
- 底部：可展开的海拔剖面及地形指标。

### 5.2 地图路线视觉规则

- 不同日期使用可区分的路线样式。
- 当前日期路线突出显示，其他日期适当弱化。
- 高速与非高速参考方案同时显示时，使用不同线型而非只依赖颜色。
- 路线基础描边与坡度色带分层绘制，保证复杂底图下仍然清晰。

### 5.3 响应式要求

- 桌面端为主要规划环境。
- 移动端优先满足查看、切换日期、查看数据和调起高德。
- 移动端不强求提供与桌面端相同效率的复杂拖拽编辑。

## 6. 领域模型

采用明确的领域命名，避免把地图渲染对象与业务对象混为一体。

| 领域对象           | 中文名称     | 职责                                       |
| ------------------ | ------------ | ------------------------------------------ |
| `RoutePlan`        | 路线方案     | 聚合整条多日路线及其设置                   |
| `ControlPoint`     | 路线控制点   | 表示用户在地图上标记的位置及其顺序         |
| `DailyRoute`       | 每日路线     | 表示一天内的起点、结束点、控制点和选定方案 |
| `RouteAlternative` | 备选路线     | 表示特定路线策略产生的一条可比较路线       |
| `RouteMetrics`     | 路线指标     | 距离、时间、费用、红绿灯和收费道路等数据   |
| `ElevationProfile` | 海拔剖面     | 路线采样点及累计爬升、下降和坡度信息       |
| `RouteStrategy`    | 路线策略     | 高德推荐、高速优先、不走高速等策略值       |
| `DaySplitRule`     | 每日拆分规则 | 驾驶时间或行驶里程约束                     |

建议划分以下业务边界：

- 路线方案域：方案、控制点、环线规则和版本状态。
- 路线计算域：顺序优化、路线策略、备选路线和路线指标。
- 每日拆分域：天数、驾驶约束及每日结束点。
- 地形分析域：海拔采样、平滑、坡度和剖面。
- 分享交付域：只读分享及高德导航衔接。

## 7. 外部能力与职责划分

### 7.1 高德地图负责

- 地图底图与地图交互。
- 驾车路线规划及路线坐标。
- 距离、时间、通行费、红绿灯和收费道路等可用数据。
- 高速优先、不走高速、少收费和大路优先等路线策略。
- 实际导航、实时路况和偏航重算。

### 7.2 本产品负责

- 控制点和路线方案管理。
- 环线业务规则。
- 控制点顺序优化。
- 每日路线拆分。
- 不同路线策略的统一比较。
- 海拔采样、平滑、地形指标和可视化。
- 路线保存、分享和导航衔接。

### 7.3 海拔数据

- 原型阶段可以评估高德 JS API 地形及单点海拔能力。
- 正式版本需要验证海拔数据的精度、稳定性、许可及服务级别。
- 如使用外部高程数据，必须解决合法授权、坐标对齐及中国境内地图合规问题。
- 不得将海拔数据进一步包装成电耗或续航承诺。

## 8. 异常与边界情况

系统应处理以下情况：

- 控制点少于形成路线所需的最低数量。
- 总天数大于可拆分路段数量。
- 没有足够控制点作为每日结束点。
- 某两个控制点之间无法生成驾车路线。
- 某种路线策略没有可用结果。
- 高德接口超时、超额或返回异常。
- 海拔数据缺失、突变或质量不足。
- 用户编辑期间旧请求晚于新请求返回。
- 控制点数量超过单次高德算路上限。

发生异常时应保留用户控制点和最后一次有效结果，不得因计算失败丢失方案。

## 9. 非功能需求

### 9.1 性能

- 首屏优先加载基础框架和二维地图，不默认加载 3D 地形。
- 地图、侧栏和剖面容器预留固定尺寸，累计布局偏移目标为 `CLS = 0`。
- 最大内容绘制应优先保证地图或方案骨架快速出现，避免被海拔计算阻塞。
- 海拔剖面和非当前日期路线延迟计算或按需加载。
- 点位调整后只重新请求受影响路段，避免重算完整行程。
- 对相同控制点和策略的有效结果进行合规缓存，以降低接口调用量。

### 9.2 稳定性

- 路线与海拔计算互相隔离；海拔失败不能阻止路线结果展示。
- 用户编辑状态应自动暂存，页面意外刷新后尽量恢复。
- 每次计算需要绑定方案版本，防止旧响应覆盖新结果。

### 9.3 准确性表达

- 距离、时间和收费均使用“预计”表述。
- 非高速方案不得承诺全程国道。
- 海拔、坡度及累计爬升均标注为估算值。
- 分享页面需要保留相同的免责声明。

### 9.4 合规与授权

- 地图、路线和相关数据的展示、缓存及分享应符合高德服务协议。
- 不隐藏或修改高德要求展示的版权、Logo 和审图信息。
- 正式公开或商业运营前，核实技术服务许可和实际调用额度。
- 生产环境通过服务端代理保护高德安全密钥。

## 10. 功能优先级

### P0：首个可验证版本

- 地图连续选点。
- 起点、途经点和环线设置。
- 控制点排序、拖动与删除。
- 完整路线生成。
- 按驾驶时间或里程拆分每日路线。
- 手动指定每日结束点。
- 高德推荐、高速优先和不走高速策略。
- 每日及全程的里程、时间、通行费、红绿灯和收费道路数据。
- 每日海拔剖面、累计爬升、累计下降和最高海拔。
- 路线与剖面双向联动。
- 方案自动暂存。

### P1：完善规划闭环

- 控制点自动顺序优化。
- 高速方案与非高速参考方案并排比较。
- 最长连续爬坡和分路段平均坡度。
- 海拔模式与坡度模式着色。
- 正式保存与方案复制。
- 只读分享链接。
- 调起高德地图。

### P2：增强展示

- 可选 3D 地形视图。
- 路线方案版本对比。
- 路线概要图片或 PDF 导出。
- 更细致的地形教育说明。

## 11. MVP 验收标准

首个版本满足以下条件即可进入用户验证：

1. 用户可以在地图上创建一条包含多个控制点的闭合环线。
2. 用户可以拖动、排序、插入和删除控制点。
3. 用户可以设置总天数以及每日时间或里程约束。
4. 系统可以在现有控制点上完成每日路线拆分。
5. 用户可以手动修改每日结束点。
6. 每日路线展示预计里程、驾驶时间、通行费、红绿灯和收费道路信息。
7. 用户可以在高速方案和非高速参考方案之间切换或比较。
8. 每日路线能够生成海拔剖面、累计爬升、累计下降和最高海拔。
9. 地图路线与海拔剖面能够相互定位。
10. 任一海拔数据失败不会影响基础路线规划。
11. 路线计算失败不会造成用户控制点丢失。
12. 产品中不存在 POI 搜索、景点推荐、住宿安排、电耗或剩余电量预测功能。

## 12. 产品核心闭环

> 地图连续选点 → 生成环线 → 优化控制点顺序 → 按驾驶时间或里程拆分每日路线 → 比较路线策略 → 查看里程、时间、收费及海拔 → 保存或分享 → 调起高德地图。
