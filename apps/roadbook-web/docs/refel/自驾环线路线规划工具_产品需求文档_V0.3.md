| 项目 | 内容 |
| --- | --- |
| 文档版本 | V0.12 |
| 文档状态 | MVP 交互基线 |
| 更新日期 | 2026-09-24 |
| 产品形态 | Web 应用，单页面全屏地图 |
| 核心定位 | 以地图控制点为基础的多方案自驾环线路线规划工具 |
| 主要使用端 | 桌面端规划，移动端承接控制点与路段的外部导航 |
| 首版目标 | 完成多路线方案管理、手动加载、地图选点、闭环算路、路线指标、基础海拔、本地暂存及外部地图衔接 |

## 1. 产品结论

### 1.1 产品形态

MVP 只有一个主页面：**全屏地图**。

地图既是页面背景，也是主要工作区。方案选择、控制点、路线策略、路线摘要、路段详情、海拔剖面和地图工具均以浮动 Widget 的形式分布在地图上；不建设门户首页、方案管理后台或独立详情页。

### 1.2 产品定位

本产品帮助用户把地图上选定的经过位置组织成可调整、可理解、可再次加载、可交给外部地图继续使用的自驾环线。

用户可以在当前浏览器保存多组路线方案。系统同一时间只将一组方案加载为活动方案，用户可通过地点搜索或直接双击地图添加控制点。系统按控制点顺序生成闭合驾车路线，并提供全程策略、里程、预计驾驶耗时和基础海拔信息。

**产品规划路线，不编排逐日行程。** 用户何时出发、用几天完成、每天行驶多少和在哪里停留，均不属于 MVP 的输入、计算或展示范围。

### 1.3 V0.3 核心决策

1. 页面始终以全屏地图为主体，功能通过浮动 Widget 叠加呈现。
2. MVP 支持本机多组路线方案，不再采用单草稿模型。
3. 新用户进入时看到空地图，不预先创建空方案。
4. 老用户再次进入时也看到未加载路线的地图，不自动恢复上次活动方案。
5. 只有用户点击已规划路线或“加载到地图”后，系统才加载控制点、适配视野并请求路线与海拔结果。
6. 同一时刻仅有一个活动方案显示在地图上；切换方案是显式用户行为。
7. 本地自动暂存只负责保存活动方案的编辑，不等同于下次启动自动打开。
8. 页面默认使用高德地图，用户可通过左下角紧凑地图入口显式切换腾讯地图；供应商切换覆盖全部地图能力。

## 2. 核心价值与产品边界

### 2.1 核心价值

| 核心价值 | 产品提供的帮助 |
| --- | --- |
| 表达路线意图 | 用户通过控制点指定经过哪里、按什么顺序经过 |
| 管理多组规划 | 用户可以创建、识别并再次加载多条独立路线方案 |
| 形成完整环线 | 系统按指定顺序连接控制点，并计算返回起点的路段 |
| 理解路线差异 | 用户可以切换全程路线策略，查看对应路线与指标 |
| 理解基本地形 | 用户可以查看全程或选中路段的估算海拔变化 |
| 保留并继续使用 | 活动方案自动暂存到本机，之后由用户主动选择加载 |
| 衔接实际导航 | 用户可从当前位置导航到控制点，也可按选中路段打开当前地图供应商继续核对 |

### 2.2 MVP 范围

| 本产品负责 | 本产品不负责 |
| --- | --- |
| 本机多路线方案的创建、列表与主动加载 | 账户体系、云端同步和跨设备恢复 |
| 地点搜索、地图双击选点与控制点编辑 | 景点、酒店及基于用户画像的智能推荐 |
| 人工维护的只读热门自驾路线专题 | 用户直接修改热门路线本体或用专题替代个人规划 |
| 按用户指定顺序生成闭合路线 | 自动安排出行日期、天数或每日行程 |
| 全程路线策略切换 | 自动拆分每日路线、指定每日结束点 |
| 路线及路段的里程、耗时和道路信息 | 费用估算、日均驾驶目标或强度评价 |
| 基础海拔剖面与地形指标 | 3D 地形和高级坡度分析 |
| 活动方案本地自动暂存 | 启动后自动打开上次活动方案 |
| 按控制点或选中路段调起当前地图供应商 App | 页面内实时导航、定位跟踪与偏航重算 |

### 2.3 设计方针

- 以路线为对象，不以日程为对象。
- 用户决定经过哪里和加载哪条路线，系统负责计算与展示。
- 地图优先，Widget 只占用完成当前任务所需的最小空间。
- 首屏不因历史数据自动发起路线或海拔请求。
- 地图、指标、海拔和活动方案必须属于同一有效版本。
- 缺失数据明确降级，不补零、不伪造、不用直线冒充驾车路线。

## 3. 用户与进入程序后的状态

### 3.1 新用户

判定条件：当前浏览器中不存在有效的路线方案索引。

进入程序后显示：

- 全屏空地图；
- “我的路线（0）”和“新建规划”入口；
- 搜索框作为稳定的路线添加入口，不在地图中央展示带步骤编号的引导卡片；
- 基础地图缩放、定位等工具；
- 不显示路线、控制点列表、路线指标或海拔结果。

用户首次从搜索结果选择地点，或双击地图时：

1. 创建一个“未命名路线”方案；
2. 请求浏览器精确当前位置并将其设为起点；
3. 将搜索结果或双击位置追加为后续控制点；
4. 打开控制点 Widget；
5. 达到可计算条件后生成闭合路线。

若浏览器拒绝定位、定位超时或精度不足，系统不得使用 IP 城市级近似坐标作为起点；保留空方案，并将搜索结果或地图选点作为用户手动确认的起点。

用户也可以先点击“新建规划”，创建未命名方案后再选点。

### 3.2 老用户

判定条件：当前浏览器中存在一个或多个有效路线方案。

进入程序后显示：

- 全屏地图，当前未加载任何路线；
- “我的路线（N）”入口和路线列表摘要；
- “当前：未选择方案”；
- “新建规划”入口；
- 地图中央提示用户选择一条已规划路线；
- 不自动读取上次活动方案的控制点；
- 不自动适配上次路线视野；
- 不自动发起算路或海拔请求。

用户点击某条已规划路线或其“加载到地图”入口后：

1. 将该路线设为活动方案；
2. 加载方案名称、控制点、顺序和策略；
3. 地图适配全部控制点的可见范围；
4. 请求或校验闭合路线结果；
5. 路线可用后展示全程及路段指标；
6. 海拔异步加载，不能阻塞路线展示；
7. 展开与当前任务相关的 Widgets。

### 3.3 共同原则

- “暂存”表示数据已保存在本机，不表示下次启动会自动加载。
- 启动时允许读取轻量方案索引，以展示名称、更新时间和数量；不得因此加载完整控制点或发起外部计算。
- 一个浏览器窗口同一时间只能有一个活动方案。
- 用户退出或刷新后，下次仍回到“未选择方案”状态。

## 4. 页面与 Widget 布局

### 4.1 单页面信息结构

| 区域 | Widget | 主要内容 |
| --- | --- | --- |
| 左上 | 方案选择器 | 我的路线数量、当前方案、新建规划、路线列表、加载入口 |
| 顶部中部 | 全局搜索 | 地点搜索、最近搜索、分类标签、热门自驾路线与预览入口 |
| 顶部中部 | 路线策略与状态 | 全程策略、计算中、失败、旧结果和暂存状态 |
| 右侧 | 路线地址列表 | 按路线顺序展示编号、地址和返回起点，首项隐式作为起点；每个控制点提供外部导航入口，路段连接线负责路段选择 |
| 右下 | 路线摘要 | 全程或当前路段的里程、耗时与高德入口 |
| 地图边缘 | 地图工具 | 缩放、定位、图层等地图级操作 |
| 左下安全区 | 地图供应商 | 默认显示地图图标，点击后向右展开高德/腾讯选项，默认高德 |
| 底部 | 海拔 Widget | 可折叠海拔剖面、累计爬升、下降和最高海拔 |
| 中央 | 上下文引导 | 空状态提示、错误提示和需要用户立即处理的动作 |

### 4.2 布局约束

- 所有业务 Widget 叠加在地图上，不切走地图上下文。
- 默认只展开当前任务必要的 Widget，避免同时遮挡地图。
- Widget 不覆盖关键控制点、当前选中路段或主要地图操作区；必要时自动换边或折叠。
- 左右 Widget 的宽度稳定，底部海拔区域预留高度，打开和关闭不得推动地图容器重新布局。
- 小屏设备使用抽屉或底部面板承载相同能力，不复制第二套业务流程。
- 状态区分不能只依赖颜色，应同时使用文字、图标、线型或描边。

### 4.3 地图视觉规则

- 完整路线使用统一基础样式，当前选中路段突出显示。
- 列表首项和“返回起点”表达同一地理位置；不额外展示“起点”文字。
- 控制点使用稳定编号；排序变化后立即更新编号与路线状态。
- 右侧地址列表的编号与地图控制点一一对应；选中地址时突出对应控制点及相邻路线段。
- 失败路段不得伪装成正常路线，旧结果必须明确标记。
- 不按日期着色，不显示“第几天”标签，不默认使用坡度色带。

## 5. 核心用户流程

### 5.1 新用户创建第一条路线

> 进入空地图 → 搜索地点、双击地图或点击“新建规划” → 创建未命名路线 → 添加起点和控制点 → 生成闭合路线 → 查看指标与海拔 → 自动暂存。

### 5.2 老用户加载已有路线

> 进入未加载地图 → 打开“我的路线” → 点击已规划路线/加载入口 → 加载控制点 → 适配地图视野 → 请求路线 → 展示指标 → 异步展示海拔。

### 5.3 多方案切换

> 当前活动方案自动暂存 → 用户打开“我的路线” → 选择另一方案 → 当前地图进入加载态 → 新方案成为活动方案 → 地图与 Widgets 全量切换到新方案版本。

切换失败时保留原活动方案及其最后一次有效结果，不展示新旧混合状态。

### 5.4 路线编辑

> 调整控制点 → 标记当前结果为更新中 → 计算受影响路段 → 汇总全程指标 → 更新海拔 → 自动暂存新版本。

### 5.5 外部导航

> 在控制点行点击导航图标 → 按当前地图供应商直接调起外部地图 App → 以当前位置为起点、该控制点为终点开始导航。路线摘要不重复提供外部导航入口。

### 5.6 浏览热门自驾路线

> 打开全局搜索 → 查看热门自驾路线 → 点击“黄金大环线” → 预览路线专题 → 在地图中查看 G219、G331、G228 线路及分层官方控制点 → 点击控制点导航，或搜索/双击地图添加“我的标记”。

热门路线专题与个人路线规划互斥展示，但不得删除或覆盖后台已暂存的活动方案。退出专题后返回原有规划上下文。

## 6. 功能需求

### 6.1 多路线方案

#### FR-PLAN-001 方案索引

系统在本机维护路线方案索引，至少包含稳定标识、名称、更新时间、控制点数量和数据格式版本；可选保存起点与末控制点名称，用于不加载完整快照即生成可识别的路线标题。

启动时仅加载索引所需的轻量元数据，不自动将任一方案设为活动方案。

#### FR-PLAN-002 创建方案

用户可通过“新建规划”创建未命名路线；在未选择方案的地图上首次添加控制点时，也应自动创建未命名路线。新方案创建后优先请求浏览器精确当前位置，并将其写入第一个控制点。

新方案不包含计划天数、日期、每日时间或里程目标。首版固定为闭合环线。

#### FR-PLAN-003 列表与加载

“我的路线”展示当前浏览器保存的全部有效方案，并按本地更新日期分组。已重命名方案使用用户输入的名称；未重命名方案优先使用“起点名称 → 末控制点名称”，缺少轻量目录数据时降级为“未命名路线”。辅助文字展示“`HH:mm · N` 个途经点”，并提供明确的加载入口。顶部活动方案标题必须直接复用对应列表项的展示名称。方案名称继续保留在索引与快照中，用于活动方案标识、重命名和删除确认。

点击方案后才读取完整快照并加载到地图。加载过程中显示目标方案名称和进度，禁止用户误以为旧地图内容属于新方案。

#### FR-PLAN-004 活动方案

同一时间只有一个活动方案。方案名称、控制点 Widget、地图折线、路线指标、海拔和外部导航入口必须全部绑定该活动方案及其当前修订版本。

#### FR-PLAN-005 自动暂存

活动方案编辑后自动暂存名称、控制点稳定标识、位置、顺序、全程策略和快照格式版本，并展示“暂存中”“已暂存至本机”或“暂存失败”。

自动暂存不改变启动规则：刷新或重新进入程序后仍不自动加载该方案。

#### FR-PLAN-006 重命名与删除

用户可以通过方案选择器管理菜单的“重命名当前路线”主动进入编辑状态；顶部方案名称默认只读，不与展开/收起操作重叠。提交空名称时恢复使用地点摘要自动命名。PC 通过方案行垃圾桶发起删除，移动端 H5 通过左滑方案行达到阈值后发起删除；删除方案前必须确认。删除活动方案后清空地图业务状态并回到未选择方案，不影响其他方案。

方案列表标题区在存在已存路线时提供管理菜单，其中的“清除全部路线”用于删除当前浏览器中的全部路线方案。批量清除前必须展示路线数量并二次确认；确认后同时清空活动方案、地图路线和相关编辑状态，取消或按 `Esc` 不得改变数据。

首版不要求方案复制、文件夹、标签、公开分享和云端版本历史。

#### FR-PLAN-007 存储异常

索引或快照损坏时标记具体方案不可加载，不影响其他方案。存储不可用或已满时明确提示未暂存，当前页面仍可继续规划。

### 6.2 地图控制点

#### FR-POINT-001 双入口连续选点

用户可以通过以下两种等价入口添加控制点：

1. 在左侧搜索框输入地点关键词，从候选地点中选择目标；
2. 在地图上直接双击目标位置。

新方案默认以浏览器精确当前位置作为起点，搜索或双击添加的地点按操作顺序追加。精确定位不可用时，第一次手动添加的点作为降级起点。地图单击用于选择、查看或拖动，不创建控制点，以减少误操作。

控制点达到 2 个后，系统按当前顺序生成返回起点的闭合路线。建议 MVP 限制为 2—20 个控制点，返回起点不重复计数。

#### FR-POINT-002 点位编辑

支持拖动地图点位、长按拖拽调整控制点顺序、在相邻点之间插入点位和删除点位。PC 与移动端都必须长按后才进入排序，普通点击只选择点位。

用户点击一条有效路线段后，地图在该路段两个控制点之间展示虚线插入引导和中间拖拽手柄。再次点击当前路段、点击地图空白处或在非文本编辑状态下按 `Esc`，均取消当前路段选择并隐藏插入引导。拖动期间只更新引导预览，不连续请求驾车算路；松手后才把手柄坐标作为正式控制点插入该路段顺序、解析地址并重新计算路线。最后一个控制点返回首项的闭环路段同样支持插入，新点追加在控制点列表末尾并继续返回首项。

点击地图控制点只执行选中和地图聚焦，不在地图点位旁展示删除入口。PC 通过地址列表删除图标，移动端 H5 通过左滑地址行发起删除；非文本编辑状态下也可按 `Backspace` / `Delete` 发起当前点位的删除确认。用户点击“删除”后才删除当前点位，点击“取消”或按 `Esc` 不改变路线数据；误点遮罩不得关闭确认框。

系统不自动重新排序、不静默跳过控制点，也不为满足假定行程目标新增点位。

#### FR-POINT-003 起点规则

列表首项天然作为起点；新方案首项默认是浏览器精确当前位置，但不显示额外的“起点”标签。终点是对同一起点的返回引用，不创建第二个独立控制点。

IP 定位只用于初始化地图视野和地点搜索范围，不得作为路线起点。精确定位失败时必须引导用户手动确认起点。

将点位拖拽到首位即变更起点；系统按新的完整列表顺序计算路线，不自动反转或优化路线。

#### FR-POINT-004 地点搜索

搜索结果至少展示地点名称和可区分的格式化地址。选择结果后按当前追加或插入上下文创建控制点；若完整控制点集合超出地图安全可视区，则平滑缩放到全部控制点，否则只将地图视野移动到新点。

输入过程中应合并不必要的重复请求，并处理无结果、超时、限流和同名地点。普通规划模式选择地点后添加控制点；热门路线专题中选择地点后添加“我的标记”，不得修改专题路线本体。

#### FR-POINT-005 地址解析与右侧联动

搜索选点优先采用搜索服务返回的名称和格式化地址；地图双击选点通过逆地理编码补充地址。地址解析失败时仍保留坐标和控制点，显示“未识别地址”，不得阻断算路。

右侧路线地址列表按控制点顺序显示编号、名称和地址。点击列表项或地图点位时，地图中心移动到对应控制点、保留当前缩放级别并保持选中；选中相邻地址之间的连接关系时，突出对应路线段。地图控制点、路线段与右侧地址信息必须保持同一活动方案和修订版本。

地图上的每个控制点仅展示一个“编号＋地点名称＋引导线”标签，标签通过引导线连接真实坐标，不再叠加独立圆形编号 Marker。相邻标签使用左右交错布局减少遮挡；标签跟随地图平移和缩放，不改变控制点坐标，并直接承接原控制点 Marker 的点击选择能力。

路线计算完成后必须使用完整路线折线复核安全可视区；道路绕行超出当前视野时再次平滑适配，确保完整路线可见。移动端新增点与任一既有点的直线距离超过 `2km` 时，即使边界判断仍认为可见，也触发一次控制点视野适配作为窄屏兜底。

### 6.3 环线与重新计算

#### FR-ROUTE-001 完整环线

系统按当前顺序连接全部控制点，并计算最后一个控制点返回起点的驾车路段。所有有效路段和返程路段都计入全程指标。

闭合只表示最终返回起点，不承诺路线无重复道路、不自交或达到全局最优。

#### FR-ROUTE-002 路段定义

一条路段连接两个相邻控制点，最后一个控制点至起点同样构成路段。路段按访问顺序编号，只代表路线结构，不代表日期或驾驶任务。

#### FR-ROUTE-003 不可达处理

某路段无法生成驾车路线时，应标记具体控制点或路段并说明原因。不得跳过控制点、用直线冒充驾车路线，或将不完整结果显示为完整环线。

#### FR-ROUTE-004 重新计算范围

| 用户操作 | 重新计算原则 |
| --- | --- |
| 加载已有方案 | 校验并请求该方案的完整闭合路线，路线优先、海拔异步 |
| 移动控制点 | 重新计算与该点连接的受影响路段 |
| 插入、删除或排序 | 根据新旧相邻关系重新计算变化路段 |
| 更换起点 | 检查闭环顺序与受影响路段，必要时重算 |
| 切换全程策略 | 更新所有受策略影响的路段 |
| 选择路段、展开 Widget | 不重复请求已有有效路线 |

### 6.4 全程路线策略

| 界面名称 | 产品含义 |
| --- | --- |
| 高德推荐 | 初次生成路线的默认策略 |
| 高速优先 | 使用接入服务支持的高速偏好策略，不承诺全程高速 |
| 非高速／国道参考方案 | 使用“不走高速”策略，不承诺全程国道 |

策略对整条环线统一生效。切换时保持控制点集合和访问顺序不变。某策略失败时保留原有效结果，并标明实际所属策略与失败原因，不静默回退。

MVP 只支持切换后查看一种结果，不提供多路线叠加、并排对比或自动差值分析。

### 6.5 路线指标

| 指标 | 全程 | 选中路段 | 数据要求 |
| --- | --- | --- | --- |
| 里程 | 默认显示“往返里程”，可切换“单程里程” | 显示“路段里程” | 往返包含全部闭合路段，单程不含最后返程段；数据为预计值 |
| 驾驶耗时 | 默认显示“往返用时”，随里程同步切换“单程用时” | 显示预计驾驶时间 | 与里程使用相同路段范围，不含停留安排 |

全程结果必须包含返程路段，并与地图展示的有效路线一致。完整路线摘要默认显示包含返程段的“往返里程”和“往返用时”，点击里程指标后同步切换为不含最后返程段的“单程里程”和“单程用时”，再次点击恢复往返口径；选中路段时固定显示该路段里程和预计驾驶时间。切换只改变已有结果的汇总展示，不重复发起路线请求。摘要底部说明里程和耗时均为预计值、仅供参考。路线摘要不展示红绿灯、通行费、收费里程、费用汇总或外部导航。


### 6.6 基础海拔

#### FR-ELEVATION-001 展示

支持查看全程和当前选中路段的距离—海拔曲线，并展示累计爬升、累计下降和最高海拔。

#### FR-ELEVATION-002 联动

鼠标移动到剖面某处时，地图显示对应位置、累计里程、估算海拔和所属路段。MVP 不要求点击地图后反向定位剖面。

#### FR-ELEVATION-003 数据质量

海拔沿实际驾车路线采样，不使用控制点直线替代道路路线。桥梁、隧道和高架区域不得将地表高程表述为精确路面高程；所有海拔与爬升结果标注为估算值。

#### FR-ELEVATION-004 独立降级

海拔加载不阻塞基础路线展示。缺失或失败只影响海拔 Widget，不影响点位编辑、路线指标、本地暂存和高德入口。

### 6.7 编辑反馈与版本隔离

- 点位编辑后立即更新地图与列表，计算期间保留并标记最后一次有效结果。
- 路线生成或更新期间在地图中央展示 Loading 和明确提示，反馈浮层不得造成布局偏移。
- 每次影响路线的编辑生成新的方案修订版本。
- 旧请求晚于新请求返回时不得覆盖新状态。
- 切换方案后，原方案的在途路线或海拔结果不得回写新活动方案。
- 至少支持撤销最近一次点位新增、拖动、排序、插入、删除、更换起点或策略修改。

### 6.8 外部地图衔接

每个控制点行提供导航图标，入口按当前地图供应商生成官方 App Scheme，并以设备当前位置为起点、该控制点为终点：高德地图使用 `amapuri://route/plan/`，腾讯地图使用 `qqmap://map/routeplan`。入口不经过地图网页，也不提供网页回退；设备未安装对应 App 时由操作系统保留在当前页面。路线摘要不重复提供外部地图入口。

外部地图可能重新计算路线，用户需要在对应地图中核对。实时路况、语音导航与偏航处理交给外部地图，本产品不在页面内执行实时导航。

### 6.9 地图供应商切换

- 页面首次进入默认使用高德地图，不读取或恢复上次供应商选择。
- 页面左下角提供紧凑地图入口，默认只显示地图图标，点击后向右展开“高德/腾讯”选项；切换期间保持锚点和尺寸稳定。
- 切换后底图、地点搜索、逆地址解析、IP 与浏览器定位转换、驾车算路统一使用目标供应商。
- 有活动方案时保留控制点和最后一次有效路线，目标供应商连接成功后重新计算闭合路线。
- 旧供应商的在途请求不得覆盖新供应商结果；切换失败不得删除控制点或路线方案。
- 桌面端入口位于左下缩放与定位工具组下方，移动端入口位于工具组上方；两端均向右展开供应商选项。

### 6.10 移动端任务布局

- 顶栏固定为三列结构，方案入口位于左侧，全局搜索位于中间并在展开后左右各保留 `16px` 安全区；搜索面板向下展开且不能覆盖系统安全区域。
- 路线地址列表位于搜索上方并优先展示顺序、路段和控制点导航入口；列表内容独立滚动，面板默认折叠为标题栏以便操作地图，用户点击后展开。
- 地形分析在移动端暂不展示，不得挤占路线顺序和搜索区域。
- 方案内容默认收起，只保留顶部稳定触发器；用户点击“我的路线”后再展开方案列表和“新建规划”。

### 6.11 全局搜索与热门自驾路线

#### FR-DISCOVERY-001 搜索状态机

全局搜索使用 `Closed → Discovering → Filtering → PreviewDialog` 明确状态机。关闭态显示紧凑胶囊；发现态在模糊蒙层上展示最近搜索、分类标签和热门路线；输入非空字符后进入过滤态；点击热门路线卡片打开预览 Dialog。桌面端支持 `Cmd/Ctrl + K`，`Escape` 可从输入、标签或推荐卡关闭搜索并把焦点归还入口。

#### FR-DISCOVERY-002 最近搜索与分类

有效搜索词保存在当前浏览器，最多保留最近 `8` 条，去重后按最近使用排序，并提供清空入口。分类标签等价于填入对应查询词；分类数量表示当前静态热门路线目录中可用路线数。

#### FR-DISCOVERY-003 热门路线专题

首个热门路线为“黄金大环线”，由 G219、G331、G228 三条概览线路组成。专题路线、官方主要控制点与数据说明均为只读，不进入 `RoutePlan`，不触发闭环驾车算路，不参与个人路线里程或耗时汇总。

概览线路必须明确说明数据精度。正式道路中心线数据未接入前，不得把专题几何表述为测绘级道路或导航路线；控制点导航以外部地图 App 实际规划为准。
热门路线推荐卡可展示从专题静态数据四舍五入得到的“约整里程”，但必须使用“约”表明估算口径；该数值仅用于专题识别，不进入个人路线指标、导航或精确里程计算。

地图按层级展示专题标签：`zoom < 7` 时只显示分散的 Gxxx 国道编号，`zoom ≥ 7` 时显示当前视野中的县市、明确口岸和景区控制点标签。右侧目录始终展示完整控制点；不维护附近中心城市。点击目录控制点后地图定位到该点并进入可见标签层级。

#### FR-DISCOVERY-004 我的标记

用户可在专题模式通过地点搜索或双击地图添加“我的标记”。标记按专题保存在当前浏览器，最多 `20` 个；支持选中、定位、删除、清空和调起当前地图供应商导航。标记不改变官方线路、官方控制点、专题里程或路线顺序。

## 7. 页面状态模型

| 状态 | 地图内容 | 主要 Widget | 允许操作 |
| --- | --- | --- | --- |
| `EmptyNewUser` 新用户空状态 | 基础地图 | 我的路线（0）、新建、中央引导 | 点击地图、新建方案 |
| `EmptyReturningUser` 老用户未加载 | 基础地图 | 我的路线（N）、新建、选择提示 | 选择并加载方案、新建方案 |
| `PlanLoading` 方案加载中 | 不展示目标方案的半成品路线 | 目标方案名、加载进度 | 取消或等待 |
| `PlanActive` 活动方案 | 控制点、完整路线 | 方案、控制点、策略、摘要、海拔 | 完整规划操作 |
| `RouteUpdating` 路线更新中 | 最后有效路线并标记旧结果 | 更新状态、可编辑输入 | 继续编辑或等待 |
| `PlanLoadFailed` 加载失败 | 原活动方案或基础地图 | 失败原因、重试 | 重试、选择其他方案 |
| `FeaturedRouteActive` 热门路线专题 | 三条概览国道、分层官方控制点、我的标记 | 专题说明、控制点与标记列表、退出入口 | 浏览、标记、删除标记、外部导航 |

任何状态都不得同时把两条方案标记为活动方案。

## 8. 领域模型与 DDD 边界

### 8.1 领域对象

| 领域对象 | 中文名称 | 职责 |
| --- | --- | --- |
| `RoutePlanCatalog` | 路线方案目录 | 管理本机方案索引、排序、选择与删除 |
| `RoutePlan` | 路线方案聚合根 | 管理名称、控制点顺序、策略和当前修订版本 |
| `ActiveRoutePlan` | 活动路线方案 | 表示当前唯一加载到地图的方案上下文 |
| `ControlPoint` | 路线控制点 | 管理稳定标识、坐标、名称、格式化地址和访问顺序 |
| `RouteLeg` | 路线段 | 表示相邻控制点之间的有向连接，包括返程段 |
| `RouteResult` | 路线结果 | 保存一次有效计算的几何、路段、策略和版本关联 |
| `RouteMetrics` | 路线指标 | 表示里程、驾驶耗时、道路信息和完整性 |
| `PlaceCandidate` | 地点候选项 | 表示地点搜索返回的名称、地址、坐标和来源标识 |
| `ElevationProfile` | 海拔剖面 | 管理采样、质量、曲线和基础地形指标 |
| `DraftSnapshot` | 方案快照 | 保存单个方案恢复编辑所需的数据与格式版本 |
| `FeaturedDrivingRoute` | 热门自驾路线 | 管理只读专题元数据、概览线路、官方控制点和数据说明 |
| `FeaturedRouteUserMarker` | 专题个人标记 | 管理用户在指定专题下保存的坐标、名称和地址，不参与算路 |

不建立 `DailyRoute`、`DaySplitRule` 等逐日对象，不在控制点或路段中保留所属日期、每日结束标记和驾驶日序号。

### 8.2 前端职责划分

- `RoutePlanCatalog`：只负责方案目录及加载意图，不直接绘制路线。
- `RoutePlanning`：负责活动方案、控制点编辑、闭环规则与重算协调。
- `RoutePresentation`：负责地图图层与 Widget 视图模型，不承载领域规则。
- `RouteMetrics`：负责指标完整性与汇总口径。
- `ElevationAnalysis`：独立处理海拔请求、质量与展示状态。
- `ExternalNavigation`：负责高德交接，不反向污染路线规划模型。

每个组件只承载一个明确职责；业务命名使用领域语言，避免以页面位置代替业务含义。

## 9. 数据、隐私与外部依赖

### 9.1 本地数据

路线方案默认保存在当前浏览器，不承诺跨浏览器、跨设备、永久保存或浏览器清理后的恢复。用户可以删除单个方案或一键清除全部方案；两类删除操作都必须通过页面内受控确认框确认，不得使用浏览器原生 `alert` 或 `confirm`。

首版不提供公开路线链接，不自动发布或分发用户路线。功能统计和普通日志不得包含精确控制点、完整路线或方案名称。

### 9.2 外部服务

| 能力 | 责任方 |
| --- | --- |
| 地图底图与地图交互 | 地图服务 SDK；本产品负责业务交互 |
| 地点搜索与逆地理编码 | 地点服务；本产品负责候选展示、选点和失败降级 |
| 驾车算路、路线坐标及道路指标 | 外部路线服务；本产品负责适配与完整性校验 |
| 环线规则、方案目录与控制点顺序 | 本产品 |
| 海拔原始数据 | 经验证且获得适用授权的高程来源 |
| 海拔采样、质量判断和展示 | 本产品 |
| 实际导航 | 高德等外部导航客户端 |

接入前必须验证地点搜索范围、同名地点区分、逆地理编码质量、策略可用性、字段、调用权限、额度、控制点限制、缓存许可、高德入口行为及高程数据授权。不得把未验证能力描述为已完成。

## 10. 异常与边界情况

| 情况 | 处理要求 |
| --- | --- |
| 首次进入 | 展示空地图，不创建无意义空草稿 |
| 老用户再次进入 | 展示方案入口，不自动加载上次方案 |
| 方案索引为空 | 回到新用户空状态 |
| 单个方案快照损坏 | 标记该方案不可加载，不影响其他方案 |
| 切换方案时请求晚返回 | 丢弃旧活动方案的过期响应 |
| 少于两个有效控制点 | 提示继续选点，不生成有效环线 |
| 达到控制点上限 | 提示当前限制，保留已有输入 |
| 点位重复或过于接近 | 提示检查，不自行删除或合并 |
| 地点搜索无结果或失败 | 保留输入并允许重试，用户仍可通过地图双击选点 |
| 双击位置无法识别地址 | 保留坐标并显示“未识别地址”，不阻断算路 |
| 某路段不可达 | 标记具体路段，不跳过、不直线补齐 |
| 某策略无结果 | 保留原有效结果并标明策略，允许重试 |
| 接口超时、限流或异常 | 保留方案和最后有效结果，说明原因 |
| 海拔缺失或质量不足 | 局部降级并解释，不阻断路线规划 |
| 本地存储不可用或已满 | 提示未暂存，允许继续当前编辑 |
| 高德入口无法调起 | 提示并提供已验证替代入口 |

任何计算失败都不应导致用户控制点或其他方案丢失。

## 11. 非功能需求

### 11.1 性能与首屏

- 首屏优先渲染稳定的全屏地图容器和必要空状态，不等待方案快照、路线或海拔数据。
- 方案索引读取不得触发路线详情或外部计算。
- 路线优先展示，海拔按需异步加载。
- 对地图 SDK、路线功能和海拔功能分层加载，非首屏 Widget 延后初始化。
- 生产环境以真实设备监测 LCP；MVP 目标为桌面端良好网络下 LCP 不高于 2.5 秒。
- 地图容器和所有 Widget 必须预留稳定尺寸，加载、展开和切换过程中 **CLS 为 0**。

### 11.2 稳定性与一致性

- 路线与海拔任务相互隔离，均绑定 `RoutePlanId` 和修订版本。
- 设置超时、取消和有限重试；切换方案时取消不再需要的请求。
- 自动暂存失败不能阻止用户继续操作，但必须显示真实状态。
- 地图、指标、海拔和高德入口不得混用不同方案或不同修订版本。

### 11.3 安全与授权

服务密钥在服务端管理，不写入前端代码或公开日志。客户端凭据按 SDK 要求配置来源限制；代理接口设置调用限制。

公开运营前核验地图、路线和高程数据的展示、处理、缓存和交接权限，并保留地图版权、Logo、审图信息等授权要求。

### 11.4 可理解性与可访问性

- 所有估算值、缺失值、旧结果、暂存状态和外部重新算路使用一致文案。
- 交互状态不只依赖颜色；键盘焦点、文本标签和错误说明必须可识别。
- 不把“已计算”“已暂存”或“已打开链接”表述为真实出行或导航完成。

## 12. MVP 验收标准

| 编号 | 验收场景 | 通过条件 |
| --- | --- | --- |
| AC-001 | 新用户进入 | 显示空地图和选点引导，不创建空方案、不发起算路 |
| AC-002 | 老用户进入 | 显示路线数量和顶部选择入口，不重复展示欢迎路线列表，不自动加载上次活动方案 |
| AC-003 | 手动加载 | 点击已有路线后才加载控制点、适配视野并请求路线与海拔 |
| AC-004 | 多方案管理 | 可创建、按日期分组列出、重命名、加载和删除多组本机路线，彼此数据隔离；未重命名路线优先显示起点和末控制点名称；PC 方案行保留垃圾桶，移动端 H5 左滑达到阈值后发起删除确认，短距离滑动回弹且不误加载方案；管理菜单可经二次确认清除全部已存路线，取消确认不改变数据 |
| AC-005 | 活动方案唯一 | 地图和全部 Widgets 始终只对应一个活动方案及一个修订版本 |
| AC-006 | 搜索选点 | 可搜索地点并从候选列表添加控制点，同名地点具有可区分地址 |
| AC-007 | 地图双击选点 | 双击地图可添加控制点，单击不误创建点，地址失败不阻断规划 |
| AC-008 | 地址联动 | 右侧地址编号与地图点位一致，选择地址或连接关系可突出对应点或路段 |
| AC-009 | 编辑控制点 | PC 与移动端长按拖拽排序、插入和删除有效；点击有效路线段展示虚线与中间拖拽手柄，拖动只预览，松手后在正确路段顺序插入正式控制点并重算，闭环返程段插点追加在列表末尾；PC 地址行保留拖拽与删除图标，移动端 H5 行内仅常驻导航图标并通过左滑发起删除；地图点位旁不展示删除图标，行内删除操作或 `Backspace` / `Delete` 均必须二次确认才删除；取消确认不改变数据，拖到首项即变更起点，顺序与地图一致 |
| AC-010 | 闭合环线 | 按全部控制点顺序生成驾车路线，返程计入汇总 |
| AC-011 | 路段选择 | 可查看路段地图、指标和海拔，不出现日期含义；再次点击当前路段、点击地图空白处或按 `Esc` 可取消选择 |
| AC-012 | 策略切换 | 策略不改变控制点顺序；失败不静默回退或误标结果 |
| AC-013 | 指标一致性 | 地图、全程和路段指标来自同一有效版本；MVP 不展示费用字段 |
| AC-014 | 基础海拔 | 覆盖正常时展示曲线、累计爬升、下降和最高海拔 |
| AC-015 | 海拔降级 | 海拔失败不影响路线、编辑、暂存和外部地图入口 |
| AC-016 | 方案切换隔离 | 旧方案晚返回的路线或海拔结果不能覆盖新活动方案 |
| AC-017 | 暂存语义 | 编辑可自动暂存，但刷新后仍回到未选择方案状态 |
| AC-018 | 外部地图衔接 | 每个有效路段可按当前供应商打开高德或腾讯地图；高德原生调起失败时由官方 URI 承接到网页 |
| AC-019 | 单页地图 | 核心流程均在全屏地图及浮动 Widgets 中完成 |
| AC-020 | 布局稳定 | 地图与 Widgets 预留尺寸，实测 CLS 为 0 |
| AC-021 | 日程逻辑移除 | 界面、模型和统计均不采集或生成逐日安排与日均驾驶量 |
| AC-022 | 隐私边界 | 无默认公开路线、无实际轨迹跟踪，日志不含完整位置方案 |
| AC-023 | 地图供应商切换 | 首次进入默认高德；左下紧凑地图入口可向右展开并切换腾讯，底图、搜索、定位和算路保持同一供应商，切换过程 CLS 为 0 |
| AC-024 | 移动端任务布局 | 搜索位于底部且结果向上展开；路线顺序优先展示；地形隐藏；地图切换和方案面板默认收起，展开不推动地图布局 |

## 14. 产品核心闭环

> **进入全屏地图 → 新建或主动加载一条路线方案 → 搜索地点或双击地图选点 → 调整顺序 → 生成闭合路线 → 查看路线指标与基础海拔 → 本地暂存 → 从控制点或选中路段调起当前地图供应商 App。**

**本产品以路线为规划对象，不以用户的逐日行程为规划对象；本地保存不等于启动自动恢复。**
