| 项目 | 内容 |
| --- | --- |

| 文档状态 | 持续迭代基线 |
| 更新日期 | 2026-09-23 |
| 适用范围 | `apps/roadbook-web` |

## 1. 文档职责

本文档定义 Roadbook Web 的视觉语言、布局规则、地图表达、状态反馈、动效、无障碍和性能基线，回答“界面应该长什么样、如何反馈状态”。

组件如何拆分、命名和组织由[组件设计与实现规范](../组件规范/组件设计与实现规范.md)定义。具体版本交付记录见[迭代文档](../迭代文档/2026-09-18-腾讯地图Web适配与路线规划体验迭代.md)。

## 2. 设计原则

1. **地图优先**：地图始终是页面主体，Widget 只占用完成当前任务所需空间。
2. **黑白克制**：近黑表达主操作，灰阶建立层级，彩色只用于必要语义和地图定位。
3. **任务就近**：方案、搜索、控制点和路线反馈靠近地图呈现，不建立第二个管理门户。
4. **状态明确**：加载、失败、旧结果、近似定位和精确定位必须可识别。
5. **交互连续**：地图平移、缩放、定位和路线更新期间，已经可用的地图不能无故消失。
6. **布局稳定**：异步加载不推动页面布局，目标 CLS 为 0。
7. **渐进增强**：精确定位、地址解析或路线服务失败时，保留可继续操作的降级结果。
8. **性能克制**：不使用大面积模糊、视频背景、网络字体阻塞和高成本滤镜。

## 3. 颜色 Token

### 3.1 基础颜色

| Token | 色值 | 用途 |
| --- | --- | --- |
| `color.ink` | `#0A0A0A` | 主按钮、活动路线、关键标题、焦点描边 |
| `color.textStrong` | `#1C1C1C` | 重要数字、活动方案名称 |
| `color.text` | `#3D3D3D` | 正文、常规图标 |
| `color.muted` | `#8A8A8A` | 次级信息、占位文本、旧结果 |
| `color.disabled` | `#C7C5C1` | 禁用文本和图标 |
| `color.border` | `#E7E5E1` | Widget 边框、分割线 |
| `color.surfaceSubtle` | `#F2F1EF` | 输入框、悬停行、弱选中背景 |
| `color.canvas` | `#FAF9F7` | 页面暖白画布 |
| `color.surface` | `#FFFFFF` | Widget、菜单和弹层表面 |

### 3.2 语义颜色

| Token | 色值 | 用途 |
| --- | --- | --- |
| `color.success` | `#2F6B4F` | 暂存成功、计算完成 |
| `color.warning` | `#946200` | 旧结果、数据不完整、需要留意 |
| `color.danger` | `#B42318` | 加载失败、不可达、破坏性操作 |
| `color.focus` | `#0A0A0A` | 键盘焦点环 |
| `color.location` | `#1677FF` | 屏幕中心点和用户地理位置点 |

状态色必须配合文字、图标、线型或尺寸变化，不得仅靠颜色传达状态。

## 4. 排版、间距与形状

### 4.1 字体

```css
font-family:
  Inter,
  -apple-system,
  BlinkMacSystemFont,
  "Segoe UI",
  "PingFang SC",
  "Microsoft YaHei",
  sans-serif;
```

首屏不得等待网络字体。指标数字使用 `font-variant-numeric: tabular-nums`。

### 4.2 字号

| 层级 | 字号/行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| `display` | `28/36` | 600 | 空状态主标题 |
| `title` | `20/28` | 600 | Widget 主标题、方案名称 |
| `subtitle` | `16/24` | 600 | 分区标题、关键指标 |
| `body` | `14/22` | 400 | 正文、列表内容 |
| `label` | `13/18` | 500 | 按钮、输入标签、状态标签 |
| `caption` | `12/18` | 400 | 辅助说明、数据来源、时间 |

### 4.3 间距与圆角

- 使用 `4 / 8 / 12 / 16 / 24 / 32 / 48` 的 4px 基础网格。
- Widget 默认内边距为 `16px`，紧凑区域为 `12px`。
- Widget 之间至少保留 `12px`。
- 图标与文字间距为 `8px`。
- `radius.sm = 8px`，用于图标按钮和标签。
- `radius.md = 12px`，用于 Widget、卡片和弹层。
- `radius.lg = 16px`，用于空状态引导卡。
- `radius.pill = 999px`，用于搜索框、主按钮和状态胶囊。

## 5. 地图工作台布局

### 5.1 基础结构

地图容器固定占满视口：`width: 100%; min-height: 100dvh`。业务组件悬浮在地图安全区域内，不推动地图尺寸变化。

| 区域 | 组件 | 桌面建议尺寸 |
| --- | --- | --- |
| 顶部左侧 | `RoutePlanSelector` | 宽 `280–320px`，高 `44px` |
| 左侧面板 | `RoutePlanWelcomePanel` 或方案列表 | 宽 `280–320px`，最大高 `60vh` |
| 顶部中部 | `PlaceSearch` | 宽 `360–480px`，高 `44px` |
| 顶部右侧 | 工作台入口或主操作 | 高 `44px` |
| 右侧 | `RouteAddressList` | 宽 `320px`，最大高 `calc(100vh - 160px)` |
| 右下 | `RouteMetricsPanel` | 宽 `280–320px` |
| 底部 | `ElevationPanel` | 高 `240–320px` |
| 地图左下 | `MapControls` | `40px` 方形按钮纵向排列 |
| 地图右下 | `MapProviderSwitch` | 高德/腾讯双标签与 Switch，最小高 `44px` |

路线选择必须使用左侧常驻面板，不得在页面初始化时以全屏模态弹窗阻断地图浏览。

### 5.2 布局稳定规则

- Widget 使用固定宽度或明确的最大尺寸。
- 异步内容使用同尺寸占位，不改变周围布局。
- 展开面板优先向地图边缘生长。
- 小屏将搜索固定在底部安全区，候选结果向上展开；路线顺序面板位于搜索上方并独立滚动，不复制第二套业务流程。
- 地图控件、定位点和浮动反馈使用独立层级，避免互相遮挡。
- 地图供应商 Switch 在桌面端固定于右下安全区；移动端改为右侧贴边图标，点击后向左展开供应商选项，不推动地图或其他 Widget 布局。
- 移动端暂时隐藏地形分析，优先保证路线顺序、控制点导航和搜索的可见空间。
- 移动端方案内容默认收起，只保留顶部触发器；点击后向下展开方案列表与新建入口。
- 移动端路线顺序默认收起，只保留约 `58px` 的标题与数量；标题栏提供展开箭头，重新展开时保留列表滚动位置和选择状态。

## 6. 地图视觉语言

### 6.1 路线

路线必须带白色外描边，保证在复杂地图底图上的可见性。

| 状态 | 主线 | 白色外描边 | 其他表达 |
| --- | --- | --- | --- |
| 活动路线 | `#0A0A0A`，`5px` | `9px` 总宽 | 实线 |
| 当前路段 | `#0A0A0A`，`8px` | `12px` 总宽 | 更粗，不只变色 |
| 旧结果 | `#8A8A8A`，`4px` | 保留 | `8px 6px` 虚线 |
| 失败路段 | `#B42318`，`5px` | 保留 | `5px 5px` 虚线及错误说明 |

路线重叠时使用线宽、虚实、层级和标签区分，不增加无约束颜色。

### 6.2 路线控制点

| 类型 | 样式 |
| --- | --- |
| 起点 | 近黑填充、白色编号、白色外环 |
| 普通控制点 | 白色填充、近黑描边、近黑编号 |
| 当前选中 | 尺寸增大、描边加粗，并与地址列表同步选中 |
| 地址解析失败 | 保留编号和坐标，显示“未识别地址” |

控制点编号与地址列表顺序必须一致。列表不额外展示“起点”文字，排序后的首项天然作为起点；“返回起点”复用首项坐标，不创建第二个控制点实体。

### 6.3 屏幕中心点与用户位置点

两类定位点使用相同基础视觉，但具有不同空间含义：

| 类型 | 定位方式 | 行为 |
| --- | --- | --- |
| 屏幕中心点 | DOM 固定在可视区域 `50% / 50%` | 地图拖动时保持不动，不拦截地图事件 |
| 用户位置点 | 腾讯地图标记图层绑定地理坐标 | 随地图平移和缩放，精确定位成功后更新坐标 |

基础样式：

```css
.loc_icon {
  width: 20px;
  height: 20px;
  background: #1677ff;
  border: 2px solid #fff;
  border-radius: 50%;
  box-shadow: 0 2px 8px rgba(0, 0, 0, 0.15);
}
```

- 屏幕中心点使用半透明蓝色脉冲外圈。
- 用户位置点使用同款蓝色圆点和外圈，不参与路线控制点排序。
- IP 定位成功后显示用户位置点，表示城市级近似位置。
- 精确定位成功后更新用户位置点坐标。
- 初始化时两点可能重叠；拖动地图后应自然分离。
- 两点不得拦截双击选点、滚轮缩放或地图拖动。

## 7. 地图加载与定位反馈

### 7.1 首次加载

- 地图首次创建前显示固定尺寸的轻量地图占位视觉。
- 收到首次 `tilesloaded` 后显示真实地图。
- 占位层只服务于首次初始化，不能用于每一次地图中心更新。
- 初始化定位优先使用 IP，地图层级为 11。
- 已授权且可信的精确位置可将地图更新到层级 14。

### 7.2 后续更新

- 点击定位、精确位置更新、路线更新和平移期间保持现有地图可见。
- 不因等待新瓦片而回退到全屏占位层。
- 定位进行中使用轻量状态文字或 Toast，不遮挡地图。
- 精确定位失败时提示“精确定位失败，已定位到当前城市”。
- 地址解析失败不删除点位，用户仍可删除、撤销或继续编辑。
- 生成或更新规划路线时，在地图视觉中心显示固定尺寸的 Loading 浮层和明确提示；浮层不改变地图与 Widget 尺寸，不造成布局偏移。

## 8. Widget 与基础控件

### 8.1 Widget

- 背景使用 `color.surface`。
- 边框使用 `color.border`。
- 圆角使用 `radius.md`。
- 阴影使用 `shadow.widget`。
- 标题使用 `subtitle`，辅助说明使用 `caption`。
- 可折叠 Widget 收起后保留稳定触发器。

### 8.2 按钮

- 主按钮高度 `44px`，背景 `color.ink`，文字为白色，圆角为 `radius.pill`。
- 一个 Widget 最多一个主按钮。
- 次按钮使用白底、细边框和近黑文字。
- 幽灵按钮使用透明背景，Hover 时使用 `color.surfaceSubtle`。
- 地图图标按钮点击目标不小于 `40 × 40px`。
- 破坏性操作使用危险色文字和图标，并要求明确确认。

### 8.3 搜索框

- 高度 `44px`，外层容器与输入区统一使用 `color.surface` 白底和胶囊圆角，不在输入区叠加灰色底层。
- Focus 使用 `2px` 近黑外环，不改变组件尺寸。
- 加载、无结果和失败在候选列表中反馈，不改变输入框高度。
- 输入请求必须防抖；清空输入后清理旧候选结果。
- 搜索候选使用 `22px` 经典实心定位针，采用 `color.ink` 填充和透明中心孔；图标占位固定，不因候选内容或 Hover 产生尺寸变化。
- 移动端隐藏 `⌘ K` 快捷键提示，为搜索输入保留有效宽度；搜索容器遵循横向安全区，最窄 `320px` 视口不得产生横向溢出。
- 移动端搜索输入字号不得小于 `16px`，避免 iOS Safari 聚焦小字号表单控件时自动放大页面；页面 viewport 使用 `viewport-fit=cover`，安全区间距由 `env(safe-area-inset-*)` 提供，禁止通过关闭用户缩放规避该问题。

### 8.4 列表行

- 普通单行高度为 `44px`，地址双行高度为 `56px`。
- Hover 使用暖灰背景。
- Selected 使用近黑左侧指示条、较高字重和暖灰背景。
- 控制点行不展示上下移动按钮，通过长按约 `250ms` 后拖拽排序；PC 鼠标与移动端触控保持一致。PC 保留拖拽提示图标，移动端 H5 隐藏该图标以减少常驻操作入口。
- 排序拖拽只允许沿垂直轴移动，列表只提供纵向滚动，不得因横向指针偏移产生左右滚动条。
- 普通点击控制点行只负责选中，并将地图中心移动到该点位；聚焦过程保留用户当前缩放级别。
- 排序后的首项自动成为起点，不展示“起点”标签，也不提供独立的“设为起点”入口。
- 导航入口与对应控制点位于同一行，点击后按当前供应商直接调起地图 App，并以当前位置为起点、该控制点为终点；导航图标不得放在路段连接行。
- PC 地址行保留独立删除图标，Hover、键盘聚焦和可访问名称说明删除语义；移动端 H5 不展示删除图标，向左滑动控制点行达到 `72px` 阈值并松开后发起删除确认。删除后地图编号和路线同步更新。

### 8.5 地图供应商 Switch

- 默认选中高德地图，关闭态表示高德、开启态表示腾讯。
- 桌面端 Switch 两侧始终显示“高德地图”和“腾讯地图”，当前供应商同时通过较高字重表达，不能只依靠滑块位置。
- 移动端默认只显示具有可访问名称的图层图标；点击后向左展开“高德/腾讯”文字选项，并用勾选图标与字重共同表达当前供应商。
- 切换期间控件保持原尺寸并进入禁用等待态，目标 CLS 为 0。
- 控件必须使用 `role="switch"`、`aria-checked` 和描述目标供应商的可访问名称。
- 切换供应商后，底图、搜索、逆地址解析、定位与算路必须保持同源；禁止混合展示不同供应商结果。

## 9. 地图交互规则

- 双击地图添加控制点。
- 禁用地图原生双击放大，避免与选点冲突。
- 地图缩放只通过滚轮、触摸手势或加减按钮完成。
- 点击定位按钮始终发起最新浏览器定位请求。
- `Esc`、`Delete` 和 `Backspace` 可删除待确认或当前选中点。
- 地图点位、地址行和路线段必须保持选中状态联动。
- 点击地图点位或地址行后，地图中心移动到对应控制点且缩放级别不变；普通点击不得误触发拖拽排序。
- 移动端 H5 控制点行只常驻展示导航图标；左滑删除只处理横向主导手势，纵向滚动、未达到阈值的滑动和取消手势不得发起删除。触发后仍须经过统一二次确认，不得直接删除。
- 点击地图点位后，在居中 marker 的右上角展示 `22 × 22px` 圆形删除图标，并通过透明扩展层保留约 `34 × 34px` 点击热区；使用 Framer Motion 对 `opacity`、`scale` 和纵向位移做轻量弹簧动效，减少动态效果模式下只保留瞬时透明度切换。
- 删除图标使用危险色图标、白色表面和稳定阴影；地图平移、缩放或点击空白处时收起，不随页面文档流占位，目标 CLS 为 0。
- 地图图标、列表图标、`Backspace` 和 `Delete` 只发起删除请求，统一打开 shadcn/ui Alert Dialog；标题固定为“确认要删除此定位吗？”，操作按钮为“取消”和“删除”。
- 确认框按钮保持黑白克制：“取消”使用白底、灰色细边框和近黑文字；“删除”同样使用白底与细边框，仅以危险色文字和 Hover 边框表达破坏性语义，不使用整块危险色背景。
- 只有点击确认框中的“删除”才执行点位删除；点击“取消”或按 `Esc` 关闭确认框且不改变数据，误点遮罩不关闭确认框。
- 输入框、文本域、原生下拉框和可编辑内容获得焦点时，`Backspace` / `Delete` 不得发起删除确认。
- 异步路线计算期间保留旧路线并标记为更新中，不能闪成空白。
- 过期请求结果不得覆盖新控制点对应的状态。

## 10. 动效

| Token | 时长 | 用途 |
| --- | --- | --- |
| `motion.fast` | `120ms` | Hover、按压、图标反馈 |
| `motion.base` | `180ms` | 菜单、Toast、轻量状态切换 |
| `motion.panel` | `240ms` | Widget 展开、底部抽屉 |

- 默认缓动使用 `cubic-bezier(0.2, 0, 0, 1)`。
- 动效优先改变 `opacity` 和 `transform`。
- 定位脉冲周期为 2 秒，不影响地图操作。
- 遵循 `prefers-reduced-motion`，关闭非必要动画。

## 11. 无障碍与可读性

- 正文与背景对比度至少达到 WCAG AA。
- 所有按钮和输入框必须具备可见键盘焦点。
- 图标按钮必须提供可访问名称和 Tooltip。
- 状态不能只通过颜色表达。
- 地图 Widget 文字必须位于实色表面，不直接压在复杂底图上。
- 纯装饰地图标记使用 `aria-hidden`，不得进入键盘焦点序列。
- `color.muted` 不用于小字号核心正文。

## 12. 性能与布局稳定性

- 地图容器、顶部工具栏、左右面板和底部区域提前预留尺寸。
- 首屏优先渲染地图容器、顶部工具栏和必要空状态。
- 图标优先使用内联 SVG 或轻量 CSS 图形。
- 避免首屏大图、背景视频和网络字体阻塞。
- 地图首次加载占位层与真实地图尺寸必须一致。
- 桌面端良好网络下 LCP 目标不高于 `2.5s`。
- 实测 CLS 必须为 `0`。

## 13. 响应式规则

- 桌面端维持全屏地图和边缘 Widget 布局。
- 窄屏顶部控件允许分组折叠，但地图始终保留主要可视区域。
- 地址列表、方案列表和指标面板在移动端进入底部抽屉。
- 地图控制按钮保持在拇指可触达区域，并避开系统安全区。
- 响应式切换不能复制领域状态或产生两套交互逻辑。

## 14. 禁止项

- 不使用彩色大面积背景或装饰渐变。
- 不将定位蓝扩展为通用品牌色。
- 不使用颜色代替文字、图标、尺寸或线型状态。
- 不使用玻璃拟态和高成本背景模糊。
- 不在初始化时使用全屏方案选择弹窗阻断地图。
- 不在后续地图更新时重新显示首次加载占位层。
- 不创建脱离地图的独立路线后台。
- 不展示未经产品确认的费用数据。
- 未完成暗色地图和路线对比度验证前不提供暗色主题。

## 15. UI 验收清单

- [ ] 颜色引用语义 Token，业务组件没有无约束硬编码颜色。
- [ ] 定位蓝只用于屏幕中心点和用户位置点。
- [ ] 屏幕中心点固定，用户位置点绑定地理坐标，拖动后可分离。
- [ ] IP 定位和精确定位具有明确降级反馈。
- [ ] 首次加载占位层正常退出，后续定位不隐藏现有地图。
- [ ] 双击选点不会同时触发地图放大。
- [ ] 路线、当前路段、旧结果和失败路段可通过线宽及线型区分。
- [ ] 地址列表与地图控制点编号、选中和删除状态一致。
- [ ] PC 鼠标和移动端触控都仅在长按后进入拖拽排序，普通点击只选中并聚焦点位。
- [ ] 路线生成期间地图中央显示稳定 Loading，显示和退出均不产生布局偏移。
- [ ] 所有交互状态具备键盘焦点和足够对比度。
- [ ] Widget 展开、加载和切换过程中 CLS 为 0。
- [ ] 首次进入默认高德地图，右下角 Switch 可在高德与腾讯之间切换且无布局偏移。
- [ ] 移动端搜索固定在底部且候选向上展开，路线顺序位于其上方并在每个控制点行显示导航图标。
- [ ] 移动端地形分析隐藏；方案与地图供应商控件默认收起，展开后不产生布局偏移。
- [ ] 移动端路线顺序可折叠为标题栏并再次展开，折叠期间地图保持完整可操作。
- [ ] 首屏没有背景模糊、网络字体阻塞或非必要大图依赖。

## 16. 规范更新规则

- 新增全局视觉模式、颜色、布局或地图语义前，先更新本规范。
- 组件级实现约束同步更新组件规范，不在两份文档中复制同一规则正文。
- 单次迭代的过程、问题和验证证据记录在迭代文档中。
- 规范发生行为变化时更新版本号和日期，并在代码评审中检查实现一致性。
