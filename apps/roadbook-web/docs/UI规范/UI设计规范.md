## 1. 文档职责

本文档定义 Roadbook Web 的视觉语言、布局规则、地图表达、状态反馈、动效、无障碍和性能基线，回答“界面应该长什么样、如何反馈状态”。

组件如何拆分、命名和组织由[组件设计与实现规范](../组件规范/组件设计与实现规范.md)定义。具体版本交付记录见[迭代文档](../迭代文档/2026-09-18-腾讯地图Web适配与路线规划体验迭代.md)。

## 2. 设计原则

1. **地图优先**：地图始终是页面主体，Widget 只占用完成当前任务所需空间。
2. **黑白克制**：近黑表达页面主操作，灰阶建立层级；地图覆盖物使用受控的导航蓝、路线绿和状态色建立空间语义。
3. **任务就近**：方案、搜索、控制点和路线反馈靠近地图呈现，不建立第二个管理门户。
4. **状态明确**：加载、失败、旧结果、近似定位和精确定位必须可识别。
5. **交互连续**：地图平移、缩放、定位和路线更新期间，已经可用的地图不能无故消失。
6. **布局稳定**：异步加载不推动页面布局，目标 CLS 为 0。
7. **渐进增强**：精确定位、地址解析或路线服务失败时，保留可继续操作的降级结果。
8. **性能克制**：不使用大面积模糊、视频背景、网络字体阻塞和高成本滤镜。

状态色必须配合文字、图标、线型或尺寸变化，不得仅靠颜色传达状态。

## 4. 排版、间距与形状

### 4.1 字体

```css
font-family:
  -apple-system,
  BlinkMacSystemFont,
  "SF Pro Text",
  "SF Pro Display",
  "PingFang SC",
  "Helvetica Neue",
  "Segoe UI",
  "Microsoft YaHei",
  sans-serif;
```

全局使用平台系统字体：macOS 与 iOS 优先使用 SF Pro 和苹方，Windows 回退到 Segoe UI 与系统中文字体。不打包或通过网络加载 SF Pro，首屏不得等待网络字体。指标数字使用 `font-variant-numeric: tabular-nums`。

### 4.2 字号

| 层级 | 字号/行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| `display` | `28/36` | 600 | 空状态主标题 |
| `title` | `20/28` | 600 | Widget 主标题、方案名称 |
| `subtitle` | `16/24` | 600 | 分区标题、关键指标 |
| `body` | `14/22` | 400 | 正文、列表内容 |
| `label` | `13/18` | 500 | 按钮、输入标签、状态标签 |
| `caption` | `12/18` | 400 | 辅助说明、数据来源、时间 |

### 4.3 间距与圆角

- 使用 `4 / 8 / 12 / 16 / 24 / 32 / 48` 的 4px 基础网格。
- Widget 默认内边距为 `16px`，紧凑区域为 `12px`。
- Widget 之间至少保留 `12px`。
- 图标与文字间距为 `8px`。
- `radius.sm = 8px`，用于图标按钮和标签。
- `radius.md = 12px`，用于 Widget、卡片和弹层。
- `radius.lg = 16px`，用于空状态引导卡。
- `radius.pill = 999px`，用于搜索框、主按钮和状态胶囊。

## 5. 地图工作台布局

### 5.1 基础结构

地图容器固定占满视口：`width: 100%; min-height: 100dvh`。业务组件悬浮在地图安全区域内，不推动地图尺寸变化。

| 区域 | 组件 | 桌面建议尺寸 |
| --- | --- | --- |
| 顶部左侧 | `RoutePlanSelector` | PC 宽 `330px`，触发器与展开菜单等宽 |
| 左侧面板 | 无暂存路线时显示 `RoutePlanWelcomePanel`；已有路线统一使用顶部方案列表 | PC 宽 `330px`，与顶部 `RoutePlanSelector` 左右边缘对齐，最大高 `60vh` |
| 顶部中部 | `GlobalSearch` | 关闭态宽 `228–242px`、高 `48px`；展开态最大宽 `600px`、高 `56px` |
| 顶部右侧 | 工作台入口或主操作 | 高 `44px` |
| 右侧 | `RouteAddressList` | 宽 `320px`，最大高 `calc(100vh - 160px)` |
| 右下 | `RouteMetricsPanel` | 宽 `280–320px` |
| 底部 | `ElevationPanel` | 高 `240–320px` |
| 地图左下 | `MapControls` | `40px` 方形按钮纵向排列 |
| 地图左下 | `MapProviderSwitch` | 默认显示地图图标，点击后向右展开高德/腾讯选项，最小高 `44px` |

路线选择必须使用左侧常驻面板，不得在页面初始化时以全屏模态弹窗阻断地图浏览。

### 5.2 布局稳定规则

- Widget 使用固定宽度或明确的最大尺寸。
- 异步内容使用同尺寸占位，不改变周围布局。
- 展开面板优先向地图边缘生长。
- 小屏使用固定三列顶栏：紧凑方案入口、居中搜索和等宽右侧占位；搜索展开后脱离网格并在视口左右保留 `16px`，结果面板向下展开。
- 不在地图中央展示“继续添加控制点”卡片或步骤数字；添加引导与搜索操作保持在同一个稳定入口中，控制点数量变化不得让入口消失。
- 地图控件、定位点和浮动反馈使用独立层级，避免互相遮挡。
- 地图供应商入口在桌面端和移动端均与缩放、定位控件归置在左下区域，默认只显示地图图标并向右展开供应商选项；桌面端位于工具组下方，移动端位于工具组上方，展开时不推动地图或其他 Widget 布局。
- 移动端暂时隐藏地形分析，优先保证路线顺序、控制点导航和搜索的可见空间。
- 移动端方案内容默认收起，只保留顶部触发器；点击后向下展开方案列表与新建入口。
- 移动端路线顺序默认收起，只保留约 `58px` 的标题与数量；标题栏提供展开箭头，重新展开时保留列表滚动位置和选择状态。

## 6. 地图视觉语言

### 6.1 路线

路线必须带白色外描边，保证在复杂地图底图上的可见性。

| 状态 | 路线结构 | 白色外描边 | 其他表达 |
| --- | --- | --- | --- |
| 活动路线 | `#0A84FF` 蓝色边界 `8px`＋`#30D158` 绿色内芯 `4px` | `11px` 总宽 | 三层实线，绿色仅表示有效路线，不表示实时路况 |
| 当前路段 | 蓝色边界 `10px`＋绿色内芯 `6px` | `13px` 总宽 | 整体加粗，不只变色 |
| 旧结果 | `#8E8E93`，`4px` | `9px` 总宽 | `8px 6px` 虚线，不显示蓝绿双层 |
| 失败路段 | `#FF3B30`，`5px` | `9px` 总宽 | `5px 5px` 虚线及错误说明，不显示蓝绿双层 |

有效规划路线从外到内依次为白色隔离层、导航蓝边界层和路线绿内芯。该结构参考移动导航界面的清晰分层，但不冒充交通数据；状态变化仍必须结合线宽、虚实和错误文字表达。

选中有效路段后，在两个端点之间展示经过插入手柄的路段调整引导：白色 `7px` 外描边、灰色 `3px` 主线和 `6px 6px` 虚线。手柄为固定 `32 × 32px` 白底近黑描边圆形，内部使用四向移动图形；手柄不使用定位蓝，也不参与页面文档流。拖动时虚线实时连接“前一控制点—手柄—后一控制点”，已有驾车路线保持可见。

路线重叠时使用线宽、虚实、层级和标签区分，不增加无约束颜色。

热门路线专题是独立参考图层，可使用受控国道语义色：G219 为 `#7D5AA6`、G331 为 `#C64B45`、G228 为 `#2E7FA3`。三条线路统一使用约 `6px` 主线和 `10px` 白色外描边，并同时展示国道编号和图例，颜色不得成为唯一识别手段。专题参考线位于用户活动路线图层之下，不承接普通路线选段和插点交互。

### 6.2 路线控制点

| 类型 | 样式 |
| --- | --- |
| 起点 | 与普通控制点保持同一视觉，由编号 `1` 表达顺序语义 |
| 普通控制点 | 96% 白色胶囊、导航蓝描边、蓝底白字编号、深色地点名称 |
| 当前选中 | 导航蓝胶囊、白色文字、白底蓝字编号和更粗白色描边，并与地址列表同步选中 |
| 地址解析失败 | 保留编号和坐标，显示“未识别地址” |

控制点编号与地址列表顺序必须一致。列表不额外展示“起点”文字，排序后的首项天然作为起点；“返回起点”复用首项坐标，不创建第二个控制点实体。

路线地址列表与地图 Marker 共用导航蓝状态语言，但控制色量必须低于地图覆盖物：普通编号使用白底、导航蓝描边和蓝色数字；当前选中编号反转为蓝底白字，并以约 8% 淡蓝行背景辅助识别。首项不得使用独立黑色实心样式。相邻路段连接线使用低透明导航蓝虚线，选中路段改为较粗的导航蓝实线；列表连接线不叠加绿色内芯，避免紧凑面板出现过多彩色信号。

每个地图控制点增加名称标签：

- 标签由编号徽标、地点名称和连接真实坐标的引导线组成；普通态使用白底蓝色描边，选中态使用蓝底白字反色，并保留轻量柔和阴影。
- 奇数编号标签位于坐标右侧，偶数编号标签位于坐标左侧，以稳定规则减少连续点位遮挡。
- 地点名称最多显示 `10` 个字符，超出后使用省略号；完整名称仍由地址列表承载。
- 名称标签宽度按“编号徽标、徽标与名称间距、实际文字宽度和左右内边距”自适应，禁止使用统一固定宽度；高度保持稳定，避免短名称产生大面积空白。
- 当前选中标签使用导航蓝背景与白色文字，同时通过反色编号、加粗白色描边和图层提升表达选中；不能只依靠颜色表达选中状态。
- “编号＋地点名称＋引导线”标签是控制点唯一可见 Marker，不叠加独立圆形编号图标；标签整体继承点位点击选择能力，标签范围外不拦截地图拖动、缩放和双击选点。
- 标签高度固定、宽度仅在名称或选中点数据变化时按内容重算，且不参与页面文档流；地图移动与异步更新期间不产生 CLS。

点击路线控制点 Marker 后，在保持点位与地址列表同步选中的同时，按需打开“未来 7 天（含今天）”天气卡片：

- 卡片使用暖白实色表面、`18px` 圆角、细边框和克制阴影，不使用玻璃模糊或大面积渐变；桌面端位于地图安全区域，移动端位于底部并为左下地图工具保留空间。
- 每日只展示星期、分层天气图标、天气文字和最高/最低温；天气文字始终保留，图标和颜色不能成为唯一信息信号。
- “今天”仅使用极浅蓝灰表面和稍高字重，不增加第二个高饱和选中信号；Marker 的导航蓝仍是当前控制点主视觉信号。
- 七天内容在窄视口内横向滚动，不压缩到不可读尺寸；关闭按钮命中区不小于 `40 × 40px`。
- Loading、成功和错误状态保持稳定卡片尺寸；点击其他 Marker 原位切换内容，点击地图空白、按 `Esc` 或点击关闭按钮收起卡片。
- 移动端天气卡片打开期间隐藏路线地址列表的呈现，避免两个白色 Widget 在短视口重叠；地址列表保持挂载并保留折叠、滚动和选择状态，关闭天气后原样恢复。
- 天气卡片、图标与请求逻辑在首次 Marker 点击后懒加载，不进入首屏关键资源；本地图标使用内联 SVG，不新增字体、图片或第三方图标依赖。

热门路线专题使用独立的层级标签规则：

- 三条专题线路采用同一高饱和冷色光谱：G331 玫红 `#FF375F`、G219 紫罗兰 `#BF5AF2`、G228 电光蓝 `#0A84FF`；线路继续保留白色外描边，在浅色地图上形成清晰分层。
- 国道路牌和控制点标签使用半透明白色材质、对应线路色描边及轻量柔和阴影；禁止使用大面积渐变或高强度发光遮挡底图信息。
- `zoom < 7` 时不显示官方控制点名称，只沿三条线路展示白底、对应线路色描边的 `G331`、`G219`、`G228` 胶囊标签。
- `zoom ≥ 7` 时隐藏 Gxxx 胶囊，显示当前视野内全部官方县市、口岸和景区控制点标签。
- 县市标签徽标显示国道编号，口岸与景区分别显示“口”“景”；颜色继续继承所属国道。
- 国道路牌与控制点标签宽度必须由文字实际宽度和固定内边距撑开，不设置统一最小宽度；徽标、间距和左右内边距保持稳定。
- 右侧目录不随缩放裁剪，必须完整展示全部官方控制点；点击目录项后地图进入 `zoom 9` 并显示对应标签。
- 专题不展示或维护“附近中心城市”。

### 6.3 屏幕中心点与用户位置点

两类定位点使用相同基础视觉，但具有不同空间含义：

| 类型 | 定位方式 | 行为 |
| --- | --- | --- |
| 屏幕中心点 | DOM 固定在可视区域 `50% / 50%` | 地图拖动时保持不动，不拦截地图事件 |
| 用户位置点 | 腾讯地图标记图层绑定地理坐标 | 随地图平移和缩放，精确定位成功后更新坐标 |

基础样式：

```css
.loc_icon {
  width: 20px;
  height: 20px;
  background: #0a84ff;
  border: 3px solid #fff;
  border-radius: 50%;
  box-shadow: 0 1px 4px rgba(28, 28, 30, 0.24);
}
```

- 屏幕中心点使用 `32px`、18% 不透明度的静态蓝色柔和外圈，不使用持续脉冲抢占注意力。
- 用户位置点使用同款蓝色圆点、`3px` 白环和柔和外圈，不参与路线控制点排序。
- IP 定位成功后显示用户位置点，表示城市级近似位置。
- 精确定位成功后更新用户位置点坐标。
- 初始化时两点可能重叠；拖动地图后应自然分离。
- 两点不得拦截双击选点、滚轮缩放或地图拖动。

## 7. 地图加载与定位反馈

### 7.1 首次加载

- 地图首次创建前显示固定尺寸的轻量地图占位视觉。
- 收到首次 `tilesloaded` 后显示真实地图。
- 占位层只服务于首次初始化，不能用于每一次地图中心更新。
- 初始化定位优先使用 IP，地图层级为 11。
- 已授权且可信的精确位置可将地图更新到层级 14。

### 7.2 后续更新

- 点击定位、精确位置更新、路线更新和平移期间保持现有地图可见。
- 不因等待新瓦片而回退到全屏占位层。
- 定位进行中使用轻量状态文字或 Toast，不遮挡地图。
- 精确定位失败时提示“精确定位失败，已定位到当前城市”。
- 地址解析失败不删除点位，用户仍可删除、撤销或继续编辑。
- 生成或更新规划路线时，在地图视觉中心显示固定尺寸的 Loading 浮层和明确提示；浮层不改变地图与 Widget 尺寸，不造成布局偏移。

## 8. Widget 与基础控件

### 8.1 Widget

- 背景使用 `color.surface`。
- 边框使用 `color.border`。
- 圆角使用 `radius.md`。
- 阴影使用 `shadow.widget`。
- 标题使用 `subtitle`，辅助说明使用 `caption`。
- 可折叠 Widget 收起后保留稳定触发器。

### 8.2 按钮

- 主按钮高度 `44px`，背景 `color.ink`，文字为白色，圆角为 `radius.pill`。
- 一个 Widget 最多一个主按钮。
- 次按钮使用白底、细边框和近黑文字。
- 幽灵按钮使用透明背景，Hover 时使用 `color.surfaceSubtle`。
- 地图图标按钮点击目标不小于 `40 × 40px`。
- 破坏性操作使用危险色文字和图标，并要求明确确认。

### 8.3 搜索框

- 关闭态为浅灰胶囊：桌面高 `48px`、宽 `228–242px`，移动端高 `44px`、最大宽 `240px`；背景 `rgba(23,24,26,.09)`，圆角 `999px`。
- 展开态高 `56px`、背景纯白，桌面最大宽 `600px`；移动端使用显式视口安全宽度，左右至少保留 `16px`，并叠加 `safe-area-inset-left/right`；使用 `0 6px 24px rgba(23,24,26,.10)` 阴影。
- 发现态和过滤态统一使用覆盖视口的 `rgba(250,249,247,.72)` 中性蒙层，不使用 `backdrop-filter`；蒙层、顶栏、搜索内容层级依次为 `60 / 65 / 70`，输入过程中不得因状态切换改变背景层级。
- 搜索面板与输入框等宽，两者间距 `12px`；面板内边距 `16px`、内容组间距 `20px`，桌面与移动端圆角均为 `16px`。移动端最大高度须扣除搜索条、间距和上下安全区，使用 `100vh` 回退及 `100dvh` 增强，并独立纵向滚动。
- 分组标题使用 `10.5px / 600`、大写和 `.42px` 字距；没有历史记录时不渲染空的“最近搜索”分区。历史词与分类使用胶囊，分类高 `34px`，默认使用白色表面和轻边框；分类计数仅在大于 `1` 时展示，并使用 `11px` 等宽数字。
- 推荐卡宽 `132px`，缩略图为 `132 × 132px`、圆角 `12px`；图片惰性加载，Hover 时仅通过 `transform: scale(1.03)` 放大预览。
- 黄金大环线推荐缩略图使用真实环线数据高度抽稀后的闭合折线，仅保留绿色渐变轮廓和小面积柔光；不展示底图、轨迹细节、国道编号、节点或图内文字。卡片文字固定为路线名称和约整里程两行，均在缩略图下方水平居中，数字使用等宽排版特性。
- 横向历史、分类和推荐列表隐藏滚动条，但保留触控和触控板横向滚动；移动端列表延伸到面板尾部内边缘并保留 `16px` 收尾空间，避免下一项被裁切在内容内边距之前；热门路线即使当前只有一个专题也保持横向卡片目录结构，不根据数量切换为纵向列表。
- 输入请求必须防抖；过滤态展示地点和热门路线结果，加载、无结果和失败不改变输入框尺寸。
- 普通规划模式占位文案说明添加控制点；专题模式说明添加“我的标记”。
- 移动端隐藏 `⌘ K`，输入字号不得小于 `16px`，页面继续使用 `viewport-fit=cover` 与安全区变量。
- 展开、过滤和关闭只改变浮层、透明度、变换及搜索容器自身尺寸，不推动地图或其他正文布局，目标 CLS 为 `0`。

### 8.4 列表行

- 普通单行高度为 `44px`，地址双行高度为 `56px`。
- Hover 仅使用约 `3%–4%` 的中性灰背景，不增加位移、强调描边或阴影；行下方分割线随 Hover 淡出，避免与完整背景形成双重边界。
- 已暂存路线的 Selected 使用暖白表面、极浅内描边、淡绿色图标底和尾部勾选标记；紧凑滚动列表内不使用外投影，避免阴影被滚动边界裁切为直角，且不得使用粗黑左侧指示条，选中行下方分割线隐藏。
- 删除入口默认使用中性灰；Hover 时使用克制的暗红文字与约 `7%` 暖红灰背景，不使用纯白浮层或品牌绿，避免破坏操作与正向操作语义混淆。
- Hover、Selected 与删除操作必须分层表达：桌面端悬停活动路线时，尾部勾选临时切换为删除入口；移动端保持勾选标记并通过左滑发起删除。
- 控制点行不展示上下移动按钮，通过长按约 `250ms` 后拖拽排序；PC 鼠标与移动端触控保持一致。PC 保留拖拽提示图标，移动端 H5 隐藏该图标以减少常驻操作入口。
- 控制点行 Hover 只使用约 4% 中性灰，Selected 使用约 8% 淡蓝背景和反色编号；禁止继续使用黑色侧边条或黑色起点圆与地图蓝白 Marker 竞争。
- 排序拖拽只允许沿垂直轴移动，列表只提供纵向滚动，不得因横向指针偏移产生左右滚动条。
- 普通点击控制点行只负责选中，并将地图中心移动到该点位；聚焦过程保留用户当前缩放级别。
- 排序后的首项自动成为起点，不展示“起点”标签，也不提供独立的“设为起点”入口。
- 导航入口与对应控制点位于同一行，点击后按当前供应商直接调起地图 App，并以当前位置为起点、该控制点为终点；导航图标不得放在路段连接行。
- PC 地址行保留独立删除图标，Hover、键盘聚焦和可访问名称说明删除语义；移动端 H5 不展示删除图标，向左滑动控制点行达到 `72px` 阈值并松开后发起删除确认。删除后地图编号和路线同步更新。
- PC 已暂存路线行保留垃圾桶删除图标；移动端 H5 隐藏该图标，向左滑动方案行达到 `72px` 阈值并松开后发起方案删除确认。两个入口必须使用与定位删除一致的页面内 `AlertDialog`，不得调用浏览器原生 `alert` 或 `confirm`。未达到阈值、纵向滚动或取消手势时必须回弹，且不得误触发方案加载。
- PC 与移动端 H5 的已存路线列表按更新日期分组；当天和前一天分别显示“今天 · M月D日”和“昨天 · M月D日”，当年其他日期不显示年份，跨年日期显示完整年月日。
- 未重命名方案优先使用“起点名称 → 末控制点名称”作为标题；只有一个有效点时显示该地点名称，轻量目录尚未包含地点名称时降级为“未命名路线”。自定义名称始终优先。
- 方案行的辅助信息展示“`HH:mm · N` 个途经点”；时间使用等宽数字特性。相邻行之间的 `1px` 分割线从文本起始位置延伸，移动端左滑时不随内容移动，也不增加行高。
- 已存路线数量使用弱化徽标表达。仅在目录非空时显示标题右侧的管理菜单，“清除全部路线”收入该菜单；点击后仍必须使用页面内 `AlertDialog` 展示当前路线数量和不可恢复说明。
- 顶部方案触发器只负责展示当前方案和展开/收起，方案名称默认为只读文本，不在触发器上叠加输入框。“重命名当前路线”收入管理菜单，用户主动触发后才在展开面板内显示独立的圆角编辑区；编辑框使用内收焦点环，不使用跨越整行的直角黑框。
- 方案行与顶部入口共用线性路线图标系统；行高不低于 `68px`，行圆角使用 `12px`。“新建规划”使用浅色次级按钮，不与页面核心主操作争夺视觉重量。
- 全局可滚动区域使用透明轨道和灰阶滑块；Chromium 与 Safari 的滚动条宽高为 `2px`，Firefox 使用浏览器支持的 `thin` 最细档。悬停只加深滑块颜色，不改变宽度或内容尺寸。
- 路线顺序列表的滚动条使用 Apple 冷中性灰：默认 `rgba(60,60,67,.18)`，Hover `rgba(60,60,67,.32)`，轨道透明；不得复用偏暖且高对比的正文灰，也不得使用导航蓝与控制点选中状态争夺注意力。

### 8.5 地图供应商选择器

- 默认选中高德地图，收起时只显示具有可访问名称的地图图标；外框宽度固定为 `42px`，与缩放、定位工具组一致。
- 桌面端和移动端共用紧凑形态；点击图标后向右展开“高德/腾讯”文字选项，并用勾选图标与较高字重共同表达当前供应商，不能只依靠颜色。
- 桌面端入口固定于左下缩放与定位工具组下方；移动端因底部搜索安全区位于工具组上方。
- 切换期间触发器与选项进入禁用等待态，锚点和高度保持不变，目标 CLS 为 0。
- 图标触发器必须提供 `aria-expanded`、当前供应商和展开/收起语义；选项组必须提供可访问名称。
- 切换供应商后，底图、搜索、逆地址解析、定位与算路必须保持同源；禁止混合展示不同供应商结果。

## 9. 地图交互规则

- 双击地图添加控制点。
- 新方案优先以浏览器精确当前位置创建第一个控制点；IP 城市级近似位置只用于地图初始化，不得静默成为路线起点。精确定位失败时允许用户通过搜索或双击地图手动确认起点。
- 添加第 2 个及后续控制点后，只有完整控制点集合超出扣除顶部面板、底部搜索和地图工具后的安全可视区时才自动适配视野；移动端任意新旧点直线距离超过 `2km` 时作为兜底触发。
- 路线计算完成后使用全部路段折线复核安全可视区，道路绕行超出视野时平滑缩小层级。高德与腾讯必须使用各自原生边界适配能力，不通过 React 动画改变地图容器尺寸。
- 禁用地图原生双击放大，避免与选点冲突。
- 地图缩放只通过滚轮、触摸手势或加减按钮完成。
- 点击定位按钮始终发起最新浏览器定位请求。
- `Esc`、`Delete` 和 `Backspace` 可删除待确认或当前选中点。
- 地图点位、地址行和路线段必须保持选中状态联动。
- 完整路线摘要默认显示“往返里程”和“往返用时”，点击里程指标区域后同步切换为“单程里程”和“单程用时”；按钮需要保留可见 Hover、键盘焦点和可访问状态，切换不得改变指标区域尺寸。选中具体路段时固定显示该路段里程和预计驾驶时间，不提供切换。
- 点击有效路线段后显示虚线路段插入引导和中间拖拽手柄；再次点击当前路段、点击地图空白处或在非文本编辑状态下按 `Esc`，均取消路段选择并隐藏引导。拖动期间只更新引导，不触发算路，松手后插入正式控制点并隐藏引导。选择控制点或切换方案时同步清除路段插入引导。
- 路线、控制点和拖拽手柄必须阻止点击事件冒泡为地图空白点击；虚线引导本身不承接选择事件，点击时视为取消当前路段选择。
- 点击地图点位或地址行后，地图中心移动到对应控制点且缩放级别不变；普通点击不得误触发拖拽排序。
- 移动端 H5 控制点行只常驻展示导航图标；左滑删除只处理横向主导手势，在任一方向位移达到 `8px` 前不得提前判定方向；确认向左横滑后锁定当前手势，纵向滚动、未达到阈值的滑动和取消手势不得发起删除。删除操作层只在当前行左移让出空间时露出；静止、Hover 和选中状态的行背景必须为不透明合成背景，不得透出底层删除文案。触发后仍须经过统一二次确认，不得直接删除。
- 地图点位点击更新选中状态和聚焦位置，并按需打开该控制点的七天天气卡片；点位及定位标记旁不展示删除图标，避免与编号、名称标签和定位标记发生视觉冲突。
- PC 地址列表删除图标、移动端 H5 左滑、`Backspace` 和 `Delete` 只发起删除请求，统一打开 shadcn/ui Alert Dialog；标题固定为“确认要删除此定位吗？”，操作按钮为“取消”和“删除”。
- 确认框按钮保持黑白克制：“取消”使用白底、灰色细边框和近黑文字；“删除”同样使用白底与细边框，仅以危险色文字和 Hover 边框表达破坏性语义，不使用整块危险色背景。
- 只有点击确认框中的“删除”才执行点位删除；点击“取消”或按 `Esc` 关闭确认框且不改变数据，误点遮罩不关闭确认框。
- 输入框、文本域、原生下拉框和可编辑内容获得焦点时，`Backspace` / `Delete` 不得发起删除确认。
- 异步路线计算期间保留旧路线并标记为更新中，不能闪成空白。
- 过期请求结果不得覆盖新控制点对应的状态。

## 10. 动效

| Token | 时长 | 用途 |
| --- | --- | --- |
| `motion.fast` | `120ms` | Hover、按压、图标反馈 |
| `motion.base` | `180ms` | 菜单、Toast、轻量状态切换 |
| `motion.panel` | `240ms` | Widget 展开、底部抽屉 |

- 默认缓动使用 `cubic-bezier(0.2, 0, 0, 1)`。
- 动效优先改变 `opacity` 和 `transform`。
- 定位点使用静态精度光晕，不增加持续装饰动画。
- 遵循 `prefers-reduced-motion`，关闭非必要动画。

## 11. 无障碍与可读性

- 正文与背景对比度至少达到 WCAG AA。
- 所有按钮和输入框必须具备可见键盘焦点。
- 图标按钮必须提供可访问名称和 Tooltip。
- 状态不能只通过颜色表达。
- 地图 Widget 文字必须位于实色表面，不直接压在复杂底图上。
- 纯装饰地图标记使用 `aria-hidden`，不得进入键盘焦点序列。
- `color.muted` 不用于小字号核心正文。

## 12. 性能与布局稳定性

- 地图容器、顶部工具栏、左右面板和底部区域提前预留尺寸。
- 首屏优先渲染地图容器、顶部工具栏和必要空状态。
- 图标优先使用内联 SVG 或轻量 CSS 图形。
- 避免首屏大图、背景视频和网络字体阻塞。
- 地图首次加载占位层与真实地图尺寸必须一致。
- 桌面端良好网络下 LCP 目标不高于 `2.5s`。
- 实测 CLS 必须为 `0`。

## 13. 响应式规则

- 桌面端维持全屏地图和边缘 Widget 布局。
- 窄屏顶部控件允许分组折叠，但地图始终保留主要可视区域。
- 路线顺序在移动端位于顶部路线选择器下方；路线摘要仅在选中路段后显示于底部搜索框上方，并在左侧为地图工具组预留空间。方案列表继续使用移动端抽屉。
- 地图控制按钮保持在拇指可触达区域，并避开系统安全区。
- 响应式切换不能复制领域状态或产生两套交互逻辑。

## 14. 禁止项

- 不使用彩色大面积背景或装饰渐变。
- 不将导航蓝扩展到地图覆盖物以外的通用品牌界面。
- 不使用颜色代替文字、图标、尺寸或线型状态。
- 不使用玻璃拟态和高成本背景模糊。
- 不在初始化时使用全屏方案选择弹窗阻断地图。
- 不在后续地图更新时重新显示首次加载占位层。
- 不创建脱离地图的独立路线后台。
- 不展示未经产品确认的费用数据。
- 未完成暗色地图和路线对比度验证前不提供暗色主题。

## 15. UI 验收清单

- [ ] 颜色引用语义 Token，业务组件没有无约束硬编码颜色。
- [ ] 导航蓝只用于规划路线边界、控制点、屏幕中心点和用户位置点。
- [ ] 屏幕中心点固定，用户位置点绑定地理坐标，拖动后可分离。
- [ ] IP 定位和精确定位具有明确降级反馈。
- [ ] 首次加载占位层正常退出，后续定位不隐藏现有地图。
- [ ] 双击选点不会同时触发地图放大。
- [ ] 有效路线呈现白色隔离层、蓝色边界和绿色内芯；当前路段、旧结果和失败路段仍可通过线宽及线型区分。
- [ ] 点击普通路段与闭环返程段均显示虚线和拖拽手柄；拖动过程流畅且不移动底图，松手后新控制点顺序正确。
- [ ] 再次点击当前路段、点击地图空白处和按 `Esc` 均可取消路段选择，点击路线、控制点或拖拽手柄时不会被空白点击误取消。
- [ ] 地址列表与地图控制点编号、选中和删除状态一致。
- [ ] 新增远距离控制点及道路绕行时完整路线处于安全可视区，近距离新增点不会无条件重置用户视野。

- 单次迭代的过程、问题和验证证据记录在迭代文档中。
- 规范发生行为变化时更新版本号和日期，并在代码评审中检查实现一致性。
