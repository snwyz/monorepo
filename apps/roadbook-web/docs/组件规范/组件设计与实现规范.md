## 1. 文档职责

本文档定义组件的领域归属、命名、职责边界、Props、状态管理、异步行为、样式、无障碍、性能和测试规则，回答“组件如何组织和实现”。

颜色、布局、尺寸和地图视觉规则以[UI 设计规范](../UI规范/UI设计规范.md)为准。具体交付过程和问题记录见[腾讯地图 Web 适配与路线规划体验迭代](../迭代文档/2026-09-18-腾讯地图Web适配与路线规划体验迭代.md)。

## 2. 总体原则

1. **领域语言优先**：组件名称表达业务含义，不表达页面左右位置。
2. **单一职责**：一个组件只负责一种业务展示或交互能力。
3. **依赖单向**：页面组合组件，组件调用应用 Hook，应用层依赖领域接口，基础设施实现领域接口。
4. **平台隔离**：Web 页面不直接调用高德或腾讯地图全局对象，小程序与 Web 通过 `@roadbook/map` 统一入口隔离。
5. **状态可解释**：加载、空、成功、失败、降级和旧结果必须具有明确模型。
6. **可渐进替换**：本地仓储、地图供应商和服务代理可以替换，不渗透到展示组件。
7. **性能可预测**：组件尺寸稳定、Effect 可控、请求可取消或隔离，避免无界重渲染。

## 3. 分层与目录职责

### 3.1 推荐分层

| 层级 | 目录示例 | 职责 |
| --- | --- | --- |
| 页面组合 | `app/` | 页面入口、路由和顶层布局 |
| 业务组件 | `components/<domain>/` | 领域视图和用户交互 |
| 应用编排 | `hooks/` | 用例协调、异步流程和页面状态 |
| 领域模型 | `domain/` | 实体、值对象、领域规则和纯函数 |
| 基础设施 | `infrastructure/` | 本地仓储、远程服务和平台实现 |
| 共享 UI | `components/ui/` | 无业务语义的基础控件和图标 |
| 跨端领域包 | `packages/map` | 地图领域契约及平台适配器 |

### 3.2 依赖方向

```text
页面组合
  → 业务组件
    → 应用 Hook
      → 领域模型与领域接口
        ← 基础设施实现
```

- 领域模型不得导入 React、Next.js 或腾讯地图 SDK。
- 业务组件不得读取环境变量、直接访问 `localStorage` 或拼装腾讯地图 WebService URL。
- 基础 UI 组件不得依赖路线规划领域类型。
- 平台 SDK 类型和对象不得泄漏到页面 Props。

## 4. 命名规范

### 4.1 组件命名

使用“领域对象 + 展示/交互角色”：

- `RoutePlanSelector`
- `RoutePlanWelcomePanel`
- `GlobalSearch`
- `FeaturedRoutePanel`
- `FeaturedRoutePreviewDialog`
- `RouteAddressList`
- `RouteStrategySelector`
- `RouteMetricsPanel`
- `ElevationPanel`
- `RouteMap`
- `MapProviderSwitch`

禁止使用：

- `LeftPanel`
- `RightBox`
- `TopWidget`
- `CommonComponent`
- `DataManager`

### 4.2 文件和函数命名

- React 组件文件使用 kebab-case，例如 `route-address-list.tsx`。
- 组件导出使用 PascalCase。
- Hook 使用 `use` 前缀和领域用语，例如 `useRoutePlanningWorkspace`。
- 事件 Props 使用 `on + 领域动作`，例如 `onSelectControlPoint`。
- 组件内部处理函数使用 `handle + 事件`，领域用例函数使用动词短语。
- 布尔值使用 `is`、`has`、`can` 或业务状态枚举，禁止含义不明的 `flag`。

## 5. 组件职责基线

| 组件 | 单一职责 | 不负责 |

| `RoutePlanWelcomePanel` | 仅在没有暂存路线时提供首次使用说明和新建入口 | 加载、切换或管理已有方案 |
| `GlobalSearch` | 管理关闭、发现、过滤与预览状态，组合最近搜索、分类、热门路线和地点候选 | 判断普通控制点或专题标记的写入目标、直接访问本地存储 |
| `FeaturedRoutePreviewDialog` | 展示热门路线简介、数据说明并返回加载决定 | 直接创建地图图层或修改个人路线 |
| `FeaturedRoutePanel` | 按国道分组展示完整官方控制点和用户专题标记，并提供定位与外部导航意图 | 修改专题路线、发起闭环算路 |
| `RouteAddressList` | 展示控制点顺序、编辑入口及当前供应商的控制点导航入口 | 计算路线和持久化 |

| `WeatherForecastCard` | 展示当前地图控制点的七天天气及加载、错误和重试状态 | 持有地图 SDK、修改路线方案或决定天气供应商 |
| `ControlPointDeleteConfirmation` | 展示点位删除确认并返回用户决定 | 直接修改方案或持有地图 SDK 状态 |
| `RouteStrategySelector` | 展示并切换路线策略 | 自行发起路线请求 |
| `RouteMetricsPanel` | 展示路线汇总指标 | 聚合原始接口响应 |
| `ElevationPanel` | 展示海拔和地形状态 | 计算驾车路线 |
| `MapControls` | 提供缩放和定位入口 | 持有业务方案状态 |
| `RouteFeedback` | 展示加载、失败和旧结果 | 决定错误恢复策略 |

## 6. 地图组件边界

### 6.1 领域接口

页面通过 `WebMapAdapter` 和 `WebMapCanvas` 操作地图，不直接访问 `window.AMap` 或 `window.TMap`。应用 Hook 通过 `WebMapAdapter.resolveCurrentLocation` 获取带精度语义的当前位置，并只在结果不是 IP 近似位置时自动创建路线起点。

地图画布接口负责：

- 接收包含稳定标识、顺序、地点名称、坐标和选中状态的 `WebMapControlPoint`。
- 使用单一控制点 Marker 渲染“编号＋地点名称＋引导线”，由该 Marker 同时负责视觉呈现和点位选择事件；禁止再叠加独立圆形编号 Marker。
- 高德和腾讯适配器复用 `createControlPointLabelVisual` 生成同一套标签图形，只在基础设施层转换覆盖物锚点与样式。

- 设置路线控制点；
- 设置路线分段；
- 设置当前路段插入意图，包括前后端点、初始中点和拖拽完成事件；
- 设置热门路线概览线、国道编号、官方控制点与个人标记独立图层；
- 设置用户位置；
- 更新地图中心和层级；
- 判断坐标集合是否位于扣除响应式边距后的安全可视区；
- 使用供应商原生边界能力平滑适配控制点或完整路线折线；
- 执行缩放和主动定位；
- 释放地图图层与事件监听。

地图适配器负责：

- 加载对应供应商的 JavaScript API；
- 创建对应供应商的地图实例；
- 转换领域坐标和 SDK 坐标；
- 创建 `MarkerStyle`、`PolylineStyle` 和独立图层；
- 调用服务端地图代理；
- 将平台错误转换为领域错误。

### 6.2 图层职责

| 图层 | 内容 | 更新来源 |
| --- | --- | --- |
| 控制点图层 | 带序号的路线控制点 | 活动方案控制点 |
| 用户位置图层 | `loc_icon` 用户地理位置 | IP 或浏览器精确定位 |
| 路线外描边图层 | 路线白色隔离描边 | 闭合路线分段 |
| 路线边界与状态图层 | 有效路线导航蓝边界，以及旧结果、失败路线 | 路线计算状态 |
| 路线内芯图层 | 有效路线绿色内芯；旧结果和失败路线不进入该图层 | 路线计算状态 |
| 热门路线概览图层 | G219、G331、G228 受控颜色线与白色外描边 | 当前热门路线专题 |
| 热门路线国道编号图层 | `zoom < 7` 时沿线路展示 Gxxx 标签 | 专题线路及标签锚点 |
| 热门路线控制点图层 | `zoom ≥ 7` 时展示县市、口岸和景区标签 | 完整官方控制点目录与选中状态 |
| 热门路线个人标记图层 | 用户搜索或双击添加的“我的标记” | 专题标记仓储与选中状态 |
| 路段插入引导图层 | 虚线外描边、主线与可拖拽手柄 | 当前选中路线段 |
| 屏幕中心覆盖层 | 固定于视口中心的 `center_icon` | React DOM，不属于地图坐标图层 |

每个图层必须独立更新。禁止将用户位置与路线控制点写入同一个 `MultiMarker` 后通过重建全部几何体更新。

### 6.3 地图生命周期

- 容器存在且地图适配器就绪后才创建地图。
- 初始化 Effect 必须持有销毁标记，忽略卸载后的异步回调。
- 地图实例只因适配器或稳定事件依赖变化而重建。
- 供应商切换必须先隔离旧算路结果，再销毁旧画布并创建新画布。
- 高频变化数据通过独立 Effect 调用画布更新方法，不重建地图。
- 销毁时移除地图事件、图层事件并执行图层 `setMap(null)`。
- `tilesloaded` 只用于首次地图可视就绪，不作为所有中心更新的完成条件。

## 7. Props 设计规范

### 7.1 Props 原则

- Props 使用领域类型，不传递任何地图供应商 SDK 对象。
- 数据 Props 与事件 Props 分组排列。
- 事件回调表达用户意图，例如 `onRemove`，不暴露内部实现，例如 `setItems`。
- 可选 Props 必须有明确默认行为。
- 禁止将完整工作台对象无选择地透传给下层组件。
- Props 数量持续增长时，优先检查组件职责是否过多，不立即创建含义模糊的配置对象。

### 7.2 状态归属

| 状态 | 推荐归属 |
| --- | --- |
| 全局搜索状态机和输入文本 | `GlobalSearch` 本地状态 |
| 热门路线专题与个人标记 | `useFeaturedDrivingRouteAtlas` |
| 活动路线方案 | 应用 Hook |
| 控制点顺序 | 领域方案模型 |
| 选中控制点和路线段 | 应用 Hook，传入地图和列表 |
| 地图供应商 | 应用 Hook，默认 `amap` |
| 地图实例 | `RouteMap` Ref |
| 地图瓦片首次可视状态 | `RouteMap` 本地状态 |
| 路线请求状态 | 应用 Hook |
| 用户位置缓存 | 地图适配器 |
| 路线持久化 | 仓储实现 |

可由现有 Props 推导的值不得重复存入本地状态。

`GlobalSearch` 必须使用 `closed / discovering / filtering / preview-dialog` 四个显式状态，不得以多个互相独立的布尔值拼接搜索阶段。最近搜索由 `LocalSearchHistoryRepository` 管理，热门路线由只读仓储提供，个人标记由 `LocalFeaturedRouteMarkerRepository` 按专题隔离；展示组件不得直接访问 `localStorage`。
热门路线推荐卡的名称、缩略图和约整里程均来自 `FeaturedDrivingRoute` 领域元数据；`GlobalSearch` 只负责格式化展示，不加载道路几何、不在渲染期计算专题里程。推荐区是可扩展的横向路线目录，即使当前只有一个专题也不得按数量切换成纵向列表。

## 8. Effect、Ref 与异步规则

### 8.1 Effect

- Effect 只同步外部系统，不承担可在渲染期完成的纯计算。
- 依赖数组必须完整；如果依赖导致地图频繁重建，应先稳定回调或拆分 Effect。
- 异步 Effect 使用 `disposed`、版本号或取消信号隔离旧结果。
- 禁止依赖异步结果返回顺序来保证界面正确。

### 8.2 Ref

- SDK 实例、地图画布和请求队列使用 Ref 或适配器内部字段保存。
- 最新控制点、选中状态和路线状态可用 Ref 提供给一次创建的地图回调。
- Ref 不得替代应触发视图更新的 React 状态。

### 8.3 异步请求

- 搜索输入必须防抖，并忽略过期响应。
- 闭合路线分段按顺序请求，避免瞬时并发超过地图服务 QPS。
- 路线计算使用版本号，旧结果不得覆盖新方案。
- 定位 Promise 只能完成一次，迟到回调必须忽略。
- 请求失败时优先保留已有可用内容，并明确标记为旧结果或降级结果。

## 9. 定位组件规则

### 9.1 初始化定位

1. 先请求 IP 位置。
2. 使用 IP 坐标创建地图并设置用户位置点。
3. 权限已授权时后台请求精确位置。
4. 精确位置可信时更新地图和用户位置点。
5. 失败时保留 IP 位置和可交互地图。

### 9.2 主动定位

- 点击定位按钮必须调用浏览器定位，不能因 IP 缓存提前返回。
- 使用 `maximumAge: 0` 请求最新位置。
- 定位超时为 8 秒。
- 精度误差超过 50 公里时视为不可信精确位置。
- 失败后返回 IP 近似位置，Toast 说明降级状态。
- 定位过程中不得隐藏已经显示的地图。

### 9.3 位置图标

- `center_icon` 是纯展示 DOM，不进入地图领域模型。
- `loc_icon` 由用户位置图层管理，不进入路线控制点数组。
- IP 和精确定位都可以显示 `loc_icon`，但状态字段必须保留 `approximate`。
- 精确定位成功后更新同一个几何体，不创建历史位置点。
- 地图销毁时必须清理用户位置图层。

## 10. 样式组织

- 全局 Token 和页面布局规则放在全局样式入口。
- 业务组件样式使用稳定的领域类名，例如 `.route-address-list`。
- 修饰状态使用 `.is-selected`、`.is-ready` 或 BEM 修饰符。
- 禁止使用 `.left-box`、`.red-text` 等位置型或具体颜色型命名。
- 地图 SDK 注入的 DOM 不作为稳定业务选择器依赖。
- 组件中不散落新的硬编码颜色；新增视觉语义先更新 UI 规范和 Token。
- 动效遵循 `prefers-reduced-motion`。

## 11. 交互与键盘规范

- `GlobalSearch` 关闭态点击或 `Cmd/Ctrl + K` 进入发现态并聚焦输入框；再次使用快捷键或按 `Escape` 关闭，并把焦点归还搜索入口。发现态进入过滤态时保留同一中性蒙层，避免输入过程中背景层级跳变；蒙层不进入键盘 Tab 顺序。
- `GlobalSearch` 通过 `onOpenChange` 告知任务面板搜索状态；H5 在同一容器展开并内联展示结果，桌面保留原有顶栏浮层。
- 输入非空字符进入过滤态；清空按钮恢复发现态并保持焦点，“取消”关闭搜索；每次输入立即递增请求版本，旧查询不得在新查询的防抖等待期回写。结果支持方向键与 Enter。
- 热门路线卡片只打开 `FeaturedRoutePreviewDialog`；只有用户确认“在地图中查看”后才加载专题。Dialog 打开时约束焦点，关闭时移除 `routePreview` URL 参数并恢复入口焦点。
- 专题模式的搜索选点和地图双击只能新增 `FeaturedRouteUserMarker`，不得复用 `ControlPoint` 或触发 `calculateClosedDrivingRoute`。官方路线和官方主要控制点均只读。
- 地图必须关闭原生双击放大；普通规划模式双击添加控制点，热门路线专题模式双击添加个人标记。
- 地图背景单击通过 `WebMapOptions.onMapBackgroundSelect` 表达清除选择意图；路线、控制点与拖拽手柄在地图适配器内阻止事件冒泡，页面不得判断供应商原始事件。
- 缩放通过滚轮、手势和加减按钮完成。
- `Esc`、`Delete` 和 `Backspace` 删除待确认或当前选中点时，应避免在输入框编辑期间误触。
- 图标按钮必须提供 `aria-label` 和 `title`。
- 装饰性 SVG 和定位中心点使用 `aria-hidden`。
- 按钮点击目标至少为 `40 × 40px`。
- 列表和地图选中状态必须同步，不能分别维护两套来源。
- 删除操作完成后同步更新控制点编号、路线和地址列表。
- `RouteAddressList` 使用稳定点位标识完成排序；PC 鼠标和移动端触控均需长按约 `250ms` 激活，普通点击只触发点位选择与地图聚焦。地图聚焦调用只更新中心坐标，不改变当前缩放级别。
- Sortable 位移必须将 X 轴归零，滚动容器使用 `overflow-y: auto` 与 `overflow-x: hidden`，确保排序只沿垂直轴且不生成横向滚动区域。
- 首项天然作为起点，不显示起点标签、不提供上下移动或独立设为起点操作；拖拽到首项即完成起点变更。
- PC 删除使用独立图标按钮，不进入拖拽触发区域，并提供 `aria-label` 与悬停说明。移动端 H5 隐藏拖拽与删除图标，仅保留导航图标；控制点行左滑达到 `72px` 阈值并松开时调用同一个 `onRemove` 意图回调。
- 每个控制点行使用独立导航链接，通过 `createMapNavigationUri` 按当前 `WebMapProvider` 生成官方 App Scheme，以设备当前位置为起点、该控制点为终点；导航入口不得进入路段连接行，组件不得自行重复拼接供应商参数。
- 完整路线摘要默认展示包含返程段的往返里程与往返用时，点击里程指标可同步切换为不含最后返程段的单程里程与单程用时；该展示偏好由 `RouteMetricsPanel` 的本地状态负责，不触发重新算路。选中路段时固定展示该路段里程和预计驾驶时间，不提供切换。摘要不展示红绿灯或外部导航；控制点外部导航统一由地址列表入口承担。
- 完整路线摘要标题使用“`N` 个坐标”描述当前点位数量，不展示与已有路线内容重复的“路线有效”状态标记。
- `RouteMetricsPanel` 在移动端任务面板的路线内容中展示全程或选中路段；收起态由独立精简摘要承载。
- `RouteAddressList` 在 H5 任务面板中内联展示，折叠由面板统一负责；隐藏路线内容时保持组件挂载，面板按任务模式记忆滚动位置。
- 控制点与路线方案的移动端滑动删除统一复用 `useMobileSwipeRemoval`，使用 Pointer Events 判断方向；任一方向位移达到 `8px` 前保持待判定，达到后只在横向位移主导且向左时锁定手势并更新 `transform` 反馈，不得因阈值内的触摸抖动提前取消；纵向手势交还列表滚动。子交互元素的 `lostpointercapture` 会冒泡到行容器，滑动 Hook 只允许行容器自身丢失指针捕获时重置，不得因子元素的捕获转移中断已锁定的左滑。删除操作层保持可渲染，由前景行的不透明合成背景在静止状态遮盖，左滑 `transform` 移出后自然露出；不得使用可能与 Pointer Event 更新时序失配的额外显隐状态。未达到阈值、`pointercancel` 或向右滑动时回弹，不得影响 PC 行内按钮、控制点长按排序和方案点击加载。
- `RoutePlanSelector` 在 PC 保留垃圾桶删除入口；移动端 H5 隐藏垃圾桶，方案行左滑达到 `72px` 阈值并松开时发起同一删除请求。该请求必须打开受控的 `RoutePlanDeleteConfirmation`，禁止调用浏览器原生 `alert` 或 `confirm`。滑动结束后的合成点击必须被短暂抑制，避免误加载被操作方案。
- `RoutePlanDeleteConfirmation` 复用 shadcn/ui `AlertDialog`，视觉、按钮顺序、危险色和阻断语义与 `ControlPointDeleteConfirmation` 保持一致。只有确认按钮返回删除决定，取消或 `Esc` 只关闭弹窗；组件在首次删除请求后惰性加载。
- `RoutePlanSelector` 仅在目录非空时展示标题右侧的管理菜单。活动方案存在时，“重命名当前路线”在展开面板内切换独立受控编辑区，顶部触发器始终保持单一展开/收起职责；`Enter` 或“完成”提交，`Esc` 或“取消”放弃未保存内容，留空提交恢复地点自动命名。“清除全部路线”意图交给 `RoutePlanClearConfirmation`，确认组件首次请求后惰性加载，必须展示将被清除的路线数量；只有确认“全部清除”才调用应用 Hook 的批量清除用例并收起列表。
- 批量清除用例由应用 Hook 编排：仓储仅删除自身命名空间内的目录和全部路线快照，Hook 同步终止旧算路结果并重置活动方案、地图路线、选择、历史、暂存和定位起点状态。展示组件不得直接访问 `localStorage`。
- `RoutePlanSummary` 可选保存起点和末控制点名称，供轻量目录生成可识别的路线标题；该扩展必须兼容旧目录，不允许为生成标题而在启动阶段遍历读取完整快照。
- `RoutePlanSelector` 的 PC 与移动端 H5 按本地日期对方案行分组。自定义名称优先；未重命名方案使用“起点名称 → 末控制点名称”，缺少目录地点数据时降级为“未命名路线”；辅助文字为“`HH:mm · N` 个途经点”。顶部活动方案必须从 `catalog` 中的对应摘要取同一展示名称。
- `RoutePlanSelector` 必须拆分方案行的 Hover、Selected 与删除状态：Hover 只提供轻量中性底色；Selected 使用暖白表面、内描边、淡绿色路线标记底和尾部勾选，不在滚动列表内使用容易被裁切的外投影，并通过 `aria-current` 暴露当前项。PC 悬停时尾部勾选切换为删除入口，删除入口只使用低透明暖红灰反馈；移动端隐藏删除入口并保持勾选可见。禁止用粗黑侧边条同时承担选中和装饰语义。
- 地图点位点击更新控制点选中状态，并由 `RoutePlanningWorkspace` 设置独立的天气查询目标；不得创建地图删除入口，也不得由地图适配器直接请求天气。
- `WeatherForecastCard`、天气 SVG 和 `useWeatherForecast` 必须通过 `React.lazy` 在首次 Marker 点击后进入独立分包；关闭卡片不卸载浏览器已经缓存的内容哈希资源。
- `RoutePlanningWorkspace` 将天气目标状态传给任务面板；天气、搜索、路线目录、路线编辑互斥呈现，桌面继续并列展示。
- 天气查询按控制点坐标保留最多 `16` 个客户端内存缓存，成功结果有效期为 `30` 分钟；服务端只缓存成功结果，错误响应使用 `no-store`，过期响应不得覆盖当前查询目标。
- 天气查询使用供应商无关的 `/api/weather/forecast` 领域入口，展示组件只消费归一化的 `WeatherForecast`，不得解析腾讯原始响应或读取地图 Key。
- 高德与腾讯适配器必须复用 `map-overlay-style` 中的地图语义颜色和线宽；有效规划路线按白色外描边、蓝色边界、绿色内芯分层渲染，旧结果与失败路线只进入状态图层。绿色内芯不得被描述为实时交通状态。
- 路线段点击由应用 Hook 维护单一选中状态，`RouteMap` 将选中路段的相邻控制点投影为 `WebMapRouteLegInsertion`。高德使用可拖拽 Marker；腾讯通过手柄覆盖物事件配合 Map 移动事件，并在拖动期间临时关闭底图拖拽。供应商差异不得泄漏到组件 Props。
- `selectRouteLeg` 使用当前路段 ID 做 toggle；`clearRouteLegSelection` 统一承接地图空白点击与非输入状态下的 `Esc`，禁止由地图组件直接修改 React 状态。
- 路段插入提交后，应用 Hook 必须再次校验原路段两端仍是当前方案中的相邻控制点；通过后在二者之间创建正式 `ControlPoint`。闭环返程段的新点追加到数组末尾。插入操作进入统一历史、逆地址解析、自动暂存和路线版本隔离链路。
- 列表删除入口、移动端左滑、`Backspace` / `Delete` 通过工作台设置同一个待删除点位，不得直接调用删除用例。
- `ControlPointDeleteConfirmation` 使用受控的 shadcn/ui Alert Dialog；仅确认按钮调用删除用例，取消和 `Esc` 只清理待删除状态，遮罩交互遵循 Alert Dialog 的阻断语义。
- Alert Dialog 基础确认按钮保持中性描边；点位删除场景通过局部危险色文字和 Hover 边框覆盖表达语义，禁止使用大面积危险色填充。
- 键盘事件目标为输入、文本域、下拉框或可编辑内容时直接忽略；确认框打开期间不得重复发起删除请求。
- 点位删除确认组件在首次删除请求后惰性加载，避免进入首屏关键资源链路。

## 12. 加载、空状态与错误状态

每个异步组件至少定义以下状态：

| 状态 | 行为 |
| --- | --- |
| `idle` | 显示可开始操作的默认界面 |
| `loading` | 保留稳定尺寸，显示局部反馈 |
| `success` | 显示最新有效数据 |
| `empty` | 说明没有数据并提供下一步动作 |
| `error` | 显示可理解错误和恢复入口 |
| `stale` | 保留旧数据并说明正在更新 |
| `degraded` | 展示降级结果及其精度或能力限制 |

- 地图首次初始化可以使用全屏等尺寸占位层。
- 后续地图更新不得重新使用首次占位层。
- 地址解析失败保留坐标和删除能力。
- 路线单段失败时保留其他状态并指出失败段。
- 错误文案不得直接向用户暴露密钥、签名或完整第三方响应。

## 13. 基础组件规则

### 13.1 Button

- 使用明确的 `primary`、`secondary`、`ghost` 和 `danger` 语义变体。
- 一个 Widget 最多一个主按钮。
- 加载状态保持按钮原尺寸并防止重复提交。
- 禁用状态必须提供不可操作原因或上下文说明。

### 13.2 SearchInput

- 输入值由组件控制，搜索请求由外部用例注入。
- 清空输入同步清空候选结果。
- Enter、候选点击和快捷键必须汇聚到同一选择用例。
- 错误、无结果和加载状态在候选区域显示。

### 13.3 Panel 与 Widget

- Panel 表达一组持续任务，Dialog 只用于必须阻断的确认。
- 路线方案选择属于持续任务，使用侧边 Panel，不使用启动模态框。
- 收起后保留稳定触发器，不改变地图容器尺寸。
- 内容过长时只滚动面板内容，不滚动整个地图页面。

### 13.4 Toast 与反馈

- Toast 用于短暂结果说明，不承载必须操作的信息。
- 定位、暂存和轻量失败提示可使用 Toast。
- 需要用户选择或修复的错误必须显示在对应 Widget 内。
- 相同错误不得无限叠加 Toast。

### 13.5 Select 与路线计算反馈

- 路线策略使用 shadcn/ui `Select`，不得回退到浏览器原生 `<select>`。
- `RouteCalculationFeedback` 只消费路线计算状态和控制点数量，在地图视觉中心使用固定尺寸浮层展示。
- 路线计算浮层不拦截地图与控制点编辑，不通过增减文档流高度实现显示和隐藏，目标 CLS 为 0。

### 13.6 地图供应商选择器

- `MapProviderSwitch` 在桌面端和移动端共用折叠图标形态，自身只表达供应商选择意图。
- 组件使用 `amap` 与 `tencent` 领域值生成选项，并将变化提交给应用 Hook。
- 临时展开状态由组件本地管理；图标按钮提供键盘操作、可见焦点、`aria-expanded`、当前供应商及展开/收起语义。
- 供应商选项保留文字和当前状态图标，选项组提供可访问名称；加载期间禁止重复切换。

## 14. 性能与稳定性

### 14.1 ECMAScript 兼容性基线

- `@roadbook/map` 同时服务 Web 与小程序，其 `tsconfig.json` 中的 `lib: ["ES2019", "DOM"]` 是当前代码兼容性上限，不是可随单次实现任意提高的编译选项。
- 地图包不得直接使用 ES2020 及以上才提供的内建 API。典型禁用示例包括 `Array.prototype.at()`、`String.prototype.replaceAll()`、`Promise.any()` 和 `Object.hasOwn()`；应使用 ES2019 等价写法，或在经过运行环境评估后引入明确且可验证的 polyfill。
- TypeScript 的 `target` 和 `lib` 不会自动为内建对象方法提供运行时 polyfill。禁止仅通过提高 `lib` 来消除 `TS2550`，否则可能把构建错误转化为旧环境运行时错误。
- 引入不确定版本的 JavaScript API 前，必须核对其 ECMAScript 版本和 `packages/map/tsconfig.json`。如确需提升基线，必须同时更新跨端兼容矩阵、构建配置、文档和运行时验证，不得作为局部修复处理。
- 修改 `packages/map` 后先运行 `rtk pnpm --filter @roadbook/map build`，再运行受影响应用或 `rtk pnpm build`，防止应用自身的 `esnext` 类型环境掩盖共享包构建错误。

### 14.2 性能与布局稳定

- 同一供应商生命周期内地图实例只创建一次，数据变化通过图层增量更新。
- 首屏不加载与当前任务无关的重型组件。
- 避免在渲染函数中创建大型坐标数组副本。
- 高频地图事件必须节流或只在交互结束时同步 React 状态。
- 路段插入手柄的高频移动只在地图适配器内部更新图层；只有拖拽结束才向应用 Hook 提交坐标，禁止在拖动过程中连续更新 React 状态或请求算路。
- 组件加载占位尺寸与最终尺寸一致，目标 CLS 为 0。
- 首屏关键资源不依赖网络字体和大图。
- 桌面端良好网络下 LCP 目标不高于 `2.5s`。
- 新增 SDK 图层时必须在销毁流程中释放。
- 高德与腾讯切换时旧地图实例、覆盖物和事件监听必须完整释放。

## 16. 新组件准入清单

新增或重构组件前确认：

- [ ] 组件名称使用领域语言，不依赖页面位置。
- [ ] 组件只有一个主要职责。
- [ ] Props 使用领域类型，没有 SDK 或基础设施对象泄漏。
- [ ] 状态归属明确，没有重复保存可推导状态。
- [ ] 加载、空、错误和降级状态已定义。
- [ ] 交互具备键盘和无障碍支持。
- [ ] 样式使用现有 Token，新增视觉语义已更新 UI 规范。
- [ ] 异步结果具备取消、版本或过期隔离机制。
- [ ] 不会导致地图实例重建或页面布局跳动。
- [ ] 相关类型检查、构建和浏览器验证已完成。

## 17. 持续迭代规则

- UI 视觉规则变化时先更新 UI 规范，再修改组件实现。
- 组件契约、分层或状态模型变化时更新本规范。
- 单次功能交付、问题和验证证据记录到 `docs/迭代文档/`。
- 参考需求和历史设计保留在 `docs/refel/`，不得作为当前规范的唯一来源。
- 评审时同时检查代码、UI 规范、组件规范和迭代文档是否一致。

### 路段列表插入契约（2026-09-26）

- `RouteAddressList` 通过 `onAddWaypoint(fromId, toId)` 提交插入意图，使用 `addWaypointDisabledReason` 表达点位已满或地图不可用；普通路段与返程段一致。
- 工作台保存方案 ID 与路段两端 ID，调用 `GlobalSearchHandle.open()` 聚焦既有搜索，显示地点上下文；搜索关闭后清除插入意图。插入模式不展示热门路线。
- `insertPlaceCandidate` 在提交时校验活动方案、相邻关系与 20 点限制；失效时提示重新选择，不退化为末尾追加。成功后进入统一历史、暂存、聚焦和算路链路，直接采用候选地点地址。

## 18. H5 任务面板与性能契约（2026-09-26）

- `WorkspaceTaskSheet` 只负责档位、标题/返回入口、滚动记忆、手势与视口几何，不读写路线仓储、不调用地图 SDK。
- 桌面通过 `display: contents` 复用同一业务组件树，H5 通过 CSS 媒体查询直接选择首屏布局。
- 工作台显式管理 discovery/catalog/planning/guide 与当前详情，`WorkspaceSheetPage` 声明页面是否活动，容器不通过组件类名推断业务。最多两层，不把切换业务当作继续下钻。
- 整块面板通过非被动 touchmove 分配纵向位移；8px 阈值区分点击，方向锁保留横向操作，已激活排序不被截获。取消手势恢复原档位。
- `consumeSheetMovement` 是纯函数：上拉先消耗展开空间再滚动，下拉先消耗内容滚动再收起；释放速度使用最后移动样本，静止后不继续惯性。
- 拖动期间仅修改 CSS 几何变量与滚动位置，不更新 React 业务状态；结束后通过 `onOcclusionChange` 提交高度，地图保留实例，仅在安全区不足时适配。
- 默认档位 medium，业务切换不改档位；搜索打开展开，关闭后恢复；输入同步聚焦以支持移动浏览器用户激活，清空与关闭是独立操作。
- `RouteAddressList`、`RouteStrategySelector`、`FeaturedRoutePanel` 按需分包；加载占位有明确尺寸。
- 固定 URL 的专题几何采用 `no-cache` 重验证与 ETag，内存复用在途 Promise，错误清除 Promise；不得改为无限强缓存。
- `WebVitalsReporter` 只在 localhost/127.0.0.1 输出指标名、数值和评级，不含坐标、路线或资源 URL，不向外部上报。地图首次 ready 单独记录。
- 吸附几何测试：`node --experimental-strip-types --test apps/roadbook-web/components/route-presentation/workspace-sheet-geometry.test.mjs`。


### 18.1 后续迭代回归口径

- 分别维护业务页面、详情选择、搜索状态与面板档位；不得用“打开某功能”的回调隐式重设用户档位。
- 滚动位置按页面键保存，切换前保存父页面位置；不能在新内容已经截短滚动范围后才读取旧位置。验证时注意自动化定位器的自动滚入视野可能改变测试前提，必要时用可见坐标点击复核。
- 手势测试覆盖：从标题、按钮与地点行起手；上拉展开后继续滚动；下拉回顶后继续收起；方向锁、点击抑制、取消、边界、搜索前后档位与详情返回位置。
- LCP、CLS 与地图首次可用时间分别记录；固定设备/视口、网络与缓存条件后比较基线。冷启动、缓存命中、弱网、完整业务流程分别报告，不能混为一个结果。
- 包体积明确统计范围、压缩口径和构建版本；当前基线是首页 HTML 引用的首方 JS 各文件 gzip 后求和，包含框架、不包含第三方 SDK。
- 地图图层导致的布局偏移仍计入 CLS；区域分类仅用于定位原因，禁止过滤掉偏移以制造达标数据。
- 静态哈希资源可长期 immutable 缓存；固定 URL 专题数据使用重验证；错误不永久缓存。变更缓存策略时同时验证更新可见性与失败重试。
- 真机验证覆盖 iOS/Android 触摸、软键盘、浏览器地址栏变化和长按排序竞争；鼠标拖动与几何单测不替代这些验收。
