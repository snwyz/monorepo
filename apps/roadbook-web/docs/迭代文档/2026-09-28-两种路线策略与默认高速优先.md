# 两种路线策略与默认高速优先

## 目标与范围

PC 与 H5 的路线策略收敛为“高速优先”“不走高速”，新方案默认高速优先。移除推荐、国道参考和全局禁用高速选项的旧呈现；布局不变。

## 关键决策与问题根因

旧界面同时提供推荐与高速选项，但将高速选项固定禁用；腾讯适配器还将 highway 映射为普通时间最短，无法保证文案与行为一致。

- Web 领域策略缩小为 highway / avoid-highway，新建方案及算路兜底默认为 highway。
- 高德使用 strategy=19（高速优先）、13（不走高速）；代理允许 19，保留 10/20 的旧调用兼容。
- 仓储主动加载旧方案时将 recommend、缺失或未知策略归一为 highway；avoid-highway 保持不变。点位、顺序、修订及时间等数据不变，load 本身不直接写入存储，后续沿用已有自动暂存流程。
- 地图包的 recommend 类型暂时保留，避免破坏旧调用者。

## 能力与降级边界

[高德路径规划文档](https://developer.amap.com/api/webservice/guide/api/direction) 明确列出 19 和 13 的含义。高速优先不承诺全程高速，不走高速不限定国道或免费。

当前接入的[腾讯驾车接口文档](https://lbs.qq.com/webservice_v1/guide-road.html) 未列出高速优先参数，不采用未经确认的扩展参数。腾讯遇到 highway 时在请求前明确返回“当前腾讯地图接口不支持高速优先，请切换高德地图，或选择不走高速”，不静默回退。后续取得该接口能力确认后再接通。

## 验证

- 仓储测试覆盖新方案默认值、旧 recommend、高速、不走高速及缺失策略的加载；核对点位与元数据保留，确认加载不直接写入存储。
- 地图包 ES2019 构建通过；Web lint、生产构建通过。
- Browser 加载旧三点方案后显示高速优先，实际返回高德路线与里程摘要；下拉仅显示两个可用选项。
- 浏览器检查策略切换和 H5 共用选项，未对腾讯未知能力进行真实请求或宣称支持。
- 未增加首屏依赖或请求；LCP/CLS、真机手势并未重测。

## 下拉宽度对齐

取消策略菜单固定的 224px 最小宽度，改用 `--radix-select-trigger-width` 同时设置 width 与 min-width，沿用 align=start，使菜单两侧与当前触发框一致。仅影响策略菜单，不改变全局 Select 或业务行为。浏览器验证 PC 菜单与触发框均为 191.875px，左右差值为 0；H5 也按其触发框宽度对齐。生产构建、git diff --check 通过，未新增运行时测量或首屏请求。
