# 全屏地图工作台整页缩放策略

## 目标

让 Roadbook Web 按全屏地图 App 式工作台运行，避免浏览器整页缩放改变地图与浮动 Widget 的整体视口关系。

## 范围

- 通过 Next.js viewport 元数据限制整页缩放。
- 地图画布补充触摸与 Safari 手势保护，覆盖从 Marker 标签起手的捏合操作。
- 保留地图自身的滚轮、触摸手势和地图工具按钮缩放。
- 同步 UI 设计规范中的交互基线。

## 关键决策与功能变化

- `viewport` 设置 `maximumScale: 1` 和 `userScalable: false`；页面初始缩放仍为 1，并保留 `viewport-fit=cover`。
- 桌面端地图缩放继续由地图滚轮和工具按钮控制；移动端地图缩放继续由地图触摸手势和工具按钮控制。
- 限制浏览器整页缩放是工作台交互选择，不代表地图渲染性能会因此提升。

## 问题与根因

全屏地图和浮动 Widget 共同构成单页工作台。浏览器级整页缩放会缩放整个视口内容，和地图自身缩放属于不同层级；此前 viewport 未表达禁止整页缩放的产品策略。

2026-09-28 用户反馈：双指缩放从 Marker 上起手时，地图标签与底部面板一起被放大。源码确认原方案只有 viewport 元数据，地图画布缺少手势保护；高德 Marker 使用独立覆盖物并隔离点击冒泡，不能依赖底图的手势处理兜住所有覆盖物。Safari 允许忽略 viewport 缩放限制，见 [WebKit 官方说明](https://webkit.org/blog/7367/new-interaction-behaviors-in-ios-10/)。这是与反馈一致的代码缺口，具体真机事件链仍需复测。

## 2026-09-28 Marker 起手缩放修复

- 画布增加 `touch-action: none`，把地图区域手势交给地图 SDK。
- `bindMapViewportGestureGuard` 在画布捕获阶段以非被动监听处理 `touchstart`、`touchmove`，仅在多指时取消默认行为；同时处理 Safari 的 `gesturestart`、`gesturechange`。
- 不调用 `stopPropagation`，保留 SDK 接收事件；不接管单指、点击、滚轮、任务面板和搜索输入。
- 监听随画布组件挂载和卸载，不随 Marker 重建重复绑定，供应商切换继续生效。
- 无新依赖、布局尺寸变更、逐帧 React 状态或额外地图请求；LCP、CLS 无回退仍需实测，不能以静态检查代替。

## 降级策略

浏览器或系统辅助功能可能覆盖 viewport 缩放限制；画布范围内补充事件保护，不全局拦截面板和输入区域。系统级辅助缩放不在本次控制范围内。

## 验证结果

- 静态确认 Next.js viewport 元数据包含 `maximumScale: 1` 与 `userScalable: false`。
- 未进行真机浏览器矩阵验证；整页缩放限制的实际执行仍受浏览器和系统设置影响。
- 2026-09-28：3 项事件回归测试通过，覆盖多指取消、单指/点击/滚轮保留、Safari 手势、地图外事件隔离与监听清理。Node EventTarget 测试只证明事件取消与清理契约，不证明浏览器真实冒泡链或地图 SDK 捏合行为。
- Web ESLint、生产构建（含 TypeScript 检查）与 `git diff --check` 通过；构建自动改写的 `next-env.d.ts` 已恢复。
- 未执行实际页面操作；用户确认自行手工验证。iOS 真机从 Marker 起手捏合、高德/腾讯 SDK 缩放及 LCP/CLS 仍待验收，尚无通过结论。

## 已知边界与后续建议

- 该改动不降低地图瓦片加载、地图图层绘制或路线更新的计算量，不能作为地图卡顿修复。
- 若后续出现缩放相关卡顿，应区分浏览器整页手势和地图 SDK 缩放操作后，再按对应渲染链路排查。
- 真机验收需覆盖高德与腾讯：双指均在标签上、一指标签一指底图、底图起手、连续捏合、Marker 点击、单指平移和面板滚动；确认 `visualViewport.scale` 保持 1 且地图自身层级变化。
