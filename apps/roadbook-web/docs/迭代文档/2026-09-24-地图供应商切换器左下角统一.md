# 地图供应商切换器左下角统一

## 目标

将桌面端地图供应商切换器从右下角移动到左下角，并与 H5 统一为“地图图标入口、向右展开选项”的紧凑交互。

## 范围

- `MapProviderSwitch` 的桌面端呈现与定位。
- 桌面端和移动端共享的紧凑选择器样式。
- 产品、UI、组件规范与稳定 AI 上下文同步。

不修改地图供应商切换用例、地图实例生命周期或算路逻辑。

## 关键决策

- 删除桌面端专用的长条 Switch 呈现，所有视口共用一套紧凑组件结构。
- 桌面端入口固定在左下角、缩放与定位工具组下方，保持 `14px` 视觉间距。
- 收起状态外框宽度为 `42px`，内部触发按钮为 `34px`，与缩放、定位工具组使用相同宽度基线。
- 移动端继续受底部搜索框和安全区约束，入口保持在工具组上方。
- 选项始终向右展开，以勾选图标和字重共同标识当前供应商。
- 桌面端地图来源文字恢复到右下 `16px` 安全边距，不再为已移走的长条切换器预留 `224px` 空间。

## 功能变化

- 桌面端不再常驻展示“高德地图—Switch—腾讯地图”长条控件。
- 左下角默认只显示地图图标；点击后显示“高德 / 腾讯”，选择后自动收起。
- 加载期间图标和选项保持禁用，避免重复切换。
- 桌面端地图来源文字位于右下角，与左下操作区分离。

## 问题与根因

原组件同时维护桌面长条 Switch 和移动端紧凑入口两套 DOM 与样式。桌面控件占据右下地图空间，且与左下已有地图工具形成分散的操作区域，不符合本次统一到 H5 交互的目标。

## 降级策略

- 切换逻辑和供应商状态未改变；样式异常时不影响当前地图继续显示。
- 控件继续使用绝对定位浮层，不改变地图容器尺寸，CLS 目标保持为 `0`。

## 验证结果

- `roadbook-web` TypeScript 检查通过。
- `roadbook-web` ESLint 检查通过。
- Next.js 生产构建通过，正常生成全部 `13` 个路由。
- `git diff --check` 通过，新文档未发现行尾空白。
- 静态布局核对确认：桌面端入口为左侧 `16px`、底部 `16px`，收起外框与缩放、定位工具组均为 `42px`；工具组底部为 `76px`，两者垂直间距为 `14px`；移动端原有安全区定位保持不变。
- 未调用未经授权的浏览器 Skill；真实点击、展开动画和地图版权区域遮挡留待人工验收。

## 已知边界

- 桌面端展开后的选项需要在真实地图版权信息和不同视口宽度下人工复核遮挡情况。
- 未授权使用浏览器 Skill，本次不自动执行真实浏览器点击验收。

## 后续建议

- 若未来增加第三个地图供应商，应评估选项展开宽度和键盘方向键导航，而不是恢复长条 Switch。
