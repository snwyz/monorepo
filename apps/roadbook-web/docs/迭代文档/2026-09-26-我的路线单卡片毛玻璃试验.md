# 我的路线单卡片毛玻璃试验

## 目标与范围

用户希望先看一张 iOS 风格卡片，再决定是否推广。本次仅调整桌面左上角「我的路线」入口，不修改展开目录、其他 Widget 或 H5 任务面板。

## 关键决策与功能变化

- 入口保留 330×56px 外框，使用低遮盖白色至冷灰渐变、10px 背景模糊、160% 饱和度、低透明顶边反光和低对比阴影。
- 鼠标、笔与触点通过 Pointer Events 驱动局部径向高光，离开或取消后淡出；触点抬起后结束反馈。
- 高光按 requestAnimationFrame 合并 CSS 变量更新，不进入 React 状态、不触发地图请求，不捕获指针或阻止原手势。
- 样式使用独立 CSS Module；UI 规范和项目入口同步明确这是单卡片例外。

## 问题与根因

原规范明确排除玻璃材质，需按当前用户要求增加局部试验条款。H5 路线目录没有独立入口卡片外壳，因此保留统一任务面板结构，避免为了材质增加重复容器。

## 降级策略

不支持背景滤镜时使用实色暖白底；减少动态效果时隐藏高光并停止跟随更新；减少透明度、增强对比度和强制颜色模式使用实色。保持原有键盘焦点和业务语义。

## 验证结果

- 环境没有 rtk，使用等价 pnpm 命令：Web lint、typecheck、build 均通过；构建改写的 next-env.d.ts 已恢复。
- 首版实际浏览器确认 blur(18px) saturate(1.35) 与半透明渐变生效，卡片外框仍为 330×56px。
- 鼠标移动时高光坐标从 (83,23) 更新为 (263,33)；离开后移除高光透明度变量。
- 鼠标点击展开/关闭、Enter 关闭目录正常，保留键盘焦点。
- 390×844 窄屏检查：路线目录继续由任务面板承载，背景透明且 backdrop-filter 为 none；检查后恢复桌面视口。
- git diff --check 通过。

## 已知边界与后续建议

本次是桌面单卡片视觉试验；触摸代码已兼容 Pointer Events，但 iOS/Android 真机触摸、辅助功能偏好和 LCP/CLS 前后对比尚未实测，不能宣称全面性能验收通过。待用户确认材质方向后再决定其他卡片和 H5 面板的应用范围。

## 第二版：增强材质与触点反馈

用户反馈首版质感偏弱、白边明显、高光几乎不可见。原因是底色遮盖率高且与白色高光接近，白色外边框、顶边和高光内描边又叠加成了明显白框。

- 底色透明度由 78%/52% 降至 38%/24%，末端带少量冷灰；模糊由 18px 调整为 10px，保留更多底图色彩变化，饱和度调整为 160%。
- 去掉整圈白边与高光内描边，使用 12% 冷灰边界及 30% 顶边反光，保持外框尺寸不变。
- 高光收拢至 68×54px 渐变半径，增加 112×88px 淡冷灰过渡；明确高光位于背景之上、文字之下，保持内容清晰。
- 浏览器确认新材质计算样式生效，高光横向移动时 CSS 坐标同步变化，离开后透明度变量清除。Web lint、生产构建（含 TypeScript）通过，git diff --check 通过。
- 继续只试改桌面入口卡片；真机触摸与性能对比尚未实测。

## 第三版：高光范围减半

用户确认材质和白边已修复，仅要求缩小移动高光。亮区渐变半径由 68×54px 改为 34×27px，外围过渡由 112×88px 改为 56×44px；透明度、材质、边缘和交互逻辑保持不变。

验证：实际浏览器计算样式已确认两层渐变半径减半；git diff --check 通过。本轮仅修改 CSS 半径，未重复生产构建。

## 第四版：推广到全部卡片

### 目标、范围与关键决策

用户认可第三版样张，要求应用到所有卡片。将单卡片 CSS Module 与独立 Hook 替换为共享 `glass-surfaces.css` 和根布局中的 `GlassSurfaces`，组件显式声明 `data-glass`，不通过运行时猜测业务类名。覆盖路线目录、搜索、欢迎、策略、地址、指标、地形、天气、专题、地图工具、反馈、确认框、选择菜单、通知和手机任务面板。

独立表面保持样张的透明度、10px 模糊、160% 饱和度和 34×27px／56×44px 高光半径；上层菜单、通知与确认框提高底色遮盖保证可读性。内部卡片不重复模糊，H5 的地址、策略、指标和天气外壳继续展平，由任务面板可见高度背景承担毛玻璃。

### 实现与问题修复

- 单组被动捕获监听兼容 Portal、懒加载组件和主触点；每帧只更新最近的有效表面，不进入 React 状态，不捕获指针，不阻止原有手势。
- 高光直接绘制在背景层，保留定位、布局和键盘焦点。滚动、取消、触点抬起、失焦、偏好变化和卸载时清理。
- 去除地址列表与指标内层实色遮盖，保留选中和今天语义。图片保持原内容，不覆盖图像。
- 半透明列表可能提前透出背面的左滑删除提示：默认隐藏，真正滑动时显示；滑动行暂用实色遮住重叠部分。
- 减少透明度、强制颜色、增强对比度和不支持滤镜时回退实色；减少动态效果关闭跟随。

### 验证与边界

- Web lint、typecheck、生产构建通过；未改动地图包。构建产生的 next-env.d.ts 路径变化恢复为原开发路径。
- 实际浏览器验证搜索材质与小范围高光、路线目录、管理菜单、取消清除确认（未执行删除）、加载已有三点闭环路线、策略下拉、地址、指标和七天天气；Portal 确认框及选择菜单计算样式均为 10px 模糊。
- 390×844 下确认背景只覆盖可见面板高度，内部容器展平；档位键盘切换、详情返回正常。短距离鼠标模拟左滑后回弹到 0px、删除底层隐藏、保持 medium 档位。
- 真机触摸、软键盘、GPU 帧率与 LCP/CLS 前后对比尚未实测，不能据此宣称性能无回退；此边界保留后续验收。

## 第五版：左右目录背景模糊一致性

用户发现左侧路线目录仍能清楚看到地图道路，而右侧路线顺序正常模糊。根因是路线目录位于带 backdrop-filter 的入口外壳内部；祖先创建的背景采样边界使弹出目录无法采样外壳范围以外的地图。仅比较 computed style 中相同的 blur 数值不能证明实际模糊一致。

将玻璃声明由 RoutePlanSelector 外壳移至入口按钮，使入口和展开目录成为同级滤镜表面。外壳只保留透明边框与圆角几何，仍为 330×56px；目录和右侧面板共用原有材质参数，业务与 H5 展平行为保持不变。

实际浏览器确认外壳 backdrop-filter 为 none、入口与目录均为 blur(10px) saturate(1.6)；截图复核左侧底图已模糊，与右侧一致。共享规范补充不得在包裹外溢卡片的祖先上添加背景滤镜。降级规则继续复用共享样式。

本轮 Web lint、生产构建（含类型检查）及 git diff --check 通过；已恢复构建自动修改的 next-env.d.ts。

## 第六版：内部元素适配透光背景

用户指出卡片已透光，但新建规划、计数、标签等仍为实色，材质不协调。本轮增加共享控件背景 Token，统一中性填充、白色填充、悬停及边界透明度；不设置整体 opacity，也不修改正常文字颜色。

覆盖新建按钮、计数徽标、搜索分类与历史、关闭/返回入口、输入框、描边确认按钮、图例、天气重试、普通地点编号底色和 H5 添加/导航操作。基础 Button 及确认框动作显式声明 data-variant 供材质适配，语义事件和 Props 不变。活动方案内层底色适度降低遮盖；普通 H5 地址/路段实色背景改为透明，保留选中和左滑遮挡行为。

实际浏览器确认：桌面和 390×844 手机端「新建规划」均为 38% 背景、文字 rgb(28,28,28)、opacity=1；搜索分类与手机添加入口同样使用透光底色，原文字色值保持不变。辅助功能回退使用实色 Token，原真机性能验收边界继续保留。

本轮 lint、生产构建（含类型检查）、git diff --check 通过。编号白底降至 32% 后，额外确认导航蓝描边保持 rgb(10,132,255)。

## 第七版：清理 H5 原样式中的实色残留

用户截图指出搜索框圆角外有矩形底色、已存路线仍呈不透明白色。全局检索发现任务面板原样式保留多处 #f6f5f3，搜索展开状态的高优先级选择器和路线行外壳还会遮住共享玻璃材质。

直接将搜索外层、路线行外壳、普通地址和路段等背景改为透明；搜索、新建、导航与地点操作控件采用共享半透明 Token。同步移除全局手机路线行的实色默认背景，保留文字色、选中语义及滑动中的遮挡处理。Web 内已无 #f6f5f3 匹配。

390×844 实际浏览器检查：关闭及展开搜索的外层背景均为透明；路线行外壳透明，活动路线仍使用 48% 到 36% 的渐变材质。截图复核搜索圆角外的矩形底色已消失。生产构建（含类型检查）通过；恢复 next-env.d.ts 开发路径。真机与性能验证边界同前。

## 第八版：路线统计的数字层级与留白

浏览器验证 390px 与 320px 手机宽度、桌面指标无横向溢出，指标左边框为 0px；实际点击单程及往返切换正常。真机与性能对比仍未实测。

本轮 Web lint、生产构建（含类型检查）与 git diff --check 通过；构建声明路径已恢复。
