# 全局系统字体策略

## 目标

将 Roadbook Web 的全局排版收敛为 Apple 设备优先的系统字体策略，同时保持 Windows 和其他平台的原生可读性，且不引入网络字体造成首屏阻塞或布局偏移。

## 范围

- Web 应用的全局无衬线字体 Token。
- `body` 及继承全局字体的按钮、输入框和选择控件。
- UI 设计规范中的字体基线。

本次不调整字号、字重、行高、组件布局或路线方案的日期呈现规则。

## 关键决策

- 使用 `-apple-system` 和 `BlinkMacSystemFont` 优先选择 Apple 平台系统字体。
- 保留 `SF Pro Text`、`SF Pro Display` 和 `PingFang SC` 作为本机字体候选，但不打包或分发字体文件。
- Windows 使用 `Segoe UI` 和 `Microsoft YaHei` 降级，避免强制跨平台使用 Apple 字体。
- 以 `--rb-font-sans` 作为单一全局 Token，并映射到 Tailwind `font-sans`，避免多处字体栈漂移。

## 功能变化

- 移除全局字体栈首位的 `Inter`，Apple 设备不再因本机安装 `Inter` 而覆盖系统字体。
- 全局组件继续通过 `font: inherit` 共享同一字体基线。
- 未新增字体请求、首屏资源或异步字体切换。

## 问题与根因

原字体栈将 `Inter` 放在系统字体之前。项目虽然没有下载 `Inter`，但用户设备如果已安装该字体，浏览器仍会优先选用，导致 Apple 设备的实际排版与期望的系统字体策略不一致。

## 降级策略

- Apple 系统字体不可用时，按顺序回退到苹方、Helvetica Neue、Segoe UI、微软雅黑和通用无衬线字体。
- 不通过网络补载字体，确保离线和弱网环境下仍可立即排版。

## 验证结果

- `rtk pnpm --filter roadbook-web lint` 通过。
- `rtk pnpm --filter roadbook-web build` 通过，全局 CSS 由 Next.js 生产构建正常处理。
- `rtk git diff --check` 通过。
- 路线方案标题、列表标题与搜索文本已使用 `min-width: 0`、单行省略和固定行高防护，字宽细微变化不会推动 Widget 尺寸。
- 本次未调用未授权的浏览器操作 Skill，未执行实际设备截图对比。

## 已知边界

- Web 字体渲染受操作系统、浏览器和本机字体可用性影响，不保证非 Apple 平台与 macOS 像素级一致。
- 系统字体升级可能带来细微的字形和字宽变化，组件仍需保留弹性宽度与文本省略策略。

## 后续建议

- 后续调整排版层级时继续复用全局 Token，不在业务组件中重复声明字体栈。
- 若未来引入品牌字体，需要单独评估授权、字库体积、字体交换导致的 CLS 与首屏加载成本。
