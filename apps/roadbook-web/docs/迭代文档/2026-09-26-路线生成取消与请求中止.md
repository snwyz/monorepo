# 路线生成取消与请求中止

## 目标与范围

响应路线生成等待较久的问题，在地图中央加载浮层增加 × 取消图标，覆盖高德、腾讯地图。保留现有闭合路线和限流规则。

## 问题与根因

- 两个控制点也有去程、返程两个串行请求，全部完成才显示路线。
- Hook 有 400ms 防抖；两套适配器的请求开始间隔至少 650ms，服务端单次供应商调用超时为 10 秒。实际耗时还受网络和供应商响应影响，不能把这些配置直接等同于截图中的实测耗时。
- 原来 Hook 只用版本号忽略旧结果；旧的在途请求并未中止，可能延迟同一适配器队列中的后续请求。
- 本次未采集用户截图对应请求的时序，不能确认该次具体慢响应来源。

## 关键决策与功能变化

- 浮层右侧新增 44px 点击区的 × 图标，提供可访问名称、原生标题提示和键盘焦点。只让取消按钮接收点击，文字与加载图标继续允许操作地图；限制浮层宽度以适应窄屏。
- 取消清理防抖定时器、失效旧版本，并通过 AbortController 中止浏览器请求。
- 适配器在排队前后、节流等待后和响应后检查取消，停止后续路段；保留 650ms 节流，不提高 QPS。
- 用户编辑、切换方案/供应商或卸载触发 Effect 清理时同样中止旧请求。
- 新增 cancelled 状态，关闭加载浮层，清除路线、摘要指标及路段选择，保留控制点和本地方案。
- 同一输入取消后不会因地址解析、地图连接完成等更新自行恢复；改变点位、策略、供应商或切换方案后允许重新生成。
- 同步产品基线、UI 规范、组件规范及适配器可选 AbortSignal 契约。

## 降级与已知边界

- 取消不作为算路失败显示，也不删除控制点。需要生成时点击“再次生成”，或调整点位、策略。
- 已发送到服务端的供应商请求可能仍完成，本次中止浏览器等待并阻止后续路段，不保证撤销供应商计费或配额消耗。
- 节流定时器最多等待剩余的 650ms 后检查取消，不会继续发请求；界面取消立即生效。
- 未新增缓存或并发请求，供应商本身响应慢仍可能影响新的完整计算。

## 同日补充：取消后再次生成

- 目标：在“已取消路线生成”摘要原位置提供直接恢复入口，无需改动点位或策略。
- UI：标题右侧显示刷新图标＋“再次生成”文字，使用中性 ghost 按钮、44px 点击高度；辅助文案改为“控制点已保留，可点击再次生成。”。标题行预留 44px 高度，加载与取消状态保持同一布局结构。
- Hook：新增独立计算次数与 retryRouteCalculation 用例，显式清除取消标记并重跑现有算路 Effect，不修改控制点、策略、方案修订或本地存储。
- 点击后立即进入 updating 并隐藏再次生成入口；仍可通过中央 × 取消新计算。地图未连接时禁用按钮并提示连接后重试。
- 产品基线、UI 和组件规范同步；本次只调整 Web，没有改动地图包。
- 浏览器连接仍返回请求失败，实际点击与移动端视觉验收未完成。
- 本次验证：Web lint、生产构建（含 TypeScript）和 git diff --check 均通过；已恢复构建改写的 next-env.d.ts。
