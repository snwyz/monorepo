# 已暂存路线一键清除

## 目标

在已暂存路线数量右侧增加“一键清除”，让用户可以通过一次确认删除当前浏览器中的全部路线方案，避免逐条操作。

## 范围

- 路线方案选择器的批量清除入口与确认交互。
- 本地路线仓储的批量清除能力。
- 活动方案和地图业务状态的同步重置。
- 产品、UI 和组件规范同步。

不包含云端数据、跨浏览器数据或删除后的恢复能力。

## 关键决策

- 入口位于“已暂存路线”标题区的数量右侧，仅在目录非空时显示。
- 批量删除属于不可恢复操作，复用页面内 `AlertDialog` 的阻断式确认，不使用浏览器原生确认框。
- 确认文案展示将被删除的路线数量，并使用“全部清除”区分单条删除。
- 仓储只清理 `roadbook.route-plan-catalog.v1` 目录及 `roadbook.route-plan.v1.` 前缀下的路线快照，不影响其他本地数据。
- 确认清除后统一重置活动方案上下文，避免已删除方案仍显示在地图上或被过期算路结果回写。

## 功能变化

- 已暂存路线数量大于 `0` 时，数量右侧显示危险色文字“一键清除”。
- 点击入口后显示当前路线数量和不可恢复说明。
- 点击“取消”或按 `Esc` 只关闭确认框，不修改数据。
- 点击“全部清除”后删除全部路线目录和快照，收起方案列表，并回到未选择方案状态。

## 问题与根因

此前方案目录只提供逐条删除用例；路线数量较多时，用户必须重复打开确认框并逐条操作。本地仓储也只有单个标识删除能力，无法保证目录、快照和活动方案状态在批量场景中一次完成清理。

## 降级策略

- 目录为空时不展示批量清除入口，避免无效操作。
- 确认组件按需加载，不进入首屏关键资源链路，不影响地图 LCP。
- 清除入口和确认框均为浮层内容，不改变地图容器尺寸，不引入页面 CLS。

## 验证结果

- `roadbook-web` TypeScript 检查通过。
- `roadbook-web` ESLint 检查通过。
- Next.js 生产构建通过，正常生成全部 `13` 个路由。
- `git diff --check` 通过，新文件未发现行尾空白。
- 已完成静态交互链路核对：入口仅在目录非空时出现，取消不调用清除用例，确认后清除仓储并重置活动方案状态。
- 未调用未经授权的浏览器 Skill；真实浏览器中的点击、取消、确认和移动端布局保留给后续人工验收。

## 已知边界

- 清除后不可恢复。
- 功能仅处理 Roadbook 当前版本命名空间下的本地路线数据。
- 浏览器禁止或限制 `localStorage` 时，沿用现有本地仓储错误边界，本次不新增持久化错误提示。
