# 规划环线方向箭头

## 目标与范围

解决个人规划路线只有蓝绿描线、难以看出前进方向的问题。覆盖高德与腾讯 Web 地图的正常和选中路线，包含最后一个控制点返回首点的路段。

## 问题根因与关键决策

原有三层折线未启用供应商的方向箭头。箭头应绘制在最上面的绿色内芯，避免被后绘制的内芯遮挡；直接沿算路返回的路径顺序展示，不改变控制点顺序或算路请求。

- 高德绿色内芯启用 `showDir`，显示原生白色箭头。
- 腾讯绿色内芯启用 `showArrow`，箭头宽 6px、长 8px、间隙 80px、移动速度为 0。
- 两家官方文档均建议箭头所在折线宽度大于 6px，因此普通内芯增至 7px、选中内芯增至 9px；蓝边与白色隔离层同步增加，保持原有分层宽度差。
- 不新增 DOM 覆盖物、图层、监听器或动画，复用原有路线更新和销毁流程。

参考：[高德 Polyline](https://a.amap.com/jsapi/static/doc/20211028/index.html?v=2)、[腾讯 PolylineStyle 与 ArrowOptions](https://lbs.qq.com/webApi/javascriptGL/glDoc/glDocVector)。

## 功能变化与降级策略

箭头表达「1 → 2 → … → 1」方向。正常与选中路段均显示；旧结果和失败路段继续使用灰色、红色虚线，不显示方向箭头。插入引导与热门专题线不添加箭头。供应商无法绘制箭头时仍可结合控制点编号判断顺序。

## 验证结果

- 地图包 ES2019 构建、类型检查通过；现有 11 项测试通过。
- Web ESLint 与生产构建通过。
- 浏览器加载已有三点闭合路线，检查高德、腾讯实际地图绘制与供应商切换；两家地图在最终加宽样式下均可见沿线白色箭头，往返方向与控制点顺序一致。
- `git diff --check` 通过。
- 构建生成的 `next-env.d.ts` 路径变更已恢复，不提交构建产物。
- 环境未安装 `rtk`，使用对应原生 pnpm 命令验证。

## 已知边界与后续建议

- 完全重合的往返道路仍可能相互遮挡，需结合控制点编号与路段选择判断；本次不引入道路偏移。
- 箭头排列由供应商原生渲染控制，两家密度不完全相同；极短路线未必容纳完整箭头。
- 未新增首屏请求或文档流元素，但本次未进行 LCP/CLS 专项性能测量，也未覆盖真机触摸验收。
