# 规划路线道路名称标注

## 目标与范围

在已有方向箭头基础上，让用户知道规划路线实际经过哪些道路。覆盖高德和腾讯地图的有效个人规划路线，不影响只读热门专题。

## 问题与根因

两家算路响应都提供步骤道路名称，但原适配器只保留总里程、耗时和整段折线，展示层无法将道路名称绑定到实际道路。

## 关键决策与功能变化

- 在 `DrivingRouteLeg` 和 `WebMapRouteLeg` 中增加可选 `roadSections`，保留名称和对应道路折线；已有不含该字段的结果仍可显示路线。
- 高德使用 `steps[].road/polyline`；腾讯使用 `steps[].road_name/polyline_idx`。腾讯下标按原始经纬度数组处理，包含末尾，先验证合法范围再映射到解码后的坐标。
- 仅合并连续且首尾相接的同名道路；缺名步骤打断合并。缺失及“无名道路”等占位名称不显示，不用 POI 或相邻道路推测。
- 独立道路名称图层位于路线之上、控制点之下。白底、灰边、近黑文字配短引导线，名称超过 14 个字符省略。
- 依据道路屏幕长度优先显示较长道路，选中路段优先；同屏同名只标一次，最多 16 个。短于 100px 的道路不标注，并避让控制点及其他路名。
- 标签候选位于实际道路折线的中点、四分之一或四分之三处，避让失败时省略。地图视野变化后重新选择，布局结果相同时不重建图层。
- 路名只复用已有算路响应，不增加逆地理、搜索或路由请求。外部名称转义为 SVG 文本；旧结果、失败路段与空路线清除路名。
- 图层和事件在适配器销毁时释放，供应商切换由现有地图生命周期管理。

接口依据：[高德驾车步骤字段](https://lbs.amap.com/api/webservice/guide/api/direction)、[腾讯官方路线服务说明](https://github.com/TencentLBS/tencentmap-webservice-skill/blob/main/references/api-direction.md)。

## 降级策略

缺失、非法道路范围与无效坐标只影响对应路名，不阻断路线展示和算路。旧结果缺少 `roadSections` 时不显示路名。被遮挡或过短的候选省略，避免挤占控制点与箭头。

## 验证结果

- 地图包 ES2019 构建与类型检查通过；17 项测试通过，其中 6 项覆盖腾讯下标、同名合并、缺名与异常状态、视野筛选、选择优先级及 SVG 转义。
- Web ESLint 与生产构建通过，构建产生的 `next-env.d.ts` 路径修改已恢复。
- 浏览器使用既有三点闭合路线验收：高德出现“复兴路”“珠市口东大街”，腾讯出现“莲花池东路”“宣武门西大街”“广安门内大街”“珠市口东大街”；名称沿真实路线显示且不挡方向箭头，供应商切换后使用新供应商路名。

- 腾讯地图滚轮放大后，路名仍锚定对应道路，视野外标签被重新筛选。
- `git diff --check` 通过。

## 已知边界与后续建议

- 本次使用当前平面地图的墨卡托投影做屏幕避让；未来开放地图旋转或倾斜时需改用供应商实际屏幕投影。
- 密度限制、候选点和碰撞避让会省略部分道路名称，并非完整道路清单；超长道路放大后也可能没有候选落在视野内。
- 避让控制点和路名，但不分析底图 POI，也不识别覆盖在地图上的业务面板。
- 名称与国道编号以供应商响应为准，不自行补充缺失编号；不同供应商路线与命名可能不同。
- 未完成真实手机、五点以上长途环线和 LCP/CLS 专项测量，后续可在大范围路线实测基础上调整密度阈值。
