# 控制点七天天气卡片迭代

## 1. 目标

用户点击路线控制点 Marker 后，可以在不离开地图工作区的情况下查看该地点含今天的未来 7 天天气，为近期自驾路线判断提供辅助信息。

天气能力不引入出行日期、计划天数、每日路线或自动行程安排，路线方案仍以有序控制点为核心对象。

## 2. 范围

- 仅对普通路线规划模式中的控制点 Marker 生效。
- 点击地址列表仍只负责选中和聚焦，不自动打开天气卡片。
- 天气数据由腾讯位置服务天气接口提供，与当前高德或腾讯底图选择解耦。
- 首版展示日期、天气现象、最高温、最低温、更新时间与数据来源。
- 不展示实况天气、空气质量、生活指数、降水概率和天气预警。

## 3. 关键决策

### 3.1 七天定义

“未来 7 天”定义为“含今天的连续 7 个日历日”。腾讯天气请求使用 `type=future&get_md=1`，服务端最多保留前 7 条有效日预报。

### 3.2 领域与组件边界

- `domain/weather-forecast/model.ts` 定义供应商无关的天气模型和图标语义。
- `tencent-weather-forecast-service.ts` 只在服务端解析腾讯响应并转换领域模型。
- `/api/weather/forecast` 是浏览器唯一访问入口，不向客户端暴露腾讯 Key 或原始响应。
- `useWeatherForecast` 负责编排请求、取消、重试与缓存状态。
- `WeatherForecastCard` 只负责展示，不持有地图 SDK 或修改路线方案。
- `RoutePlanningWorkspace` 只维护当前天气目标 ID，并区分 Marker 点击与地址列表点击。

### 3.3 分包、包体积与缓存

- `WeatherForecastCard` 使用 `React.lazy`，天气组件、SVG、Hook 和客户端请求代码在第一次点击 Marker 后才下载。
- 天气图标使用组件内联 SVG，不新增图标包、位图、字体或运行时动画依赖。
- Next 生成的内容哈希分包由浏览器按静态资源缓存规则复用；关闭卡片不会重新下载分包。
- 客户端按四位小数坐标缓存成功结果 `30` 分钟，最多保留 `16` 个地点，避免同一会话内反复请求。
- 服务端使用 Next 数据缓存保存成功结果 `30` 分钟；HTTP 响应允许浏览器缓存 `5` 分钟、共享缓存 `30` 分钟，并允许 `1` 小时后台重新验证。
- 腾讯错误响应使用 `no-store`，避免权限、额度或短暂故障被长期缓存。

## 4. 交互与视觉

- Marker 点击继续同步选中地图标签和地址列表，并打开天气卡片。
- 点击其他 Marker 时切换查询目标；旧请求通过 `AbortController` 取消。
- 点击地图空白、按 `Esc` 或点击关闭按钮收起卡片。
- 桌面端卡片位于地图安全区域；移动端固定在底部并避让左下地图工具与版权信息。
- 移动端天气卡片打开时只隐藏路线地址列表的 CSS 呈现，避免短视口中两个白色 Widget 形成错位叠层；列表组件保持挂载，关闭天气后恢复原折叠与滚动状态。
- 七天内容在窄视口横向滚动，不缩小到不可读尺寸。
- “今天”使用极浅蓝灰表面和较高字重，Marker 导航蓝仍是主选中信号。
- 天气图标使用分层实色和统一光学重量，文本始终同步显示天气语义。
- Loading、成功和失败状态保持稳定的卡片外框尺寸，不推动地图或 Widget，目标 CLS 为 `0`。

## 5. 降级策略

- 缺少天气权限、额度耗尽、网络异常或返回数据无效时，卡片显示“天气暂不可用”和重新加载入口。
- 天气失败不改变控制点、路线、地图供应商或本地方案数据。
- 腾讯返回少于 7 个有效日预报时，标题使用实际天数，不伪造缺失日期。
- 切换到热门路线专题、加载其他方案或删除当前控制点时关闭天气卡片。

## 6. LCP 与 CLS

- 首屏不加载天气代码、不请求天气接口，因此不增加首屏接口瀑布。
- 图标全部为内联 SVG，不产生额外图片请求和图片尺寸回流。
- 卡片绝对定位于地图工作区之外的文档流，异步状态不改变地图容器尺寸。
- 天气分包只在用户表达查看意图后加载，内容哈希变化时才失效浏览器缓存。

## 8. 已知边界

- 当前项目无法在代码层确认腾讯账号的天气权限与实际配额，部署前需在腾讯位置服务控制台核验。
- 腾讯天气数据在高德底图上展示时仍明确标注“腾讯天气”；正式商用前应复核当前账号协议对跨供应商展示的要求。
- 当前天气卡片是地图安全区域 Widget，不依赖供应商坐标转屏幕像素能力，因此不绘制指向 Marker 的箭头。
