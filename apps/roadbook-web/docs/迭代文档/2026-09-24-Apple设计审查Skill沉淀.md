# Apple 设计审查 Skill 沉淀

## 目标

将 Roadbook Web 在 Apple HIG 原则、WWDC 视觉气质、界面质感和交互状态方面的判断沉淀为可重复调用的 Codex Skill，减少连续迭代中的审美漂移，并让视觉建议具备明确证据、根因、风险和验证方式。

## 范围

- 新建个人可发现 Skill：`roadbook-apple-design-review`。
- 建立 Roadbook 界面审查清单。
- 在 Roadbook Web AI 上下文中登记调用和降级规则。

本次不修改页面业务逻辑、视觉 Token、组件实现或构建依赖。

## 关键决策

- Skill 安装在 `~/.codex/skills/roadbook-apple-design-review`，保持默认自动发现，仅在 Apple/WWDC、界面质感或 UI/UX 校正类任务中触发。
- 明确区分 Apple HIG 的交互原则与 WWDC 的视觉气质，不把渐变、模糊、圆角和阴影直接等同于 Apple 风格。
- 默认执行只读审查；只有用户明确要求修改或已经确认方案时才实施，继续遵循项目的“预检—确认—执行—验证”流程。
- 项目现行 AI 上下文、UI 规范、组件规范和最新迭代记录优先于 Skill 的通用启发式，发现冲突必须显式报告。
- 不复制完整 Apple 官方文档。需要精确引用时只使用 Apple 官方来源；无法核实时将结论标记为设计推断。
- 不新增脚本、图片、字体或第三方依赖。Skill 只包含入口说明、UI 元数据和按需读取的审查清单。

## 功能变化

- 审查覆盖信息层级、布局稳定性、排版、表面材质、颜色语义、交互状态、图标、动效、可访问性、响应式、LCP/CLS 和组件职责。
- Default、Hover、Selected、Focus、Pressed、Disabled、Loading、Empty、Error、Destructive 与移动端状态被要求分别核对，避免只针对单张截图修复。
- 输出必须区分“必须修正”“建议优化”和“审美偏好”，并提供位置、证据、根因、默认方案、风险和验证方式。
- 固化已验证的反模式，包括状态信号叠加、删除图标纯白浮块、滚动容器裁切外投影、输入框覆盖触发器以及 Hover 位移引发横向滚动。
- Roadbook Web AI 入口增加 Skill 路由；未安装 Skill 的环境回退到项目正式规范和 Apple 官方 HIG。

## 问题与根因

此前 Apple/WWDC 风格校正主要依赖单次对话中的审美判断。即使正式 UI 规范能够记录最终结果，也缺少一套在新页面、新状态和新任务开始时主动检查的统一流程，容易重复出现“用重阴影制造层级”“Hover 与 Selected 混用”或“为了统一主色破坏危险语义”等问题。

Skill 将可复用的决策框架与项目具体视觉结果分开：入口只保存工作方式和不可变边界，详细检查项按需加载，页面最终数值和组件行为仍由项目正式规范负责，从而避免形成第二套设计系统。

## 降级策略

- Skill 未安装、未被发现或当前环境不支持 Skill 时，直接读取 `apps/roadbook-web/AGENTS.md` 路由的正式规范继续工作。
- 无法访问 Apple 官方资料时，不阻断一般视觉审查，但不得把设计推断描述为官方强制规则。
- 未授权浏览器操作时完成代码和静态状态核对，并明确保留真实视口截图验收。

## 验证结果

- Skill 名称使用合法的 kebab-case，长度小于 `64` 个字符。
- `SKILL.md` 包含且仅包含允许的 `name`、`description` 前置字段，未残留脚手架 TODO。
- `agents/openai.yaml` 的界面字符串已加引号，默认提示显式引用 `$roadbook-apple-design-review`，保持默认自动发现策略。
- `references/review-checklist.md` 已从 `SKILL.md` 提供明确的按需读取路径。
- 官方 `quick_validate.py` 因本机 `python3` 缺少 PyYAML 而无法启动；未擅自安装依赖，已按校验器源码完成等价人工检查。
- 项目文档通过 `git diff --check`。

## 已知边界

- Skill 当前安装在个人 Codex 目录，不随仓库自动分发；其他设备或协作者需要单独安装。
- 自动发现依赖 Skill 描述与当前请求匹配，普通非视觉前端任务不会强制加载。
- Skill 能提升检查一致性，但不能代替真实用户测试、设备验证或产品决策。

## 后续建议

- 在新的页面类型或真实失败案例出现后，以最小修订方式更新清单，避免为每个局部问题增加全局绝对规则。
- 如果未来需要团队共享，再评估将 Skill 源文件纳入仓库并建立受控的安装或同步流程。
