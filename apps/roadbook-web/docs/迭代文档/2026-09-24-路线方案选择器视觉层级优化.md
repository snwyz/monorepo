# 路线方案选择器视觉层级优化

## 目标

优化路线方案选择器的信息识别效率与视觉层级，使地点信息优先于重复的“规划路线”和完整时间戳，同时降低批量清除与新建按钮对地图工作区的视觉干扰。

## 范围

- 路线方案目录的轻量摘要数据。
- `RoutePlanSelector` 的日期分组、标题、辅助信息、管理菜单和新建入口。
- 选择器相关的间距、圆角、图标和轻量动效。

本次不改变路线计算、控制点顺序、单条删除、批量清除用例或活动方案加载规则。

## 关键决策

- 方案目录增加可选的起点与末控制点名称，作为轻量标题数据，不在启动时读取完整路线快照。
- 新增字段保持可选，继续使用现有 `schemaVersion: 1`，旧数据直接降级为“未命名路线”，后续暂存时自然补齐。
- 日期提升为分组标题，行内只保留时间与途经点数量。
- 批量清除保持二次确认，仅将显性危险文字收进管理菜单。
- 保持实色表面和轻边框，不引入玻璃模糊或高成本滤镜；紧凑滚动列表内的选中行不使用外投影，避免阴影在滚动边界被裁切。

## 功能变化

- 路线按“今天”、“昨天”、当年日期和跨年日期分组。
- 自定义名称优先；未重命名路线优先显示“起点 → 末控制点”。
- 行内摘要改为“`HH:mm · N` 个途经点”。
- 数量改为弱化徽标，批量清除收入标题右侧的管理菜单。
- 列表行使用共享路线 SVG 图标、`68px` 最小行高、`12px` 圆角和从文本区开始的分割线。
- “新建规划”改为浅色次级按钮；展开面板与管理菜单增加遵循减少动效偏好的短时透明度/位移动效。
- 方案列表仅允许纵向滚动，隐藏横向溢出；行悬停只改变背景和操作可见性，不再水平位移。
- 顶部方案触发器不使用整块 Hover 背景变色，并移除叠加在触发器上的常驻输入框；名称默认只读，“重命名当前路线”收入管理菜单，主动触发后在展开面板内显示独立圆角编辑区。
- 方案行 Hover 与 Selected 改为两套独立反馈：Hover 仅使用低对比中性底色，并淡出行下方分割线；Selected 使用暖白表面、极浅内描边、淡绿色路线图标底和尾部勾选，不再使用粗黑左侧指示条或外投影，并隐藏选中行下方分割线。
- 桌面端悬停活动路线时，尾部勾选平滑切换为删除入口；移动端继续保留勾选，通过左滑进入删除确认。
- 删除入口的 Hover 从纯白浮块改为低透明暖红灰背景与克制暗红图标，在维持危险语义的同时融入整体暖灰色调。

## 问题与根因

原列表以完整更新时间戳和重复的“规划路线”承担主标题，用户很难在多条方案中快速识别路线内容。数量、危险操作和黑色主按钮同时占据高视觉权重，又进一步压缩了路线信息的层级。首轮优化后，列表的双向 `overflow: auto` 与桌面端行悬停水平位移组合，导致内容短暂超出容器并在列表底部生成横向滚动条。顶部触发器的 Hover 背景只作用于底层按钮，而可编辑方案名称是覆盖其上的独立白底输入框，因此产生了灰白断层；输入框聚焦时又触发全局直角外描边，使单一卡片在视觉和交互上都被切成两个竞争控件。方案行又把 Hover 与 Selected 合并为同一块暖灰背景，并叠加粗黑侧边条、绿色图标底和分割线，多个高对比信号同时争夺注意力，导致选中态显得厚重且缺乏层次。继续细化后发现，删除入口的纯白 Hover 背景在暖灰卡片上形成额外浮块，危险红也因对比过强脱离主色调；Selected 的外投影则会被列表滚动边界裁切，底部呈现近似直角的灰带，与卡片圆角冲突。因此删除反馈改为低透明暖红灰，选中层级改由暖白表面和内描边承担。

## 降级策略

- 旧目录没有起点或末控制点名称时显示“未命名路线”，不为生成标题额外读取快照。
- 时间无法解析时归入“日期未知”分组，并显示“时间未知”。
- 用户关闭减少动效后，全局规则会将新增动效缩短到近乎即时。

## 验证结果

- `rtk pnpm --filter roadbook-web lint` 通过。
- `rtk pnpm --filter roadbook-web typecheck` 通过。
- `rtk pnpm --filter roadbook-web build` 通过，Next.js 正常生成页面与 API 路由。
- `rtk git diff --check` 通过。
- 已完成静态交互链路核对：历史目录字段可选、新暂存写入起点与末控制点名称、管理菜单仅在目录非空时展示，重命名编辑区只在用户主动请求后出现，`Enter`/完成、`Esc`/取消和留空恢复自动命名的状态分支明确，批量清除仍经过原确认组件。
- 未调用未授权的浏览器操作 Skill，真实浏览器中的桌面端/移动端截图对比保留给后续人工验收。

## 已知边界

- 旧目录需在对应路线下次暂存后才会获得地点标题，这是为了保持启动阶段的轻量索引读取。
- 本次不修改用户自定义名称，长名称继续使用单行省略。

## 后续建议

- 当路线目录增加搜索或标签时，应继续使用轻量摘要，不把完整快照读取带回首屏链路。

## 2026-09-28：重命名输入崩溃修复

### 目标与范围

修复进入路线重命名后编辑文字导致页面报错的问题。范围仅涉及 `RoutePlanSelector` 的输入事件处理、组件规范和本迭代记录；仓库缺少 `AI.md`，按项目约定补充上下文导航入口。

### 问题与根因

- 本地开发页面实际复现：点击“重命名当前路线”可以打开编辑区，首次修改文字后出现 `Cannot read properties of null (reading 'value')`，继而进入与用户截图一致的 `This page couldn’t load` 错误页。
- 原实现把 `event.currentTarget.value` 放在 `setRenameDraft` 的函数式更新器中读取。更新器执行时事件分发可能已结束，`currentTarget` 已被置空，从而导致组件渲染失败。
- 此次复现定位到输入阶段；没有单独复现仅点击菜单而未输入就崩溃的分支。

### 关键决策、功能变化与降级策略

- 在输入事件处理函数内同步取得字符串，再由函数式更新器更新已有草稿；保留草稿不存在时返回原状态的保护。
- 保持完成、回车、取消、`Esc` 和留空恢复自动命名的既有行为。继续复用现有自动暂存与失败反馈，不新增存储格式、依赖或地图请求。
- 不修改布局、样式或首屏资源加载策略；不以此次验证声称 LCP 或 CLS 已达到目标。

### 验证结果

- 使用已获授权的内置 browser 技能，在 `http://localhost:3000` 先复现旧实现错误，再验证修复后的实际页面。
- 桌面：中文名称输入、“完成”保存、回车保存、取消按钮、`Esc` 放弃、全选删除后留空回车提交均通过。刷新后名称仍保存在路线目录，且没有自动加载活动路线。
- 窄屏 `390 × 844`：从“我的路线”管理菜单进入编辑、输入中文名称并保存通过，列表显示更新后的名称；结束后恢复默认视口。
- 修复后的操作没有新增控制台错误。测试使用本次新建的空路线，保留为“重命名回归测试·移动端”，没有修改既有路线。
- Web ESLint 通过。RTK 的类型检查快捷模式提示不支持 workspace 过滤，因此改用 `rtk proxy pnpm --filter roadbook-web typecheck`，确认目标应用类型检查通过。
- 使用 `ROADBOOK_NEXT_DIST_DIR=.next/rename-validation` 隔离目录完成 Web 生产构建，避免覆盖现有开发服务；已恢复构建自动改写的 `next-env.d.ts` 和 `tsconfig.json`。

### 已知边界与后续建议

- 窄屏验证不等于 iOS/Android 真机软键盘与输入法验收。
- 测试期间地图仍显示加载提示，本次结论仅覆盖路线名称编辑与保存，不包含地图加载性能验收。
- 后续受控输入框修改应保留真实输入回归，静态类型检查不能发现这类事件生命周期错误。

## 2026-10-07：新建规划入口前置

### 目标、范围与根因

用户指出新建入口位于展开目录底部，必须先打开目录才能创建。创建与读取历史路线被绑定在同一交互路径，降低了首屏可发现性。本轮调整方案选择器、共享玻璃样式和 H5 目录布局，并同步产品、UI 与组件规范。

### 关键决策与功能变化

- 桌面入口外壳保持 `330×56px`，选择按钮与“＋ 新建规划”按钮并列；创建按钮固定 `104×44px`，长路线名称省略，展开箭头紧邻名称。
- 未加载方案的展示文案改为“选择路线”，活动方案状态与启动不自动加载规则保持原逻辑。
- 新建按钮直接调用已有创建回调，继续关闭目录、管理菜单与重命名草稿；不依赖选择按钮的冒泡事件，不额外触发目录展开。
- 删除目录底部的重复入口；H5 使用同一组件树，将创建按钮与“已存路线”标题并列，列表与重命名区域占满下一行。
- 玻璃材质由入口按钮移至入口标题栏，标题栏与目录为同级采样表面，内部按钮不增加模糊。创建按钮沿用浅色控件 Token、冷灰焦点提示和既有透明度降级。
- 选择按钮通过稳定 ID、`aria-controls` 和 `aria-expanded` 关联目录，保留键盘原生按钮行为。

### 降级策略与性能范围

- 沿用现有玻璃材质的实色、增强对比度和减少动态效果回退。
- 不增加依赖、图像、网络字体或地图请求；入口高度与按钮尺寸固定，不因标题、数量或展开状态改变尺寸。
- 本轮静态布局检查不等于 LCP、CLS 或真机帧率验收，仍需实际页面测量。

### 验证结果

- Web ESLint、TypeScript 检查和差异空白检查通过。
- 独立复核最终差异：选择与创建是同级按钮，目录只有一个新建入口，手机目录通过 CSS 展平标题栏并保持创建按钮可见，原加载、重命名与删除回调未改变。
- 未运行完整生产构建：此次范围为展示组件和 CSS，不涉及依赖、领域计算或构建参数。
- 已请求本轮内置浏览器控制工具授权；尚未获得授权，实际页面交互与截图验收待完成，未将静态检查写作浏览器通过。

### 已知边界与后续建议

- 后续实际页面验收须覆盖桌面收起态直接创建、展开态创建后收起、长活动路线名称、空目录和 H5 目录标题布局；同时复核管理菜单与重命名区域仍可正常操作。
- LCP、CLS 无回退及 iOS/Android 真机触摸仍待实测，不以固定 CSS 尺寸代替测量结果。
