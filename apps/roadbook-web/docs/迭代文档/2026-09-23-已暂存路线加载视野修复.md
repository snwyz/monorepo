# 已暂存路线加载视野修复

## 目标

统一已暂存路线加载、新增远距离控制点和路线计算完成后的地图视野适配。地图只在目标几何超出安全可视区时缩小层级，并确保完整道路折线可见。

## 范围

- 已暂存路线的主动加载流程。
- 第 2 个及后续控制点的新增流程。
- 路线计算完成后的完整折线视野复核。
- 高德与腾讯地图共用的地图画布领域接口。
- 地图异步初始化和地图供应商切换时的视野恢复。

不改变控制点顺序、路线计算和定位行为。

## 关键决策

- 由应用 Hook 在方案加载成功后创建一次性的“路线视野适配请求”，避免地图组件根据普通控制点变化自动调整视野。
- 地图组件消费请求后调用既有 `fitCoordinates`，以全部控制点适配视野。
- 地图画布通过 Web Mercator 投影、当前中心、zoom、容器尺寸和响应式四向边距判断坐标是否位于安全可视区，不使用固定公里数代替全部视口判断。
- 新增控制点时先执行单点聚焦，再检查完整控制点集合；仍在安全区内时保持当前 zoom，超出时调用供应商原生边界适配。
- 移动端新增点与任一既有点超过 `2km` 时额外触发适配，作为窄屏和极端布局的兜底规则；桌面端不复用固定距离阈值。
- 路线计算完成后使用全部路段折线再次检查，道路绕行超出控制点包围范围时执行第二次适配。
- 高德使用 `setBounds` 的非立即模式和平滑过渡，并按上、下、左、右传入避让；腾讯沿用 `fitBounds`，统一边距限制在 `96px`，避免窄屏过度缩小。
- 使用递增序号保证每次主动加载均可触发，同时避免同一次请求因组件更新被重复执行。
- 地图尚未创建时保留待处理请求，在画布初始化完成后执行；切换地图供应商并重建画布时重新应用当前路线视野。

## 功能变化

- 点击已暂存路线后，地图立即移动并缩放到该方案全部控制点所在范围。
- 新增远距离控制点后，地图平滑缩小到全部控制点可见；近距离新增点不无条件重置 zoom。
- 路线生成后若实际道路折线超出当前视野，自动二次适配到完整路线。
- 单控制点方案继续使用地图适配器既有的单点视野层级。
- 点击地址列表中的单个控制点仍只移动地图中心，不修改用户当前缩放级别。
- 用户主动定位、搜索选点和双击选点行为保持不变。

## 问题与根因

原方案加载流程只更新了活动方案、控制点和路线计算状态。后续虽然为已暂存路线增加了一次性 `fitCoordinates` 请求，但新增控制点仍只聚焦新点，路线折线也没有参与边界判断；两个点距离较远或道路明显绕行时，起点和部分路线会落在视野外。

## 降级策略

- 方案没有控制点时不执行视野适配。
- 地图尚未完成初始化时延迟消费请求，不阻断方案加载和路线计算。
- 地图适配沿用供应商适配器现有实现，不新增地图 SDK 能力或首屏依赖。
- 无法获得有效容器尺寸时按“不可确认可见”处理并执行边界适配，优先保证路线完整可见。
- 用户主动选择单个控制点时仍只聚焦该点，不改变 zoom；只有新增点和新路线结果进入自动适配判断。

## 验证结果

- `roadbook-web` TypeScript 类型检查通过。
- `roadbook-web` ESLint 检查通过。
- `roadbook-web` Next.js 生产构建通过，13 个路由均正常生成。
- Git 差异格式检查通过。
- 静态检查确认只有主动加载方案会创建视野适配请求；普通控制点变化不会自动重置用户视野。
- 静态检查确认地图初始化完成后会消费尚未执行的请求，地图供应商切换重建画布后会重新适配当前路线。
- 新增点安全区判断、移动端 `2km` 兜底和完整路线折线复核接入后，`@roadbook/map` TypeScript 与生产编译、`roadbook-web` ESLint、TypeScript、Next.js 生产构建及 `git diff --check` 通过；生产构建正常生成全部 13 个路由。
- 首次生产构建发现 `packages/map/src/web.ts` 为显式类型出口且遗漏 `WebMapFitOptions`；补齐公共出口后重新执行地图包编译与 Web 生产构建通过。
- 未使用未授权的浏览器操作技能，真实地图下的高德平滑过渡、腾讯边距表现、移动端 `2km` 兜底和道路绕行二次适配保留给用户手工验收。

## 已知边界

- 视野范围由控制点和已生成路线决定，不额外包含定位点。
- 供应商 SDK 对边界留白的具体视觉效果可能略有差异。

## 后续建议

- 后续如补充前端自动化测试，可覆盖“地图初始化前加载方案”和“切换供应商后保持路线视野”两个时序场景。
