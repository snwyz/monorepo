# Web 数据库分库建表规范落地

日期：2026-10-09。范围：仅中文架构文档；没有修改 Web 行为、Prisma 配置、数据库或部署。状态：规范已归档，实施待独立任务与授权。

## 1. 目标与范围

将 Web 用户、手机号登录、路线 UGC、文件/链接/文本导入、复制/fork/裁剪、会员与 AI 数据基础的分库建表规则落实为可验收规范。正式文档按用户指定保存在 [服务端文档目录](../../../backend/docs/README.md)。

## 2. 问题与依据

此前模型已描述实体、关联与事务，但缺少统一的 database/schema 归属、分区与拆库准入、命名及迁移门禁。当前 `packages/db` 只有单 datasource 和迁移历史，尚未配置 DDD schemas；旧模型与 Web 私人路线语义不同，不能直接覆盖迁移。

## 3. 关键决策

- 每环境一个 Web 业务数据库，生产/预览/开发隔离；库内按 DDD 上下文分 schema，保留领域表前缀。
- 明确 46 张拟议逻辑表的 schema 归属，按阶段启用；初期不物理拆库、不分片，不一次创建全部未来表。
- 路线、修订、归属/权限、权益决策、幂等与 outbox 等必要原子操作留在同库；未来拆库先重新设计事件、补偿、授权与删除传播协议。
- 新表必须完成设计卡，约束、索引、运行权限与兼容迁移可审查；会员点数限制不写死在表结构。
- 旧模型保持真实映射；禁止通过修改 schema 归属意外删表重建。迁移执行、部署、安装扩展与删除数据另行授权。

规范正文见 [数据库分库分表与建表规范](../../../backend/docs/数据库分库分表与建表规范.md)，已同步总方案、模型设计、一致性设计与目录入口。

按用户要求，已将规范接入根目录 [AGENTS.md](../../../../AGENTS.md)：数据库相关工作必须先读取正式规范，并遵守 schema 归属、表设计卡、事务边界、会员额度及迁移授权规则。入口保留关键约束，详细规则以正式文档为准。

## 4. 功能变化与故障策略

本次无产品功能变化。规范要求权威写入失败时不确认云端成功，Redis 与向量投影不作业务事实来源；分区不削弱幂等和唯一性，拆库不暗中取消原子保证。具体故障处理沿用 [一致性设计](../../../backend/docs/一致性与故障处理设计.md)。

## 5. 验证结果

- 已只读核对仓库数据库配置与现有文档，并查证 PostgreSQL schema、分区/外键约束及 Prisma 多 schema 能力。
- 已检查完整表归属覆盖、本地链接、Markdown 表格/代码围栏与空白格式；仅文档改动，不运行应用构建。
- 没有读取忽略的环境配置、真实数据库或用户数据，没有生成/执行迁移、安装工具、提交或 push。
