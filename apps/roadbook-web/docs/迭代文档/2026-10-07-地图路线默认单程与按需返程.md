# 地图路线默认单程与按需返程

## 目标与范围

地图规划默认计算并展示单程，用户点击里程区域后才补算返回起点的道路、里程和用时。地图图形、路线摘要、地址列表和沿途设施使用同一实际路线范围。覆盖高德与腾讯 Web 适配器、路线规划 Hook、摘要及地址列表，不改变小程序能力。

## 问题与根因

原实现始终请求闭合路线，摘要面板独立维护单程／往返开关，并通过移除最后一段汇总单程指标。切换只影响数字，地图始终展示返程，且默认会产生用户尚未要求的返程请求。

## 关键决策与功能变化

- `DrivingRoute` 通过 `scope` 表达单程或往返。新增 `calculateDrivingRoute`，保留原 `calculateClosedDrivingRoute` 兼容入口；地图包继续遵循 ES2019。
- 新建和主动加载方案默认单程；N 个控制点请求 N−1 个有向路段，不自动返回起点。
- 开启往返只请求末点到起点的一段，不重新请求已有单程。返程道路来自供应商实际计算，不将单程里程或用时乘二。
- 返程成功后由领域函数校验首尾控制点并组合结果。工作台统一下发往返指标、图形和“返回起点”连接行；切回单程时同时移除返程图形、道路名称与列表入口，并清理路段选择和搜索插入上下文。
- 返程缓存绑定当前单程结果对象；相同版本来回切换不发起新请求。控制点、策略或供应商变化后重新计算，切换方案恢复单程。
- 沿途设施查询与缓存作用域包含当前实际路线范围，避免单程和往返的站点图层混用。
- 海拔面板仍为未接入高程数据的占位能力，本次没有新增海拔请求或曲线。
- 摘要沿用原有布局与切换入口，计算提示复用固定单行页脚，不新增首屏依赖或改变地图容器尺寸。

## 降级与异步隔离

- 补算返程期间保留单程数字与图形，页脚提示正在计算，再次点击取消。
- 返程失败自动恢复单程，页脚提示保留单程及点击里程重试，错误详情通过提示信息保留。
- 取消、方案切换、输入与供应商变化会中止旧请求。请求版本、单程计算键和清理标识共同阻止过期返程覆盖新方案，避免返程请求抢占新单程计算。
- 单程本身失败沿用既有错误与旧结果处理，不删除控制点或本地方案。

## 已知边界与后续建议

- 返程开关与算路缓存为当前页面的临时状态，不改写方案存储格式；刷新后仍需主动加载方案，默认恢复单程。
- 腾讯适配器本次使用可控网络测试，实际地图浏览器验收使用高德。腾讯原有高速优先不支持提示继续有效。
- 手机验证使用浏览器视口模拟，未进行 iOS／Android 真机触摸与软键盘验收。
- 已验证摘要区域尺寸稳定，未重新采集完整页面 LCP、CLS 数据；不将局部尺寸证据视为全页面 CLS=0 或 LCP 目标达成。
