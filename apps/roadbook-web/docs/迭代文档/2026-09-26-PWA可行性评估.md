# Roadbook Web PWA 可行性评估

日期：2026-09-26。状态：静态评估与方案建议，尚未实施或真机验收。

## 目标与结论

评估当前 Web 应用增加安装入口、独立窗口和离线降级的可行性。建议先提供可安装的在线应用，再按实际需求增加离线只读能力；完整离线地图与算路不纳入本次建议范围。

现有 Next.js App Router、单页面工作台、本机仓储及 H5 任务面板可以复用，不需要重写为原生应用。PWA 的直接收益是更方便地再次进入、独立窗口体验与受控的离线提示；不能据此承诺 SDK 运算性能提高或完整离线导航。

**实施硬性前提：不得导致现有 Web 应用的 LCP、CLS 回退。** 此要求适用于全部 PWA 阶段，是交付门槛，不是可选优化项；必须以改动前后的同口径实测证明，未验证或存在回退不得判定验收通过。

| --- | --- |

| `app/layout.tsx`、`app/icon.svg`、`public/` | 已有 viewport-fit=cover 与 SVG 图标；未发现 manifest、Service Worker 注册、安装用 PNG 图标组或离线页面 |
| `components/route-presentation/workspace-task-sheet.*` | 已适配安全区、动态视口与软键盘，仍须验证 standalone 状态栏和真实设备 |

| `hooks/use-route-planning-workspace.ts` | 主动加载方案会清空当前路线结果，随后通过适配器重新算路；无专门在线/离线状态编排；暂存存在 360ms 防抖 |
| `../../packages/map/src/amap-web.ts`、`../../packages/map/src/tencent-map-web.ts` | 地图 SDK 从供应商远端加载。默认高德、可切换腾讯，两套均需验收 |
| `next.config.ts`、专题仓储 | 固定 URL 几何文件使用 HTTP 重验证与 ETag，不能被 SW 永久缓存覆盖 |
| 天气 API、地图代理 | 天气已有 HTTP/服务端缓存；地图请求与高德安全代理有 no-store 约束，应避免通用 SW 缓存规则介入 |

仓库根级上下文称 Web 使用腾讯地图，但 Web 正式入口与实际代码已是默认高德、可切换腾讯。本评估以实际双供应商实现为依据。

## 分阶段范围与成本

以下为一名熟悉项目的开发者的粗略人日估算，包含对应验证；假设生产 HTTPS 和测试设备可用，不含供应商授权沟通与商店上架。

| 阶段 | 交付范围 | 估算 |
| --- | --- | --- |
| A：安装与独立窗口 | manifest、192/512 PNG 与 maskable 图标、Apple touch icon、主题色、按能力显示安装入口、iOS 手动添加指引、安全区与外部导航验收 | 1–2 人日 |
| B：基础离线降级 | 小型 SW、预缓存独立离线页、导航失败兜底、版本更新提示、恢复联网与回滚验证 | 追加 1–2 人日 |
| C：离线只读方案 | 脱离地图 SDK 的本机方案列表与控制点阅读界面，完整缓存所需资源、离线状态及恢复流程 | 追加 3–5 人日 |
| D：离线结果与地图 | 路线结果持久化、数据版本/过期策略、地图数据授权与离线渲染；离线算路还需要道路图与算法 | 独立立项，当前证据不足以可靠估时 |

A 不以完整离线为安装前提。A+B 是建议首版，约 2–4 人日；C 视用户是否真正需要在无网途中查阅而决定。上述阶段均保留“启动未选择方案，用户主动加载”的现有规则。

## 技术方案与缓存边界

- A 使用 Next 原生 `app/manifest.ts`，设置稳定 id、start_url、scope、standalone 显示模式与品牌图标；在根布局补充主题色和 Apple 图标配置。不为安装单独引入构建插件。
- 安装入口按浏览器能力增强，已安装时隐藏；iOS 使用添加到主屏幕操作指引，不依赖 beforeinstallprompt。内嵌浏览器及不同 Android 环境的安装结果需要实测。
- B 的 SW 仅在生产注册，部署响应头确保脚本可更新；只对同源导航请求提供离线兜底，不将 HTML 返回给 API、脚本或 RSC 请求。离线页明确地图与算路需要联网。
- 第一版保留现有 Next 哈希资源 HTTP 缓存，不必缓存整站。若后续缓存应用壳与懒加载包，必须使用构建版本资源清单并验证旧页面与新 chunk 共存，不能简单对全部请求套 CacheFirst。
- `/api/amap/*`、`/api/tencent-map/*`、`/_AMapService/*` 默认不增加 SW 缓存；天气沿用现有缓存，不再叠加无限期兜底；错误响应不缓存。
- 专题几何维持在线重验证。若要在离线时使用副本，应作为明确的新产品行为，核验数据使用权限并同步规范，标明时间和离线状态。
- 首版不主动缓存第三方 SDK、瓦片或批量地图区域。当前尚未核验供应商离线存储与展示许可，不将许可未知写成技术上可交付。
- SW 更新不强制刷新正在编辑的页面。提示更新后，先确认暂存成功，再激活并刷新；暂存失败时保留页面。回滚清理仅限本应用缓存，不删除用户路线存储。

## LCP、CLS 无回退约束与验收门槛

### 实现约束

- PWA 注册、安装引导及缓存逻辑不得阻塞首页渲染、hydration 或地图初始化，不增加首屏同步任务和非必要资源预加载。
- SW 注册、安装与预缓存安排在首屏关键加载完成后的空闲阶段；控制预缓存范围与并发，避免与地图 SDK、底图及关键脚本竞争带宽和主线程。延后注册只是实现措施，不能替代性能实测。
- 安装入口、离线提示和更新提示使用预留空间或不改变文档流的展示方式，不因能力检测、SW 状态或异步加载挤动现有布局；图标、占位和 standalone 安全区尺寸保持稳定。
- 在线请求不得等待无必要的缓存初始化或额外串行请求；SW 已接管页面时仍须验证导航与资源加载开销。
- 不得通过延迟地图、隐藏业务内容、替换 LCP 候选元素或过滤地图布局偏移来制造达标数据；地图首次可用时间单独记录，不以 LCP 改善掩盖地图变慢。

### 对照方法与通过条件

1. 实施前保存当前生产构建作为基线，候选构建仅包含待验证改动。固定设备、浏览器版本、视口、网络、CPU 限速、测试数据和操作流程，记录构建版本、HTTP 缓存与 SW 状态。
2. 桌面与移动分别验证首次访问（无 SW、冷缓存）、已安装 SW 后的冷资源缓存启动、再次打开（缓存命中）、弱网和更新流程；普通浏览器与 standalone 分别记录。新增 standalone 模式记录独立结果，不用其缓存收益抵消普通网页的回退。
3. 每组至少交替执行 3 次基线与候选测量，保留逐次结果并比较中位数；若波动较大或出现退化样本，追加验证查明原因，不以单次最佳值或不同场景平均值宣称通过。
4. LCP 在各可比场景下不得相对基线变慢；同时保留项目桌面良好网络下不高于 2.5 秒的目标。测试噪声导致无法判断时标记“未验证”，不得自行放宽百分比或毫秒阈值。
5. CLS 同时覆盖首屏与一致的完整业务流程，包括搜索/键盘、面板切换、路线加载以及安装、离线、更新提示。项目目标为 CLS=0；已有非零基线必须如实记录，PWA 不得增加布局偏移，也不得将“未增加”写成全应用已达到 CLS=0。
6. iOS/Android 真机复核安全区、软键盘与主屏幕启动；自动化或桌面模拟结果不能代替真机结论。未完成的场景列为验收缺口。

发现回退时，先调整或撤回对应注册、预缓存、请求拦截或提示逻辑，复测通过后才交付；必要时缩减为已验证无回退的安装元数据阶段，不以 PWA 功能完整性换取 LCP、CLS 退化。估算工期不构成降低验收标准的理由。

## 已知风险与降级

1. 安装后仍需要在线地图与服务端代理。没有完整资源缓存时，即使 localStorage 有方案，冷启动也可能无法打开工作台。
2. PWA 本机数据不是云备份。不同浏览器或安装容器的存储共享/迁移行为必须真机核验，不能承诺安装后自动继承全部方案；卸载、清理站点数据、空间压力等也需考虑。后续可单独评估导入导出与持久存储请求。
3. 外部地图 Scheme、定位权限、返回应用后的状态与软键盘是主要兼容验收点。离线定位即使得到 GPS 坐标，也不代表当前在线坐标转换与地图链路可用。
4. SW 安装和预缓存不能抢占首屏地图带宽。现有 SDK 主线程成本不会因安装 PWA 自动消失；分别测量冷启动、再次打开、LCP、CLS 和地图首次可用时间。
5. 不支持安装的浏览器继续使用普通网页；SW 不可用时保持在线应用；离线且未预缓存时不得承诺离线页可用。恢复联网需要允许重试失败的 SDK 加载，而非只更新一个网络图标。
