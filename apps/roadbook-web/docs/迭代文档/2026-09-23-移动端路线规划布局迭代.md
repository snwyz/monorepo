# 移动端路线规划布局迭代

## 1. 迭代信息

- 日期：2026-09-23
- 状态：控制点导航语义已更新，移动端手工验收由用户执行
- 应用：`apps/roadbook-web`
- 目标：重新排列移动端地图工作台的任务优先级，突出路线顺序与控制点导航，减少默认展开面板对地图的遮挡和控制点行的常驻图标数量。

## 2. 范围

- 搜索固定到底部安全区，搜索结果向上展开。
- 移动端隐藏地形分析。
- 地图供应商切换与缩放、定位控件在左下纵向排列，供应商选项向右展开。
- 路线顺序面板固定在顶部路线选择器下方，每个控制点行提供导航图标。
- 外部导航按当前地图供应商生成高德或腾讯官方 App Scheme。
- 移动端方案欢迎面板默认隐藏，通过顶部“我的路线”展开方案列表和新建入口。
- 路线顺序面板支持折叠到标题栏，方便直接操作地图。
- 移动端 H5 控制点行仅常驻导航图标，删除改为左滑触发；PC 保持拖拽图标和删除图标不变。
- 移动端 H5 已暂存路线行隐藏垃圾桶，复用左滑阈值与回弹逻辑；PC 方案删除入口不变。
- 移动端点击路线段后显示当前路段摘要，未选择路段时不常驻占用地图空间。

## 3. 关键决策

### 3.1 路线顺序优先

路线顺序是移动端的主要业务面板。面板位于顶部路线选择器下方，采用稳定最大高度和内部滚动，展开时向下生长，避免控制点增加时推动地图或搜索栏。导航入口与控制点同处一行，以设备当前位置为起点、该控制点为终点；路段连接行只负责选择和查看路段。

### 3.2 统一外部导航 Scheme

`createMapNavigationUri` 统一负责供应商参数和坐标顺序：

- 高德使用官方 `amapuri://route/plan/`，省略起点参数时由客户端使用设备当前位置。
- 腾讯使用官方 `qqmap://map/routeplan`，传入 `fromcoord=CurrentLocation`，并按腾讯要求使用“纬度,经度”的坐标顺序。

控制点导航入口复用同一个生成器，避免供应商切换后仍打开高德；导航只传终点，由地图 App 使用设备当前位置作为起点。路线摘要不再提供重复的外部导航入口。

### 3.3 折叠不改变地图尺寸

地图供应商、缩放和定位控件通过绝对定位在左下纵向排列，供应商选项只向右展开；方案入口、搜索结果和路线列表均覆盖在地图上，不参与地图容器文档流。移动端不渲染可见地形面板，为路线顺序和搜索预留稳定空间，目标 CLS 为 0。

### 3.4 路线顺序默认收起

路线顺序虽然是移动端最重要的业务面板，但常驻展开会遮挡大面积地图，影响平移、缩放和选点。最终交互确定为默认收起：首次显示时只保留 `58px` 标题栏、控制点数量和展开箭头；用户需要查看或编辑路线时再主动展开。折叠只改变呈现状态，不卸载排序上下文，不清空滚动位置、当前控制点或当前路段选择。

### 3.5 移动端单图标与滑动删除

移动端 H5 控制点行隐藏拖拽提示图标和删除图标，只保留外部导航图标；已暂存路线行同时隐藏垃圾桶。两处统一复用 `useMobileSwipeRemoval`：向左滑动时以 `transform` 提供跟手反馈，横向位移达到 `72px` 后显示“松开删除”，松开后进入各自既有二次确认流程，不直接删除数据。方向判断要求横向位移大于纵向位移，导航与独立删除入口排除在手势识别外；方案行还会抑制滑动结束后的合成点击，避免误加载路线。PC 不启用滑动逻辑，原有行内图标和交互保持不变。

### 3.6 移动端路段摘要按需显示

移动端不展示完整环线的常驻摘要。用户点击地图路线段或路线顺序中的连接线后，在底部搜索框上方显示当前路段摘要，仅包含预计里程和预计驾驶时间；摘要左侧为地图工具组预留空间。选择任一控制点时清除当前路段选择并收起摘要，避免摘要与点位操作语义并存。

### 3.7 活动方案名称使用列表摘要作为单一来源

方案列表已使用时间标题，但顶部触发器仍直接显示活动快照中的默认名称“未命名路线”，导致用户选中方案后两处语义不一致。现在由领域展示名称函数统一处理默认时间标题和自定义名称；顶部优先读取 `catalog` 中的当前方案摘要，与列表项使用同一数据源，不再从 `activePlan.updatedAt` 另行生成时间。

### 3.8 搜索入口承载连续添加与当前位置起点

移除地图中央仅在前两个控制点阶段出现的“继续添加控制点”卡片及步骤数字，避免把引导误认为已经创建的地图点位。路线添加引导统一进入搜索框占位文案：新方案说明从当前位置出发，定位期间反馈起点获取状态，已有控制点后始终提示继续添加，不因第三个控制点出现而消失。

新方案创建时请求浏览器精确当前位置并作为第一个控制点；搜索选点和地图双击会等待该起点请求完成后再追加，避免异步结果颠倒顺序。IP 城市级位置仍只服务于地图初始化和搜索范围，定位权限拒绝、超时或精度不足时不自动写入起点，改由用户通过搜索或地图选点手动确认。

### 3.9 搜索框轻量层次

搜索框保持原有尺寸、白底和胶囊结构，外层改用 `1px` 灰阶渐变描边，并使用比通用 Widget 更紧凑的双层阴影建立轻微抬升感。按钮状态和交互规则保持不变，描边继续占用原有 `1px` 边框空间，不引入布局位移。

## 4. 功能变化

- 搜索栏使用底部安全区，加载、空结果、失败和候选列表均在输入框上方显示。
- 地图中央不再展示带步骤数字的添加引导卡片；搜索框以稳定的上下文占位文案承载起点定位和后续控制点添加提示。
- 新方案默认以浏览器精确当前位置创建第一个控制点；定位失败时不使用 IP 城市级近似坐标，保留手动选择起点的降级入口。
- 搜索框外层与输入区统一为白底；移动端隐藏 `⌘ K` 提示，并使用左右安全区约束释放输入宽度。
- 搜索框外层增加 `1px` 灰阶渐变描边和紧凑双层阴影，在地图上形成轻微抬升感，不改变搜索按钮状态。
- 搜索候选的虚线水滴图形替换为 `22px` 经典实心定位针，统一使用项目近黑色和透明中心孔，保持固定占位避免列表文字横向跳动。
- 地图供应商默认只显示图层图标，展开后显示“高德/腾讯”和当前状态勾选。
- 每个控制点行始终显示导航图标；每个路段继续显示路段名称，包括返回起点路段，但不再承载导航图标。
- 移动端 H5 控制点行隐藏拖拽和删除图标，左滑 `72px` 后松开可发起删除确认；短距离滑动、纵向滚动和取消手势自动回弹。
- 移动端 H5 已暂存路线行隐藏垃圾桶，左滑 `72px` 后松开进入原有方案删除确认；未达到阈值时回弹且不加载方案。
- PC 与移动端 H5 的已暂存路线行之间均增加 `1px` 边框色分割线；分割线由行容器固定绘制，移动端左滑时保持静止且不改变列表高度。
- H5 顶部方案触发器与展开菜单共用顶栏可用宽度，不再出现触发器保留 PC `330px` 上限、菜单却铺满屏幕的宽度分叉。
- PC 与移动端 H5 的未重命名方案标题使用“`YYYY-M-D HH:mm` 规划路线”，已重命名方案显示自定义名称，小字改为“`N` 个位置信息”，不再重复展示更新时间。顶部活动方案复用对应列表项的同一展示名称。
- PC 垃圾桶与移动端 H5 左滑删除统一打开页面内 `RoutePlanDeleteConfirmation`，复用定位删除弹窗的遮罩、容器、按钮和危险色规则，不再调用浏览器原生 `window.confirm`。
- 方案列表、搜索结果、路线顺序等全局滚动区域统一使用透明轨道和细灰阶滑块；Chromium 与 Safari 精确使用 `2px`，Firefox 降级为 `thin` 最细档。
- 顶部方案选择器默认收起；未加载方案时不再自动展示大面积欢迎面板。
- 欢迎面板仅在没有任何暂存路线时提供首次使用说明和新建入口；已有路线时不再重复渲染路线列表和第二个“新建规划”，统一通过顶部方案选择器加载或新建。
- PC 顶部方案触发器与展开菜单统一为同一 `330px` 列宽；顶栏采用左右对称列，搜索框以最大 `460px` 宽度在中间列居中。移动端方案栏继续随安全区横向铺满，搜索仍固定在底部。
- 路线顺序默认折叠为 `58px` 标题栏，点击标题栏箭头后展开；列表保持挂载，再次收起与展开时保留滚动和选择状态。
- 移动端选中路线段后显示 `RouteMetricsPanel`；未选中路段时隐藏，选择控制点后同步收起。
- 桌面端保留现有顶栏搜索、双标签供应商 Switch、路线摘要和地形分析布局。
- 桌面端控制点行继续显示拖拽提示、导航和删除图标，不启用滑动删除。
- 桌面端已暂存路线行继续显示垃圾桶，点击删除与确认流程保持不变。

## 5. 降级与边界

- 高德与腾讯 App Scheme 的调起受系统、App 安装状态和内置浏览器策略影响；产品按明确要求不提供网页降级。
- 设备未安装对应地图 App 时，浏览器通常保留在当前页面，具体反馈由操作系统和浏览器决定。
- 外部地图会重新计算路段，本页面不承诺外部路线与当前折线完全一致，也不承担实时导航。
- 本次只在移动端隐藏地形分析，没有删除海拔领域状态或桌面端能力。
- 搜索框的移动端宽度由左右安全区共同约束，不设置固定像素宽度；异步状态和候选结果不改变搜索框占位，避免 CLS。
- 自动起点依赖浏览器定位权限和定位精度；失败时不会阻断新方案或搜索，只取消自动起点并提示用户手动确认。
- iOS Safari 会在聚焦小于 `16px` 的表单控件时自动放大页面；移动端搜索输入固定使用 `16px` 字号，不通过 `maximum-scale` 或 `user-scalable=no` 禁止用户缩放。
- 页面 viewport 启用 `viewport-fit=cover`，使搜索框已有的底部与横向 `safe-area-inset` 规则在刘海屏和 Home Indicator 设备上获得真实安全区值。
- 滑动删除仅负责发起删除请求，控制点继续复用统一 Alert Dialog，路线方案继续复用既有浏览器确认框；未确认前不改变控制点、编号、路线或方案目录。
