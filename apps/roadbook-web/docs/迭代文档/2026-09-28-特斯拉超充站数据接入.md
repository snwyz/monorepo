# 特斯拉超充站数据接入

## 目标与范围

按用户提供的两个特斯拉中国公共接口，接入超充站目录和单站详情，为规划路段查询充电站提供数据基础。第一阶段完成数据层；同日第二阶段按用户提供的红色闪电图钉参考与 WWDC 视觉方向，将站点接入路段、地图和详情面板。自动充电规划不在本轮范围内。

来源：

- [站点目录](https://apigateway-socialconnect-api.tesla.cn/ext/v2/findus/get)
- [站点详情示例](https://apigateway-socialconnect-api.tesla.cn/ext/v1/site/details?trtid=102302&ctype=s)

接口当前可公开访问；未取得接口稳定性、数据更新时间、完整性、调用额度或开源许可说明，不将其描述为有长期兼容承诺的开放平台 API。

## 数据核实与关键决策

2026-09-28 首先流式读取目录第一条记录，只读取 8192 字节便取得宁波万豪酒店的完整样本。后续在内存中汇总目录，响应约 2.8 MB、4502 条地点记录，其中有 2807 条 `supercharger` 详情；这些计数仅为当次观察，不作为固定验收值。

- 目录混有门店、维修、交付、目的地充电站，必须遍历每个地点的 `data` 数组，只取 `location_type === "supercharger"`，按 `location_id` 去重。
- `location_id` 用作应用站点 ID；`trt_id` 单独保存为 `sourceSiteId`，用于详情参数 `trtid`，不能混用两个标识。
- 宁波万豪酒店：`location_id=cnsc9915`、`trt_id=31448`，证明两者不必相等。
- 成都双流万达广场：`location_id=102302`、`trt_id=102302`；详情响应 `trtid=102302`，本次返回总桩数 3、可用桩数 3、最高功率 250 kW。
- 坐标直接采用目录的腾讯坐标字段 `qq_lat/qq_lng`，与现有国内地图道路坐标配合使用，不额外重复转换；尚未逐站核验地图偏差。
- 未知桩数、功率、非 Tesla 开放状态为 `null`，不得默认为 0、开放或不开放。`business_hours=null` 不解释为全天营业。
- 未输出供应商整份目录到浏览器，未把原始目录作为静态资源提交。

## 应用接口

### 路段附近超充站

`POST /api/route-charging/tesla`

请求示例：

```json
{
  "path": [
    { "latitude": 30.59, "longitude": 103.92 },
    { "latitude": 30.60, "longitude": 103.94 }
  ]
}
```

- 输入实际道路折线，支持 2–20000 个坐标，请求体上限 2 MiB。
- 以 2000 米为固定候选范围，逐线段求近似最近投影，不只搜索折线顶点，不以起终点直线替代道路轨迹。
- 返回 `source`、`fetchedAt`、`stale`、`radiusMeters`、`stations`，站点按路线投影里程排序。
- `distanceFromRouteMeters` 是站点到道路折线的近似直线距离；`distanceAlongRouteMeters` 是本段起点至最近投影的折线估算里程。
- 两种距离都不是驶入站点的导航里程；没有核实对向服务区、封闭道路、停车场入口、下高速和绕路成本，不标记“顺路可达”。
- 路线请求只发送到本站服务端，不传给特斯拉。响应为 `Cache-Control: no-store`，不记录请求轨迹。

### 单站详情

`GET /api/route-charging/tesla/{stationId}`

例如：`GET /api/route-charging/tesla/102302`。

服务端先从目录解析 `stationId` 对应的 `sourceSiteId`，再请求固定域名的详情接口，固定 `ctype=s`。详情返回的 `trtid` 必须与请求相符。

返回 `stationId`、`source`、`fetchedAt` 与 `details`。详情归一化如下：

| 领域字段 | 来源字段 | 口径 |
| --- | --- | --- |
| `totalStalls` | `allChargerCount` | 接口返回的总桩数 |
| `availableStalls` | `availableChargerCount` | 查询时接口报告的可用数，不保证到站仍可用 |
| `maximumPowerKw` | `maxPowerKW` | 接口提供的最高功率 |
| `amenities` | `amenities` | 设施枚举原值，样本含 Wi-Fi 和地锁 |
| `usabilityStatus` | `siteUsabilityArchetype` | 站点状态原值 |
| `availabilityIndicator` | `isAvailableCharger` | 保留原值，不推断车辆兼容性 |
| `teslaTariff` | 顶层计费字段 | 分项值与分时段 |
| `nonTeslaTariff` | `noneTeslaRate` | 非 Tesla 计费字段；缺失为 null |

### 计费字段边界

样本中 `nowRate=0`，同时 `nowRateSvc=1.07`、`nowRateElc=0.82`。因此不将 `nowRate` 当成最终总价，也不把零值解释为免费。

- `current.base/service/electricity` 分别保留 `nowRate/nowRateSvc/nowRateElc`。
- `periods` 保留 `start/end/days/svcDays/elcDays` 和 `rateBase/rateSvc/rateElc`，不擅自解释空星期字段。
- `maximumParkingRate` 保留 `maxParkingRate`，其具体费用类型、单位和计算规则待确认。
- `noneTeslaRate` 存在、为空或全零，均不能作为站点向非 Tesla 车辆开放的证据；开放字段以目录明确提供的布尔值为准。
- 目前没有将这些费率加总、格式化为页面价格或用于费用估算。

## 分层、性能与降级

- `domain/route-charging`：数据类型和路线几何筛选，独立于 React、Next.js 和供应商 SDK。
- `infrastructure/route-charging`：供应商解析、固定来源获取、目录与详情缓存。
- `app/api/route-charging/tesla`：请求边界、字段校验、站点关联与响应归一化。
- 目录成功结果在服务实例内缓存 6 小时，同一实例共享在途请求；刷新失败可使用不超过 24 小时的旧目录并返回 `stale=true`，失败后至少 60 秒再重试。
- 详情按站点请求，不预取全国详情；缓存 30 秒，最多保存 128 站，最多 16 个不同站点在途请求，同站请求合并。刷新失败返回错误，不延用超过 30 秒的旧可用桩数。
- 缓存是实例内内存缓存，多实例和冷启动可能分别请求上游；未宣称分布式共享缓存。
- 上游请求超时 15 秒；流式限制目录为 8 MiB、详情为 256 KiB，异常响应和空目录不作为成功结果缓存。
- `fetchedAt` 为本站抓取时间，不是特斯拉保证的数据更新时间。目录与详情的抓取时间分别计算。
- 页面选中路段后才消费这些接口。超充面板与查询模块按需加载，响应按方案、修订、供应商与道路轨迹隔离；未选路段时不查询站点，不预取全国详情。

## 第二阶段：路线与地图展示

### 功能与设计

- 点击普通或返程路段，或从完整路线摘要点击“沿途超充”，进入当前路段的候选列表；提供上一段、下一段和返回路线顺序。
- 桌面用列表替换侧栏路线顺序区，保留路段摘要；H5 复用同一个底部任务面板，站点详情在列表内部展开，不增加导航层级。
- 将用户参考图重绘为共享 SVG 轮廓：红色水滴图钉、白色闪电、轻量阴影，选中增加深色边界，保持针尖锚点不变。没有为图标引入图片生成、位图依赖或网络字体。
- 详情展示查询时的桩位、最高功率、地址、Wi-Fi/地锁等已识别设施、停车提示和非 Tesla 开放状态；费率含义仍未确认，不在产品界面展示调试字段。
- 用户可导航或加入当前路段；插入后沿用原有路线重算、撤销和暂存逻辑。原方案点位不会因为数据查询失败而改变。

### 发现与修正

- 根据图钉过大的截图反馈，地图标记由 44×54px 等比缩小三分之一至约 29.33×36px。高德与腾讯复用同一尺寸，针尖锚点同步缩放，保留 SVG 原始坐标与比例，避免拉伸或偏移；列表图标保持原尺寸。
- 缩放后地图包与 Web 生产构建通过；独立浏览器实测两个高德站点图钉均约 29.328×36px，图片与容器尺寸一致（宽度差来自浏览器子像素取整），本地 3100 预览已更新。
- 手机半屏面板中，原路段摘要占用过多空间，已改为站点优先、摘要在后，并去除重复路段说明。
- 原地图单点聚焦直接居中，可能落在手机面板后方；新增共享墨卡托坐标偏移计算，将目标置于实际可视地图区域中心，且不改变面板档位。
- 详情刷新在切换可见性时可能重叠，增加请求版本隔离，避免取消的旧请求把新结果覆盖成错误。
- 列表加载占位、详情数字区、更新时间和设施标签预留尺寸，遵循 CLS=0 目标；未将设计措施等同于已通过全部真实设备性能验收。

## 第三阶段：全程设施图层与点击缓存（2026-09-28）

### 目标与根因

用户反馈：四个控制点对应四段充电列表，加入超充后变成五段，重复找站被迫重新分页。根因是查询、图钉和详情都绑定选中路段。此前章节的分段列表为历史实现，以本节及同步后的正式规范为准。

### 范围与关键决策

- 用「沿途设施＋Tesla 图标开关」替代整行跳转，取消站点列表、前后路段按钮。未来设施有数据后再增加独立图标，不展示无数据占位开关。
- 后台以现有路段几何为传输分片，最多三路并发，合并全程含返程站点。同一站点按 ID 去重，最近路段决定插入锚点；等距重叠道路取首次经过。
- 点击地图图钉才打开单站详情，支持加入途经点和导航。加入后关闭详情、保持设施图层，路线重算后更新候选；已加入站点禁用重复添加。
- 图层与路段选择解耦，PC 与 H5 共享详情组件，移动面板保持用户档位。重算期间保留同一方案、供应商的旧图钉，禁用按旧路径插入。
- 浏览器验收发现控制点标签可能抢占相邻充电图钉点击，高德站点提高点击层级并启用图钉内容指针事件，避免误打开天气。

### 缓存与降级

- 首次主动开启后请求；客户端同一轨迹缓存五分钟，旧目录一分钟，WeakMap 随轨迹释放；服务端继续复用已有目录缓存。
- 同轨迹、同站点的在途请求共享。退出图层或详情仅取消订阅，底层请求有独立超时，完成后缓存，避免快速反复点击重复请求。
- 单站详情最多缓存 100 项，新鲜度按查询时间计算为三十秒。再次打开优先显示缓存；过期注明「缓存待更新」及查询时间，可见页面后台刷新，失败注明失败并保留历史时间。缓存为当前页面会话内存，不承诺刷新页面后恢复。
- 任一分片失败不发布不完整的全程结果；已有候选可保留并提示失败，允许重试。方案、供应商、修订和请求版本隔离旧响应。

- 新增独立领域与客户端请求测试，覆盖全程去重、最近路段/返程锚点、等距顺序、空集合、缓存命中、共享请求取消、手动刷新、失败重试与三路并发限制。
