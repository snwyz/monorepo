# 腾讯地图 Web 适配与路线规划体验迭代

## 1. 迭代信息

- 日期：2026-09-18
- 应用：`apps/roadbook-web`
- 地图领域包：`@roadbook/map`
- 状态：已实现并通过本地检查
- 目标：在保留小程序腾讯地图 SDK 的前提下，为 Web 端补齐腾讯地图 JavaScript API 适配，并完善路线规划工作台的定位、搜索、选点、路线绘制和方案管理体验。

## 2. 核心技术决策

### 2.1 统一地图领域入口

继续保留 `@roadbook/map` 作为地图能力的统一领域入口：

- 小程序端继续使用现有腾讯地图小程序 SDK。
- Web 端在包内新增腾讯地图 JavaScript API 适配器。
- 页面层只依赖 Web 地图领域接口，不直接操作腾讯地图全局对象。
- 控制点、路线分段、定位结果和地点候选项使用统一领域类型表达。

### 2.2 WebService 通过服务端代理访问

地点搜索、地址解析、驾车路线、IP 定位和坐标转换统一通过 Next.js 服务端接口请求腾讯地图 WebService，避免在浏览器中暴露签名密钥。

当前接口包括：

- `/api/tencent-map/suggestion`
- `/api/tencent-map/reverse-geocode`
- `/api/tencent-map/driving`
- `/api/tencent-map/ip-location`
- `/api/tencent-map/coordinate-translate`

### 2.3 环境变量约定

- `NEXT_PUBLIC_TENCENT_MAP_KEY`：浏览器加载腾讯地图 JavaScript API 使用，可公开到前端构建产物。
- `TENCENT_MAP_KEY`：服务端 WebService Key，可选；未设置时服务端可使用公开 Key。
- `TENCENT_MAP_SK`：服务端签名密钥，只能在服务端使用，禁止添加 `NEXT_PUBLIC_` 前缀。

Next.js 默认从具体应用目录读取环境变量。Monorepo 根目录环境文件不会自动成为 `apps/roadbook-web` 的运行环境，因此本地开发应在 Web 应用环境中注入这些变量，例如使用 `apps/roadbook-web/.env.local`。

## 3. 已实现功能

### 3.1 地图加载与页面结构

- 腾讯地图 SDK 由 Web 适配器动态注入，页面不需要手写固定 `<script>` 标签。
- 路线方案选择由全屏弹窗调整为左侧常驻面板。
- 地图首次加载期间展示轻量占位视觉，避免初始化白屏。
- 地图完成首次瓦片加载后显示真实地图。
- 后续定位、平移和地图中心更新不再隐藏已显示地图，避免相同中心点不触发 `tilesloaded` 时卡在加载占位层。
- 地图、面板和工具控件使用绝对定位，不因异步地图加载产生布局跳动。

### 3.2 初始化定位策略

地图初始化采用“IP 优先、精确位置增量更新”的策略：

1. 页面进入后先请求腾讯地图 IP 定位。
2. 使用 IP 位置创建地图，默认地图层级为 11，呈现城市级范围。
3. 如果浏览器位置权限已经是 `granted`，后台继续请求浏览器精确位置。
4. 精确位置可信时，将地图更新到该坐标，地图层级调整为 14。
5. 精确定位失败、超时或精度不足时，继续保留 IP 定位，不影响地图使用。

浏览器返回的经纬度还会通过腾讯地图坐标转换接口进行归一化，确保与腾讯地图底图坐标体系一致。

### 3.3 定位可信度与降级

- 浏览器定位启用高精度模式。
- 主动定位使用 `maximumAge: 0`，避免复用旧的低精度位置。
- 单次定位最长等待 8 秒。
- 浏览器返回的精度误差超过 50 公里时，不再将其视为精确位置。
- 浏览器定位失败时保留已有 IP 位置。
- 定位 Promise 只允许完成一次，超时后迟到的浏览器回调会被忽略，避免重复错误和重复更新地图。
- 用户主动点击定位时始终发起浏览器定位请求，不再被已有 IP 缓存提前拦截。

### 3.4 位置视觉标记

地图包含两类位置图标：

- 屏幕中心点：固定在当前地图可视区域中心，不随地图拖动，不拦截鼠标和触摸事件。
- 用户地理位置点：绑定实际地理坐标，随地图内容移动。

两类图标采用统一视觉：

- 20px 蓝色圆点；
- `#1677ff` 背景；
- 2px 白色描边；
- 圆形阴影；
- 屏幕中心点带脉冲动画；
- 系统开启“减少动态效果”时停止脉冲动画。

IP 初始化成功后即显示用户地理位置点，并将其标记为近似位置；精确定位成功后更新到精确坐标。初始化时屏幕中心点与用户位置点可能重叠，拖动地图后两者会自然分离。

### 3.5 地图交互

- 禁用腾讯地图原生双击放大。
- 保留双击地图添加路线控制点。
- 地图缩放通过滚轮、触摸手势或左下角加减按钮完成。
- 左下角定位按钮用于主动请求浏览器位置并回到当前位置。
- 按 `Esc`、`Delete` 或 `Backspace` 可以删除当前待确认或选中的控制点。
- 地址列表提供明确的删除入口。
- 地图点位与地址列表保持选中状态联动。

### 3.6 地点搜索与地址解析

- 顶部搜索框接入腾讯地图地点输入提示服务。
- 搜索请求通过服务端签名代理发送，解决浏览器直接请求时的签名验证失败问题。
- 搜索结果携带名称、地址和坐标，可直接添加为路线控制点。
- 地图双击选点后调用逆地址解析。
- 地址解析失败时仍保留“地图选点”和坐标信息，用户可以继续调整或删除该点。

### 3.7 路线生成与绘制

- 两个及以上控制点会计算闭合驾车路线。
- 闭合路线包含最后一个控制点回到第一个控制点的路线段。
- 每一段分别保存距离、时间、红绿灯数量和折线路径。
- 腾讯地图 `MultiPolyline` 样式统一使用 `PolylineStyle` 实例，解决样式对象类型错误。
- 路线提供普通、选中、更新中和失败状态样式。
- 路线分段请求顺序执行并进行节流，降低触发腾讯地图状态码 120 的概率。
- 路线重新计算带版本标识，过期结果不会覆盖新控制点对应的路线。
- 控制点更新进行防抖处理，避免拖动或连续选点产生瞬时高频请求。

### 3.8 路线方案与数据保存

- 新用户可直接从地图创建新规划。
- 已有方案通过左侧面板随时加载。
- 路线方案包含控制点、顺序、路线策略和更新时间。
- 当前版本没有登录和注册功能。
- 路线方案仅保存在当前浏览器的 `localStorage`，不会跨浏览器、跨设备或公开分享。

### 3.9 控制点排序、聚焦与路线反馈

- 地址列表移除上下移动按钮、起点文字和独立设为起点操作；排序后的首项天然作为起点。
- PC 鼠标与移动端触控统一采用约 `250ms` 长按激活拖拽，普通点击只选中点位，不触发排序。
- 拖拽 Transform 将 X 轴位移归零，地址列表只开放纵向滚动，横向偏移不再生成左右滚动条。
- 点击地址行或地图点位后，地图中心移动到对应控制点，同时保留用户当前缩放级别。
- 删除入口只显示图标，删除动作与拖拽触发区域隔离，并保留悬停提示和可访问名称。
- 路线生成或更新期间在地图中央显示 shadcn/ui 风格的 Loading 和控制点数量提示；浮层不改变地图布局且不拦截继续编辑。
- 路线策略由浏览器原生下拉框替换为 shadcn/ui `Select`，统一菜单、选中态、键盘焦点和禁用态视觉。
- 点击地图控制点后，在点位右上方通过 Framer Motion 展示圆形删除图标；继续操作地图时自动收起。
- 地图删除图标采用交互后惰性加载，不进入首屏关键资源链路；动效遵循系统“减少动态效果”设置。
- 点击删除图标，或在非文本编辑状态按 `Backspace` / `Delete`，均发起同一个控制点删除确认流程。
- 地图删除图标、地址列表删除图标和键盘删除快捷键统一改为先打开 shadcn/ui Alert Dialog；提示“确认要删除此定位吗？”，提供“取消”和“删除”两个按钮，只有再次确认才调用删除用例。
- 删除确认按钮由整块危险色背景调整为白底细边框，仅保留危险色文字和 Hover 边框，与经典黑白设计基线一致。

## 4. 错误处理与本地调试

本地开发环境会输出统一前缀的定位日志：

```text
[roadbook/map][location]
```

日志只在 `localhost` 和 `127.0.0.1` 输出，不记录腾讯地图 Key 或 SK。

主要事件包括：

- `initial:ip-start` / `initial:ip-success`：初始化 IP 定位；
- `permission:state`：浏览器位置权限状态；
- `geolocation:request-start`：开始浏览器定位；
- `geolocation:success-callback`：浏览器定位成功回调；
- `geolocation:error-callback`：浏览器定位失败回调；
- `geolocation:application-timeout`：应用侧定位超时；
- `geolocation:accuracy-rejected`：定位精度不足；
- `coordinate-translate:success`：坐标转换成功；
- `map:location-applied`：地图中心更新成功；
- `map:user-location-applied`：用户位置图层更新成功；
- `map:tilesloaded`：腾讯地图瓦片加载完成。

## 5. 主要问题与处理结论

| 问题 | 根因 | 处理结论 |
| --- | --- | --- |
| `MultiPolyline.styles` 类型错误 | 直接传入普通对象 | 改为 `PolylineStyle` 实例 |
| 地点搜索状态码 111 | WebService 签名或 SK 配置错误 | 服务端统一计算签名，SK 仅在服务端使用 |
| 路线状态码 120 | 多路线段并发及重复计算导致 QPS 超限 | 顺序请求、节流、防抖和过期结果隔离 |
| 双击地图同时放大 | 腾讯地图默认双击缩放未关闭 | 关闭原生双击缩放，只保留双击选点 |
| 第三点后部分路线缺失 | 分段计算并发、失败状态和旧结果覆盖 | 顺序计算全部闭合路线段并进行版本控制 |
| 点击定位后地图空白 | 后续定位重新进入加载态，但相同视图不触发新瓦片事件 | 加载占位层仅用于首次初始化 |
| 授权后仍停留在错误位置 | 浏览器返回超大精度误差，仍被当成精确坐标 | 设置 50 公里可信度阈值并降级到 IP |
| 主动定位没有发起浏览器请求 | IP 缓存和权限预检查提前返回 | 主动定位跳过预检查并请求最新位置 |
| 定位超时重复报错 | 应用超时和浏览器原生超时先后回调 | 定位 Promise 增加单次完成保护 |
| 只显示屏幕中心点 | IP 近似位置被位置图层过滤 | IP 位置也显示用户地理位置点，精确定位后更新 |
| 长按拖拽与普通点击容易冲突 | 排序与选中共用点位行，需要区分短按和持续按压 | PC 使用 `MouseSensor`、移动端使用 `TouchSensor`，两者统一采用 `250ms` 延迟与 `6px` 容差 |
| Next.js 构建提示 `aria-pressed` 重复 | 拖拽属性与业务选中状态同时写入同一按钮 | 调整属性合并顺序，由业务选中状态最终覆盖拖拽默认属性 |
| 拖拽点位时出现横向滚动条 | Sortable Transform 保留 X 轴位移，同时列表使用双轴 `overflow: auto` | 将拖拽 X 轴归零，并拆分为纵向自动滚动、横向隐藏 |
| 点击点位后地图缩放发生变化 | 聚焦点位复用了同时设置中心和 zoom 的 `setView(point, 14)` | 地图领域接口增加仅更新中心的 `setCenter`，点位聚焦不再修改 zoom |
| 地图点位缺少就近删除反馈 | SDK `MultiMarker` 图形无法直接挂载 React 动效组件 | 点位点击后先保持居中，再在 React 地图覆盖层按视口中心锚定并惰性加载 Framer Motion 删除入口 |
| 键盘删除可能误伤输入内容 | 全局键盘事件未区分文本编辑上下文 | 输入框、文本域、下拉框和可编辑内容获得焦点时忽略快捷键 |
| 多个删除入口直接修改路线 | 地图、列表与键盘入口缺少统一的二次确认状态 | 工作台集中管理待删除点位，所有入口先打开 Alert Dialog，确认后才执行原始删除函数 |

- 浏览器确认点击地图空白区域后删除图标退出；页面始终满足 `scrollWidth = innerWidth`、`scrollHeight = innerHeight`，未产生布局偏移或额外滚动区域。

- 浏览器分别验证点击“取消”和按 `Esc` 后确认框关闭，原有两个控制点均保持不变；为保护本机路线数据，未在浏览器中点击破坏性的“删除”确认按钮。

## 7. 当前边界与后续建议

### 7.1 当前边界

- 浏览器精确定位依赖操作系统、浏览器和网络定位服务，授权成功不代表一定能返回高精度位置。
- IP 定位只能用于城市级初始化，不能代表用户实际所在道路或建筑。
- 腾讯地图 WebService 免费配额和 QPS 仍由腾讯地图控制，前端节流不能替代服务端配额治理。
- 当前数据仅保存在本地浏览器，没有账号体系和云端同步。
- 当前没有公开分享、多人协作和跨设备恢复能力。

### 7.2 后续建议

- 为定位结果补充“精确位置 / 城市级位置”的可视状态说明。
- 在服务端增加路线请求缓存和统一限流，进一步降低状态码 120 风险。
- 为搜索、逆地址解析、坐标转换和路线计算补充自动化契约测试。
- 为腾讯地图适配器增加定位超时、低精度拒绝、IP 降级和过期路线结果的单元测试。
- 账号体系确定后，将本地路线仓储替换为可同步仓储，同时保留离线草稿能力。
