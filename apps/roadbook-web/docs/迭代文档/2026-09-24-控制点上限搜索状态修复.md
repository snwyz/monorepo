# 控制点上限搜索状态修复

## 目标

当活动路线达到 20 个控制点上限时，停止提供无法完成的地点搜索操作，并明确告知用户需要先删除一个点位。

## 范围

- 地点搜索框的禁用状态与提示文案。
- 基于 Radix Toast 的全局公共通知能力。
- 搜索禁用时的进行中请求和候选结果清理。
- 不调整控制点上限、地图服务或路线计算逻辑。

## 关键决策

- 复用领域常量 `ROUTE_PLAN_CONTROL_POINT_LIMIT` 判断是否达到上限，避免在工作台新增魔法数字。
- 由工作台组合层区分“地图服务未就绪”和“控制点已满”两类禁用原因，搜索组件只负责呈现原因并停止搜索交互。
- 提示放在原搜索输入框内，不新增浮层或改变 Widget 尺寸，避免引入布局偏移。
- 公共 Toast 使用 Radix Toast 负责无障碍、计时、滑动关闭和视口管理，业务统一通过 `appToast` 调用。
- Toast 视口固定在屏幕水平中央、距顶部三分之一处，并使用浏览器最高常用层级，避免被地图控件或弹层遮挡。

## 功能变化

- 达到 20 个控制点时，搜索输入框和搜索按钮不可用。
- 输入框显示“当前点位已满（20/20），请先删除一个点位”。
- 首次进入某条路线的满额状态时，同步展示相同文案的 `info` Toast；删除点位后再次达到上限会重新提示。
- Toast 在不同屏幕尺寸下均保持水平居中、距顶部三分之一的位置，不参与页面布局，因此不会产生布局偏移。
- 搜索被禁用时会使旧请求失效，并清空已有关键词和候选列表。
- 删除任一控制点后，搜索自动恢复可用。
- 新增公共 `info`、`success`、`loading`、`fail` Toast API；Loading 可通过返回的 ID 更新为成功、失败或主动关闭。

## 问题与根因

领域用例会拒绝第 21 个控制点，地图插点入口也会在满额时关闭；但地点搜索此前只根据地图服务状态决定是否可用。因此用户仍能搜索和选择候选项，最后由应用 Hook 静默拒绝新增，界面没有解释原因。

满额路线的完整道路折线可能包含大量坐标。高德与腾讯适配器此前先创建经纬度中间数组，再通过展开参数调用 `Math.min` / `Math.max`；坐标数量超过浏览器函数参数上限时会触发运行时错误。现统一改为单次遍历的包围盒聚合，同时完成有效坐标过滤，以 `O(n)` 时间和 `O(1)` 额外空间计算边界。

## 降级策略

地图服务未就绪时继续使用原有“地图服务连接后可搜索”提示；上限状态不影响删除、排序和已有路线查看。

## 已知边界和后续建议

- 地图双击和路段插点已有领域上限保护，不会创建第 21 个控制点。
- 普通经纬度最小值与最大值仍沿用既有矩形边界语义；跨国际日期变更线的最短包围范围不在本次国内地图产品范围内。
