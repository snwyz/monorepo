# H5 底部任务面板重构

## 目标与范围

参考用户提供的苹果地图截图，解决 H5 搜索、方案、地址列表、天气与指标浮层争抢空间的问题。保留路线规划领域、闭环规则、本机存储和桌面工作台布局，重构移动端呈现与交互，不新增导航、账户或多交通方式。

## 关键决策与功能变化

- `WorkspaceTaskSheet` 以同一业务组件树提供收起、半展开、展开三档，默认半屏约可用视口 52%，收起为 96px，展开扣除系统安全区与软键盘。
- 默认半屏发现入口显示搜索、我的路线、新建规划与指南；收起时只保留搜索或当前页面标题。
- 发现、方案目录、路线编辑、路线指南显式切换。路线页使用 72px 简短摘要、连续途经点、添加入口与末尾策略，地点天气及路段摘要是二级详情。
- 整个面板支持连续纵向拖动，包括按钮和地点行；8px 方向判断区分点击与横向操作。上拉先展开后滚动，下拉先回顶再收起；把手保留点击/方向键，移除展开/半屏按钮。
- 任务切换按模式记忆滚动位置；隐藏内容保持组件挂载。搜索打开时同步聚焦，清空文字留在搜索，取消恢复原档位。
- 每个业务最多根页面与详情两层，右上角 X 返回父页面；业务根页面可回到发现入口，保留地图上下文。H5 热门路线预览内联替换搜索内容，X 返回搜索；桌面预览仍使用 portal，破坏性确认仍为独立确认框。
- 地图实例不因面板收放而重建。拖动只更新 CSS 几何变量与内容滚动位置，不逐帧更新 React 业务状态，松手后更新遮挡高度并检查安全区；全展开不强行把路线缩入顶部窄条。
- 地图工具在面板上方两侧：右侧缩放/定位，左侧供应商；全展开隐藏工具。高德与腾讯原生 Logo、版权及审图号按面板位置避让。

## 问题与根因

- 原移动端把独立桌面 Widget 叠到小屏，展开后互相覆盖；现通过统一任务容器管理空间。
- 原地图避让依赖固定顶部/底部像素，无法感知任务面板档位；现使用面板提交的实际遮挡高度。
- 原搜索清空同时关闭搜索，且旧查询可在新查询防抖期间回写；现拆分清空和取消，并在输入时立即废弃旧请求版本。
- 底部面板覆盖原生地图版权；验收时识别并调整位置，未删除地图版权元素。
- 固定专题 URL 使用 force-cache，数据更新可能长期命中旧缓存；现采用 HTTP 重验证。

## 性能与缓存

- 途经点编辑（含 dnd-kit）、路线策略（含选择控件）和专题目录按需分包；天气、预览和删除确认继续按需加载。没有新增依赖、网络字体或动画库。
- 地图容器不随面板改变尺寸；主要动画使用 transform，尊重减少动态效果设置。VisualViewport 处理键盘，pinch zoom 不视为键盘。
- 专题几何使用 `cache: no-cache`，响应 `public, max-age=0, must-revalidate`，支持 ETag 与 304；同一仓储复用在途 Promise，失败清除以允许重试。
- 内容哈希脚本继续使用 Next 静态资源缓存；没有增加 Service Worker 或改写第三方瓦片缓存策略。
- 本地主机通过 `WebVitalsReporter` 记录无坐标、无路线内容的性能指标；CLS-observed 使用 1 秒间隔、5 秒上限的 session window，排除近期用户输入。地图首次 ready 单独记录，不能用 LCP 代替地图可用时间。

## 验证结果

- `pnpm --filter roadbook-web lint`、`typecheck`、生产 `build` 通过；环境无 rtk，直接执行 pnpm。
- 手势几何测试 7 项通过：原有档位边界及新增的连续展开→滚动、回顶→收起、短内容过拉约束。
- 浏览器验证：390×844 三档点击与拖动、搜索候选与取消、连续添加 5 个公开地点形成闭环、返程路段指标、天气打开/关闭；320×568 搜索内容宽度未溢出，面板稳定后顶部为 12px。
- 生产 HTTP 验证：专题响应包含重验证缓存头与 ETag，If-None-Match 请求返回 304。
- 同口径首页 HTML 中 script src 对应的首方 JS（各文件 gzip 后求和，含框架，不含第三方 SDK）：改造前 11 个脚本，原始 886,260 bytes，gzip 272,804 bytes；中间验收版本 10 个脚本，原始 781,873 bytes，gzip 237,572 bytes，gzip 降低约 12.9%。最终复测见下方补充。
- 一次生产构建的本地 390px 视口刷新样本：LCP 380ms，地图首次 ready 1,416ms。未限速，已有浏览器缓存；不是冷启动、真实手机或线上 P75 结果。

## 降级策略与已知边界

- 精确定位不可用时仍允许手动搜索添加起点，不代替用户接受定位权限。
- 无 VisualViewport 时使用窗口高度；不支持布局偏移观测的浏览器跳过本地 CLS 诊断。
- 地址解析、路线和天气保持现有独立失败处理；加载失败不删除用户方案。
- 真机 iOS/Android 的键盘、地址栏伸缩、触摸滚动与排序竞争，以及弱网/低端机耗时仍需要设备验收。桌面尺寸模拟不能宣称这些已经通过。
- Web Vitals 本地观测不是线上真实用户统计；不宣称 INP/P75 已达标。
- 地图标签仍沿用现有碰撞与左右分布规则，密集点位可能互相遮挡。第三方供应商原生控件布局存在差异，需随 SDK 版本继续回归。
- 测试方案仅在本地验收端口的浏览器存储中创建，不改写用户原开发端口的既有方案。

## 后续建议

对同一真实设备分别测冷启动、缓存命中和弱网；采集 LCP、CLS、INP、地图首次可用时间与首方/第三方资源量。优先处理真实设备发现的问题，再评估小面积材质增强。

## 第二轮交互纠偏（用户挑战后）

### 根因与修正

第一轮虽然统一了容器，业务内容仍按桌面 Widget 堆叠，默认收起、仅把手/空白区下拉、业务回调强制半屏均不符合用户要求。本轮将高度与业务导航解耦，默认半屏；容器只接收标题、返回回调、页面键及内容，不再从业务组件类名猜测显示规则。页面通过 `WorkspaceSheetPage` 明确声明活动状态。

- 整块面板分配连续纵向位移，水平动作交给左滑删除和天气横滑，输入编辑不被接管，已激活的长按排序优先。释放速度只取最近一次移动，静止后不沿用旧速度。
- 手势开始时缓存档位、可滚动范围等几何；移动时不重读内容尺寸、不重建地图、不调用算路。CSS transform 移动面板，裁切高度同步，地图遮挡只在释放与视口变化后提交。
- 路线选点、选路段、加载方案、业务切换不再改变高度；搜索主动展开，退出恢复之前档位。
- 地点详情集合地址、导航、删除与七天天气；路段详情集合起终点与摘要。X 回到路线；指南沿线地点也只有一层详情。
- 浏览器验收发现并修复：拖动选择页面文字；透明地点行暴露左滑删除底层；旧指南折叠样式隐藏目录；切换页面时读取已被新内容截短的滚动位置导致返回丢失位置。

### 第二轮验证与性能

- lint、生产 build（含 TypeScript）与 7 项手势几何测试通过。
- 390px 浏览器验收了默认半屏、整行上拉展开并进入滚动、下拉回顶再收起、地点详情 X 返回、搜索聚焦展开及取消恢复半屏、指南内联预览 X 返回与加载指南后回到原半屏高度。
- 首屏 11 个首方脚本通过生产 HTTP 获取，raw 787,616 bytes、gzip 239,516 bytes。相对原始基线 gzip 272,804 bytes 减少约 12.2%；相对第一轮略增约 1.3 KB。最终代码复测如有变化记录在后续补充。
- 固定 390×844 后刷新的一次缓存命中样本：LCP 316ms，地图首次可用 629ms；首屏 CLS-observed 为 0。无弱网限速，不代表真机或线上 P75。
- 首次测试中，先加载桌面再于约 32 秒后切换移动视口产生 LCP 32,564ms，属于跨视口会话样本，不作为固定移动首屏数据；保留异常背景，不删除不利观测。
- 真机触摸、键盘、长按排序竞争与低端设备帧率仍需设备验收；浏览器鼠标拖动与纯函数测试不能证明 iOS/Android 的最终手感。

### 第二轮最终复核

- 真实鼠标点击（避开自动化 locator 的自动滚入视野行为）验证：路线列表滚动 169px → 地点详情 → 右上角 X → 列表仍为 169px。连续手势由地点行开始可展开到全屏并继续滚动，不误触地点详情。
- 指南根页面目录可见，丹东沿线地点下钻后 X 返回；320×568 全展开稳定后顶部 12px，无横向溢出；1440×900 面板恢复 display: contents、移动把手隐藏、桌面搜索可见。
- 最终首屏 11 个脚本，raw 788,025 bytes、gzip 239,689 bytes，比原始基线减少约 12.1%。脚本 immutable 缓存、专题重验证与 ETag 保持有效。

- 不将地图图层产生的位移从 CLS 中过滤掉；保留观测值与来源，让后续优化可复核。

## 搜索返回与清空入口调整（2026-09-26）

- 目标与范围：解决路段添加途经点时重复出现“取消”的问题，调整共享搜索组件与移动搜索栏，同步 UI、组件规范。
- 根因：插入上下文与搜索栏各提供一个关闭动作，返回与输入编辑混在同一输入表面内。
- 功能与决策：插入提示改为“正在添加途经点：起点 → 终点”，移除提示内取消；搜索框外右侧使用 44×44px 的 X 返回上级。框内仅在有文字时显示清空 X，保留焦点和插入目标，继续隔离过期搜索响应。两个图标均具备独立无障碍名称与标题。
- 布局：移动搜索头固定 52px，避免百分比高度随面板伸缩造成额外空白；不新增依赖、资源请求或地图状态更新。
- 验证：lint、生产 build（含 TypeScript）通过；浏览器验证空输入隐藏清空按钮、有输入显示清空按钮、清空后保持焦点与插入上下文、外侧 X 返回路线页；320px 无横向溢出，390px 视觉检查及 1440px 桌面搜索入口回归通过。
- 降级与边界：搜索失败与地图加载沿用既有处理；本次浏览器中地图加载提示持续存在，未据此宣称地图能力验收通过。没有修改路线数据；没有测量同口径 LCP/CLS，不宣称性能指标已通过。
- 后续建议：使用 iOS/Android 真机确认清空时软键盘保持、外侧 X 返回时键盘收起。

## 手机搜索黑框与卡顿静态诊断（2026-09-26）

- 目标与范围：根据用户反馈检查搜索入口黑框、移动面板卡顿与样式异常；本轮只诊断，不修改产品行为。
- 已确认：移动搜索入口与输入容器显式设置 `border: 0`；全局 `button:focus-visible` 设置近黑色 2px outline，移动样式没有覆盖。关闭搜索或加载专题后会主动将焦点移回入口，因此浏览器若将恢复焦点判为 focus-visible，就会出现黑色外环；键盘 Tab 导航同样会触发。输入自身另有 `outline: 0`，不能把入口按钮与展开后的输入框混为一谈。
- 性能风险：VisualViewport resize/scroll 直接同步 CSS 几何、读取布局并提交地图遮挡状态，未合并到动画帧；软键盘动画期间存在连续布局与 React 更新风险。纵向 touchmove 被接管，逐事件写 scrollTop 与祖先 CSS 变量，同时改变内容和背景高度；没有逐帧 React 更新不等于没有布局开销。
- 样式风险：搜索时禁用面板过渡的 CSS 仍匹配 `data-mode="search"`，当前组件只输出 `data-page`，该规则不会命中；搜索展开、聚焦与键盘几何更新可能同时发生。尚未确认这些风险与用户真机症状的对应关系。
- 验证：检查当前组件、CSS 与状态传递代码；用户截图中未显示明显黑色外环。不将静态推断或此前桌面模拟结果表述为真机复现，未重测 LCP/CLS/INP。
- 降级与边界：保持现有行为与键盘可访问性，不直接全局移除焦点提示。后续需补充手机系统、浏览器、卡顿发生阶段及异常状态，进行相应真机复现后修复。

## 现场开屏上下跳修正（2026-09-26）

- 目标与范围：用户现场图显示 iPhone 内置浏览器形态下开屏面板悬空、地图上方大块空白，并反馈上下跳；修正工作台视口定位、键盘误判与搜索聚焦行为。截图不能证明具体浏览器品牌或完整触发顺序。
- 已确认代码问题：未编辑时仍把布局高度与 VisualViewport 的差值作为键盘避让；地图用 svh、面板用 dvh、档位用 VisualViewport，缺少统一基准；页面外层未禁止滚动；搜索关闭动画规则匹配不存在的 data-mode。
- 关键决策与功能变化：移动工作台固定铺满布局视口，地图与档位复用实际布局高度，页面滚动仅由任务面板内部承接。键盘避让要求编辑焦点、未缩放和超过 100px 的底部遮挡，失焦清除。视口和焦点事件按动画帧合并，调整期间暂停吸附过渡；搜索使用真实 data-search-open 状态关闭过渡，程序聚焦使用 preventScroll。
