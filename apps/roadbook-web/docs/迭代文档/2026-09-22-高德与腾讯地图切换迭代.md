# 高德与腾讯地图切换迭代

## 1. 迭代信息

- 日期：2026-09-22
- 状态：标记点修复与双供应商 Chrome 回归完成
- 应用：`apps/roadbook-web`
- 地图领域包：`@roadbook/map`
- 目标：默认接入高德地图，并在页面右下角提供高德地图/腾讯地图 Switch，使用户可以在不丢失路线方案的情况下切换完整地图供应商能力。

## 2. 范围

- 新增高德地图 JavaScript API 2.0 适配器。
- 新增高德地点搜索、逆地址解析、IP 定位、坐标转换和驾车算路代理。
- 新增高德 JavaScript API 同源安全代理，`AMAP_SK` 仅保留在服务端。
- 将 Web 地图组件与应用 Hook 从腾讯具体类型调整为供应商无关接口。
- 页面右下角新增高德地图/腾讯地图 Switch，默认高德。
- 供应商切换后重新创建地图并重新计算当前活动路线。
- 小程序与后端行政区同步不在本次范围内，继续保持现有腾讯实现。

## 3. 关键决策

### 3.1 完整能力切换

Switch 不只替换底图。地点搜索、双击选点后的逆地址解析、定位坐标转换和闭合驾车算路全部跟随当前供应商，避免不同来源数据混用。

### 3.2 领域接口隔离

地图包新增 `WebMapAdapter` 和 `WebMapProvider`。`AmapWebAdapter` 与 `TencentMapWebAdapter` 实现同一契约，`RouteMap` 只接收领域接口，不暴露 SDK 对象。

### 3.3 默认值与持久化

页面每次进入都默认高德地图。本次不保存用户上次供应商选择，确保“默认高德”语义稳定，也不修改现有路线方案快照格式。

### 3.4 高德密钥安全

- 当前环境只需要以下两个变量，不需要新增 WebService 专用 Key 或 SK：

```dotenv
NEXT_PUBLIC_AMAP_KEY=<高德 Web 端 JS API Key>
AMAP_SK=<该 Key 对应的 securityJsCode>
```

- `NEXT_PUBLIC_AMAP_KEY` 仅用于加载高德 Web 端 JavaScript API。
- `AMAP_SK` 作为对应 `securityJsCode`，只由 Next.js 服务端读取。
- 浏览器通过 `/_AMapService/*` 同源代理完成高德 JavaScript API 安全校验。
- 业务 WebService 通过 `/api/amap/*` 服务端路由访问，不在浏览器中拼接或打印安全密钥。
- WebService 开启数字签名时，服务端检测到 10007 后自动按参数名升序生成 MD5 `sig`，并在后续请求中复用数字签名模式。

## 4. 功能变化

### 4.1 地图工作台

- 首次进入显示高德地图。
- 右下角固定展示“高德地图/腾讯地图”双标签 Switch。
- Switch 关闭态为高德，开启态为腾讯；当前供应商同时通过文字字重表达。
- 切换期间 Switch 进入禁用等待态，但保持固定尺寸，不引起布局偏移。

### 4.2 路线与异步隔离

- 切换供应商时递增路线计算版本，旧供应商晚返回的结果会被忽略。
- 旧地图画布销毁后释放覆盖物和事件监听。
- 控制点与路线方案继续保存在原有领域模型和本地仓储中，不因切换丢失。
- 新供应商就绪后使用相同控制点和策略重新计算闭合路线。

### 4.3 高德路线策略

| 领域策略 | 高德策略码 |
| --- | --- |
| 推荐 | `10` |
| 高速优先 | `20` |
| 不走高速 | `13` |

高德返回耗时以秒为单位，适配器统一转换为领域模型的分钟；折线路径由各步骤的 `polyline` 合并，并去除相邻重复点。

## 5. 降级策略

- 高德未配置或连接失败时保留路线方案，显示高德地图不可用信息，用户仍可切换腾讯地图。
- 腾讯地图未配置或连接失败时采用同样处理，不自动静默回退，避免界面供应商标识与实际数据来源不一致。
- IP 定位失败时仍以默认中心创建地图；浏览器精确定位失败时优先保留已有城市级位置。
- 逆地址解析失败时保留坐标并显示“未识别地址”，不阻断算路。

## 6. 性能与布局

- 高德 SDK 与腾讯 SDK 均按当前供应商异步加载，不同时进入首屏关键资源链路。
- 地图容器与 Switch 使用固定尺寸和绝对定位，供应商切换不改变页面文档流，目标 CLS 为 0。
- Switch 使用项目内轻量基础组件，没有增加新的运行时依赖。

## 7. 标记点不可见问题修复

### 7.1 问题与根因

- 高德地图已经成功完成 IP 定位，双击事件也能新增控制点，但用户位置点和控制点均不可见。
- 高德 `Marker` 的内容节点初始尺寸由内容撑开；项目基础样式会为图片设置响应式最大宽度，图片受父级初始零宽度约束后最终渲染为 `0 × 0`。
- 腾讯地图使用带固定宽高的 `MarkerStyle`，因此没有相同问题。这一差异造成了“高德没有定位、双击没有标记”的表象。

### 7.2 修复决策

- 高德适配器继续在基础设施层创建 Marker 内容，不向页面泄漏高德 SDK 类型。
- Marker 内容增加固定尺寸容器，并显式解除图片响应式最大宽度约束；用户位置点和控制点复用同一尺寸边界。
- 容器和图片继续禁用指针事件，保证双击选点、滚轮缩放、触摸手势与地图拖动不被标记内容拦截。
- 路线摘要按当前供应商显示数据来源；海拔降级文案改为供应商无关描述，避免切换后残留腾讯专属文案。

- 供应商选择当前不持久化；若未来需要记忆选择，应作为独立产品决策并保证首次用户仍默认高德。

## 10. Vercel 构建兼容性修复

### 10.1 问题与根因

2026-09-23 的 Vercel monorepo 构建在 `@roadbook/map` 阶段失败：高德路线步骤合并逻辑使用了 `Array.prototype.at(-1)`，但地图包 `tsconfig.json` 的运行库基线为 `ES2019`。`.at()` 属于 ES2022 API，TypeScript 因此报告 `TS2550`，构建在生成 Web 应用前终止。

### 10.2 修复决策

- 使用 `path[path.length - 1]` 读取最后一个坐标，保持原有去重语义。
- 不提升地图包的 `lib` 或运行目标，避免只放宽类型检查却把 ES2022 API 依赖留给旧运行环境。
- 本次不调整 `turbo.json` 或 Vercel 环境变量声明；相关警告不属于本次授权范围。

### 10.3 验证记录

## 11. 定位兼容与控制点导航修复

### 11.1 问题与根因

- 高德 IP 定位响应的 `rectangle` 字段在无有效矩形时可能不是字符串；适配器只声明了静态字符串类型并直接调用 `split`，导致浏览器精确定位失败后进入 IP 降级路径时抛出运行时错误。
- 地址列表的导航图标归属于路段连接行，生成的是地图网页 URI；高德虽然携带 `callnative=1`，仍会先进入网页分发逻辑，不能保证按产品要求直接调用客户端。

### 11.2 修复决策

- IP 定位矩形在解析前执行运行时类型校验；非字符串响应视为无可用城市矩形并进入既有降级流程，不再把供应商返回值直接当作可信类型。
- 导航图标移动到每个控制点行，语义调整为“设备当前位置到该控制点”。路段连接行只负责选择路段，不再承载导航入口。
- 高德使用 `amapuri://route/plan/`，腾讯使用 `qqmap://map/routeplan`，不再通过地图网页 URI 中转，也不提供网页回退。
- 路线摘要保留选中路段的起终点外部入口，但统一改用相同的 App Scheme 生成器。

### 11.3 降级与边界

- 设备未安装对应地图 App 时，Scheme 是否被系统处理取决于浏览器与操作系统；Roadbook 不自动跳转网页或下载页。
- 腾讯 Scheme 的 `referer` 使用公开的 `NEXT_PUBLIC_TENCENT_MAP_KEY`；未配置该 Key 时腾讯地图能力本身不可用。
- 本次没有新增依赖，控制点行和导航点击区域使用固定尺寸，不改变首屏资源链路或异步布局，LCP 与 CLS 目标不变。
