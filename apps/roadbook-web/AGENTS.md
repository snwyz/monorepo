## 1. 项目一句话定义

Roadbook Web 是一个以全屏地图为工作区、以地图控制点为路线意图、支持本机多方案管理和闭合驾车路线计算的单页面自驾环线规划工具。

产品规划的是“路线”，不是逐日“行程”。

## 3. 产品边界

### 3.1 MVP 负责

- 本机多路线方案的创建、列表、重命名、删除和主动加载。
- 地点搜索、地图双击选点和控制点编辑。
- 按用户指定顺序生成闭合驾车路线。
- 全程路线策略、里程、耗时和可用道路信息。
- 基础海拔和地形分析。
- 点击路线控制点 Marker 查看含今天的未来 7 天天气，辅助近期路线判断。
- 活动方案在当前浏览器自动暂存。
- 路段与外部地图导航衔接。
- 从全局搜索进入只读热门自驾路线专题，按地图层级查看国道编号与完整官方控制点，并创建本机“我的标记”。

### 3.2 MVP 不负责

- 登录、注册、账户体系、云端同步和跨设备恢复。
- 自动恢复上次活动方案。
- 景点、酒店或基于用户画像的智能推荐；首版只提供人工维护的热门自驾路线专题。
- 出行日期、计划天数、逐日路线、每日结束点和日均驾驶目标。
- 费用估算、收费里程和强度评价。
- 页面内实时导航、轨迹跟踪、偏航重算和实际驾驶状态。
- 默认公开路线或多人协作。

当前路线方案保存在浏览器 `localStorage`。本地保存不等于云端保存，也不等于下次启动自动加载。

热门自驾路线与用户路线方案是两个独立上下文。热门路线本体只读，不进入 `RoutePlan`、不触发闭环算路；用户在专题中添加的“我的标记”按专题独立保存在本机，只支持定位、删除和外部导航。

## 4. 核心用户流程

### 4.1 新用户

进入全屏地图 → 搜索地点、双击地图或点击“新建规划” → 创建未命名路线并以浏览器精确当前位置作为起点 → 添加后续控制点 → 生成闭合路线 → 查看指标与海拔 → 自动暂存。

若精确定位不可用，不得以 IP 城市级近似坐标静默创建起点；保留空方案并引导用户通过搜索或地图选点手动添加起点。

首次进入不得预先创建无意义空方案。

### 4.2 老用户

进入未加载路线的地图 → 查看“我的路线”摘要 → 主动选择一条方案 → 加载控制点 → 适配地图视野 → 请求路线 → 展示指标 → 异步加载海拔。

不得自动加载上次活动方案或因读取方案索引而自动发起路线请求。

### 4.3 编辑

控制点变化 → 旧路线标记为更新中 → 计算闭合路线 → 汇总指标 → 更新海拔 → 暂存同一方案的新修订版本。

过期异步结果不得覆盖新控制点或新活动方案。

## 6. 地图能力基线

### 6.1 跨端入口

- `@roadbook/map` 是统一地图领域入口。
- 小程序继续使用现有腾讯地图小程序 SDK。
- Web 默认使用高德地图 JavaScript API，并允许用户通过页面左下角的紧凑地图入口切换腾讯地图。
- Web 页面通过 `WebMapAdapter`、`WebMapCanvas` 等领域接口操作地图，不依赖具体供应商类型。
- 地图供应商切换同时作用于底图、地点搜索、逆地址解析、定位坐标转换和驾车算路。

### 6.2 服务端地图接口

- `/api/tencent-map/suggestion`
- `/api/tencent-map/reverse-geocode`
- `/api/tencent-map/driving`
- `/api/tencent-map/ip-location`
- `/api/tencent-map/coordinate-translate`
- `/api/weather/forecast`：按坐标查询并归一化腾讯未来 7 天天气，成功结果缓存 `30` 分钟

地点搜索、逆地址解析、驾车路线、IP 定位和坐标转换不得在浏览器中使用 SK 直接签名。

高德地图对应接口包括：

- `/api/amap/suggestion`
- `/api/amap/reverse-geocode`
- `/api/amap/driving`
- `/api/amap/ip-location`
- `/api/amap/coordinate-translate`
- `/_AMapService/*`：高德 JavaScript API 同源安全代理

离线生成热门路线道路几何时，高德 Web API 的账号级并发上限为每秒 `3` 次。生成脚本必须让所有高德请求共享同一节流器，调用间隔不得短于 `400ms`（约每秒 `2.5` 次），不得用并行分段请求突破该上限。

### 6.3 环境变量

- `NEXT_PUBLIC_TENCENT_MAP_KEY`：浏览器加载地图 JavaScript API。
- `TENCENT_MAP_KEY`：服务端 WebService Key，可选。
- `TENCENT_MAP_SK`：服务端签名密钥，禁止添加 `NEXT_PUBLIC_` 前缀。
- `NEXT_PUBLIC_AMAP_KEY`：浏览器加载高德地图 JavaScript API 的 Web 端 Key。
- `AMAP_SK`：与高德 Web 端 Key 配套的 `securityJsCode`，仅允许由服务端安全代理读取。

不得读取、打印、提交或写入文档中的真实 Key/SK。Next.js 环境变量应注入到具体 Web 应用运行环境；不要假设 monorepo 根目录环境文件会自动加载。

## 7. 定位行为基线

### 7.1 初始化

1. 默认先通过 IP 定位。
2. 以 IP 位置和地图层级 11 创建地图。
3. IP 成功后显示用户地理位置点，状态为近似位置。
4. 若浏览器权限已是 `granted`，后台请求精确位置。
5. 精确位置可信时转换坐标、更新用户位置点，并将地图层级更新为 14。
6. 精确定位失败时保留 IP 位置和可交互地图。

### 7.2 主动定位

- 点击定位按钮始终调用浏览器定位。
- `maximumAge` 为 0，定位超时为 8 秒。
- 浏览器精度误差超过 50 公里时，不视为可信精确位置。
- 定位 Promise 只能完成一次；超时后的迟到回调必须忽略。
- 失败后降级到已有 IP 位置，并向用户说明“精确定位失败，已定位到当前城市”。
- 定位和平移过程中不能隐藏已经显示的地图。

### 7.3 位置图标

- `center_icon` 固定在地图可视区域中心，不属于地理坐标图层。
- `loc_icon` 绑定用户地理坐标，属于独立地图标记图层。
- 两者使用 Apple 蓝 `#0A84FF` 圆点、3px 白环和静态柔和精度光晕；用户位置图层使用 32px 画布，屏幕中心点保持 20px 主体。
- 导航蓝只用于规划路线边界、控制点和定位信息，不扩展为页面通用品牌色。
- 初始地图中心与 IP 位置相同时两点会重叠；拖动地图后自然分离。
- 图标不得拦截双击选点、滚轮缩放、触摸手势或地图拖动。

## 8. 地图交互与路线规则

- 禁用地图原生双击放大；双击只用于添加控制点。
- 地图缩放使用滚轮、手势或左下角加减按钮。
- `Esc`、`Delete` 或 `Backspace` 删除待确认或当前选中点；输入框编辑时不得误触。
- 地图点位点击负责选中、聚焦并按需打开七天天气卡片，不在点位或定位标记旁展示删除图标；删除入口保留在地址列表、移动端左滑和键盘快捷键。
- 点击有效路线段后展示端点间的虚线路段插入引导与中间拖拽手柄；拖动期间只更新地图预览，松手后才在该路段顺序中插入正式控制点、逆地址解析并重新算路。再次点击当前路段、点击地图空白处或按 `Esc` 均取消路段选择。
- 地址解析失败保留坐标并显示“未识别地址”，不阻断路线计算。
- 新增第 2 个及后续控制点时，仅在完整点集超出响应式安全可视区时自动适配视野；移动端新旧点直线距离超过 2 公里作为兜底触发。
- 路线计算完成后使用全部路段折线复核视野，道路绕行超出安全区时平滑缩小 zoom，确保完整路线可见。
- 两个及以上有效控制点计算闭合路线，最后一个点必须返回第一个点。
- 路线段顺序请求并节流，避免地图供应商 QPS 限流。
- 控制点变化需要防抖；路线请求使用版本号隔离过期结果。
- 旧路线在更新期间保持可见并标记状态，不闪成空白。
- 腾讯适配器的 `MultiPolyline` 样式必须使用腾讯地图 `PolylineStyle` 实例。

## 9. UI 基线摘要

- 全屏地图是页面主体，业务能力通过边缘浮动 Widget 呈现。
- 桌面端方案选择使用左侧常驻面板；H5 使用统一底部任务面板，默认半屏，禁止初始化全屏模态弹窗。
- 主色体系是暖白、纯白、近黑和稳定灰阶。
- 页面 Widget 保持黑白克制；地图覆盖物使用受控的导航蓝、路线绿和状态色，其中绿色有效路线内芯不代表实时交通数据。
- Widget 使用实色表面、轻边框、克制阴影，不使用玻璃模糊。
- `RoutePlanSelector` 按本地日期分组路线，优先使用“起点 → 终点”标题和“`HH:mm · N` 个途经点”摘要；Hover 只提供低对比中性底色并淡出分割线，Selected 使用暖白表面、极浅内描边、淡绿色路线图标底和尾部勾选，不使用粗黑侧边条或会被滚动容器裁切的外投影。桌面端悬停活动路线时，勾选切换为低透明暖红灰删除入口；移动端隐藏该入口并继续使用左滑删除。
- 有效规划路线采用“白色隔离层＋导航蓝边界＋路线绿内芯”的三层结构；旧结果和失败路段分别使用灰色、红色虚线，不显示蓝绿双层。当前路段通过整组三层线宽突出，不只靠颜色。
- 控制点编号与地址列表顺序、选中和删除状态一致。
- 路线地址列表的普通编号使用白底导航蓝描边，选中编号使用蓝底白字并配合淡蓝行背景；首项不设置黑色特例，路段连接线使用低透明导航蓝，不在紧凑列表中复制绿色路线内芯。
- 地图控制点仅展示“编号＋地点名称＋引导线”标签，不再叠加独立圆形编号 Marker；标签自身承接点位点击选择事件。
- 天气卡片使用独立暖白 Widget 展示含今天的未来 7 天；天气图标、卡片组件和请求 Hook 在首次 Marker 点击后懒加载，窄视口横向滚动，不进入首屏关键资源。
- 移动端使用 `WorkspaceTaskSheet` 的收起、半展开、展开三档；搜索、我的路线、路线编辑和天气互斥显示。高度由用户连续滑动控制；业务根页面与详情最多两层，右上角 X 返回父页面。收起态显示搜索或标题，地点天气属于路线详情。
- 桌面端地图工具仍在左下；移动端缩放与定位在面板上方右侧，供应商入口在左侧，随面板拖动，展开态隐藏工具；地图版权标识必须避让面板。
- `RouteMetricsPanel` 在完整路线中默认展示往返里程与往返用时，允许同步切换为不含返程段的单程里程与单程用时；选中路段时展示该路段的里程和预计驾驶时间。红绿灯与外部导航不进入摘要面板，控制点导航继续由地址列表承担。
- 首次地图加载可以使用等尺寸占位层；后续定位、平移和路线更新不得重新显示首次占位层。
- 状态不能只通过颜色传达。
- 所有异步区域预留稳定尺寸，目标 CLS 为 0。
- 桌面端良好网络下 LCP 目标不高于 2.5 秒。

详细 Token、尺寸和验收项必须读取：

`apps/roadbook-web/docs/UI规范/UI设计规范.md`

## 10. 组件实现摘要

- 页面只负责组合，业务组件负责展示，Hook 负责编排，领域层负责规则，基础设施负责外部系统。
- 同一供应商生命周期内地图实例只创建一次；切换供应商时销毁旧实例，再创建新实例。
- 控制点、路线、位置和选中状态通过独立方法增量更新。
- 控制点、用户位置、路线外描边和路线主线使用独立图层。
- Effect 只同步外部系统，依赖完整，异步回调具备 `disposed`、版本号或取消机制。
- 可由 Props 推导的值不得重复保存为本地状态。
- SDK 实例使用 Ref；会影响视图的状态仍使用 React State。
- 搜索需要防抖并忽略过期响应。
- 天气预报按坐标使用客户端内存缓存、Next 服务端缓存和标准 HTTP 缓存；供应商响应在服务端归一化，错误不缓存，切换 Marker 时取消旧请求。
- 组件至少考虑 `idle`、`loading`、`success`、`empty`、`error`、`stale` 和 `degraded`。
- 图标按钮具有 `aria-label` 和 Tooltip；装饰性图形使用 `aria-hidden`。
- 新增 SDK 图层时必须在销毁流程释放。

详细准入清单必须读取：

`apps/roadbook-web/docs/组件规范/组件设计与实现规范.md`

## 11. 数据、隐私与安全

- 路线方案默认仅保存在当前浏览器。
- 不默认公开、发布或分享用户路线。
- 普通日志不得包含完整路线、全部控制点、方案名称或密钥。
- 本地定位调试日志仅允许在 `localhost` 和 `127.0.0.1` 输出。
- 服务密钥只在服务端管理；客户端公开 Key 按地图 SDK 要求限制来源。
- 外部地图、高程和路线能力必须在宣称完成前验证字段、权限、额度、缓存和展示许可。
- 任何计算失败都不能导致用户控制点或其他方案丢失。

## 12. 质量门禁

### 12.1 修改前

- 读取本文件和任务对应的正式规范。
- 确认需求是否属于 MVP 边界。
- 检查工作树，保留用户已有修改。
- 不读取 `.gitignore` 中的环境、密钥、缓存或构建产物。
- 明确会影响的领域、组件、接口和文档。

### 12.2 修改后

按改动范围执行最小充分验证：

```bash
rtk pnpm --filter @roadbook/map typecheck
rtk pnpm --filter roadbook-web lint
rtk pnpm --filter roadbook-web build
rtk git diff --check
```

- 修改 `packages/map` 时，必须先执行 `rtk pnpm --filter @roadbook/map build`，再执行受影响应用或 monorepo 完整构建，确保 ES2019 类型基线和真实产物构建同时通过。
- 出现 `TS2550` 等内建 API 兼容性错误时，优先改用 ES2019 等价写法；只有在明确更新运行环境兼容矩阵并提供必要 polyfill 后，才允许提高 `target` 或 `lib`。
- 只改文档时不要求重新构建应用，但必须检查标题、链接、格式和文档一致性。
- 生产构建可能自动改写 `apps/roadbook-web/next-env.d.ts`；如果并非本次改动，恢复原有开发声明路径。
- 浏览器交互变更必须验证实际页面，不仅依赖静态检查。
- 定位授权、精确位置和其他敏感浏览器权限由用户控制，不代替用户授权。

### 12.3 地图浏览器验收

- 首次地图加载后占位层退出。
- IP 初始化位置和层级 11 正确。
- 定位失败时地图保持可见。
- 中心点固定，用户位置点随地图内容移动。
- 双击添加控制点时地图不放大。
- 滚轮、手势和加减按钮可缩放。
- 创建至少 5 个控制点的闭合路线，确认所有路线段均绘制。
- 点击普通路段和闭环返程段，确认虚线与拖拽手柄出现；拖动期间不请求算路，松手后新控制点插入正确顺序并触发一次路线更新。
- 删除点位后编号、地址列表和路线同步更新。
- 页面首次进入默认高德地图；左下角紧凑地图入口可切换腾讯地图并重新计算当前路线。

## 15. H5 任务面板实现补充（2026-09-26）

- H5 的长期设计基线是“地图主体＋单一当前业务面板”：默认半屏，整块面板连续拖动；普通业务操作不得替用户改变高度，搜索是主动展开入口。
- 每个业务面板讲清一个完整任务，最多根页面与详情两层；X 返回父页面，切换业务替换当前内容，不继续叠加层级。禁止将桌面 Widget 原样堆入移动面板。
- 具体交互与评审清单见 [UI 规范 5.3、5.4](docs/UI规范/UI设计规范.md)，状态职责与性能验证口径见 [组件规范 18](docs/组件规范/组件设计与实现规范.md)。
- 桌面与移动端共享同一业务组件树，CSS 决定布局，不在 hydration 后替换整棵树。
- 整块面板按纵向手势分配高度变化与内容滚动，拖动不更新 React 业务状态，松手吸附后更新地图安全区；全展开不把整条路线挤进顶部窄条。
- 软键盘通过 VisualViewport 调整面板可用空间，页面缩放不视为键盘；真实 iOS/Android 键盘手势必须另行真机验收。
- 途经点编辑（含拖拽依赖）、路线策略、专题目录、天气与确认框按需加载。
- 专题几何使用 HTTP 重验证与 ETag；客户端共享在途请求，失败后可重试，不强制永久命中固定 URL。
- `WebVitalsReporter` 仅在本地主机输出无位置与路线内容的性能记录；LCP 不能替代首次地图可用时间。项目 CLS=0 是目标，当前地图图层偏移与真机触摸/键盘验收仍未闭环，不得把用户认可交互方向写成全部性能验收通过。
