# Roadbook Web 一致性与故障处理设计

更新日期：2026-10-09。版本：V1.1。状态：实施前设计；所有故障与并发验收尚待执行。

本文事务基线是同一 Web 业务数据库内的跨 schema 操作，不是跨数据库事务。物理归属、拆库准入与每个写库保留本地 outbox 的规则见 [数据库分库分表与建表规范](数据库分库分表与建表规范.md)；未来拆库必须先修改一致性协议，不能直接照搬本地原子提交保证。

## 1. CAP 的适用边界

CAP 指出：发生网络分区时，不能同时对所有请求保证原子一致性与可用性。这里的 C 是线性一致性，A 是符合模型的请求持续得到有效响应，不等同于 ACID 中的约束一致性或业务可用率。[Gilbert 与 Lynch 原论文](https://groups.csail.mit.edu/tds/papers/Gilbert/Brewer2.pdf)

因此本项目不宣称“同时满足 CAP”，也不简单给整个系统贴 CP/AP 标签。对权威私人数据，在无法联系可信写入节点时不确认云端成功；对可重建的公共投影，允许返回有界旧数据。

浏览器离线继续编辑属于本地可用性，不等于云端已接受写入。PostgreSQL 事务、乐观版本锁可以保护单主聚合，却不能单独证明跨故障切换的线性一致性。

## 2. 按操作定义取舍

| 操作 | 权威来源 | 分区或依赖故障时的行为 | 一致性要求 |
| --- | --- | --- | --- |
| 登录、权限、会话撤销 | 认证供应商或 PostgreSQL 会话与用户状态 | 无法验证时拒绝新的受保护访问 | 安全优先，不用旧缓存授权 |
| 私人路线创建、保存、删除 | PostgreSQL 主节点 | 不返回云端成功；本机保留待同步操作 | 聚合事务、版本条件与幂等 |
| 导入、复制、fork、裁剪提交 | 版本化候选/源内容＋PostgreSQL | 解析可排队，提交时无法验证来源/目标则失败；原路线不受影响 | 固定源版本、目标独立、对象先完成后事务引用 |
| 会员高点数操作 | 权威订阅与版本化策略 | 无法核验不确认新权益操作，不截断存量路线 | 服务端判定与有期限的受理快照 |
| 短信验证与换号 | 一次性 challenge＋号码凭据 | 依赖失效时不放行验证码猜测或换绑 | 原子消费与号码唯一约束 |
| 私人路线读取 | 经授权的主节点聚合快照 | 可在本人当前本机工作区展示旧副本并标记；不跨用户回退 | 云端读己之写；不把未知状态当最新 |
| 热门专题 | 已发布静态版本/CDN | 可继续展示已知版本 | 有版本的只读内容 |
| 天气、公共站点事实 | 合法供应商与许可内缓存 | 在允许的有效期/旧数据窗口内返回，并标注来源时间 | 有界陈旧；错误不伪装新结果 |
| 海拔公共接口额度 | 共享协调器；严格预算时使用持久账本 | 无法确认额度时拒绝新外部调用 | 保守控制，不退回每实例计数 |
| AI 生成 | 固定输入版本＋运行记录 | 可延迟/失败；核心路线编辑继续可用 | 异步、可追溯，不保证自动完成 |
| AI 建议应用 | PostgreSQL 路线聚合 | 版本或权限无法确认即拒绝 | 与人工写入使用同一事务协议 |

这些是业务操作策略，不代表选用某一品牌数据库后天然获得对应保证。

## 3. PostgreSQL 事务与读取

### 3.1 写入事务

一次路线保存必须在同一事务完成：

1. 验证会话、用户状态与输入契约。
2. 按用户、操作与幂等键占用幂等记录，并检查请求哈希。
3. 用 owner、方案标识、基础版本和未删除条件更新聚合根，获得写锁。
4. 按内容模式验证控制点/会员策略，或引用 ready 的权威几何，重算内容输入哈希；同时锁定必要资源以防回收竞争。
5. 插入不可变修订；需要异步投影时插入发件箱。
6. 保存原版本回执，提交后返回成功。

版本更新示意，非本次执行的迁移或生产 SQL：

```sql
UPDATE planning_route_plan
SET version = version + 1,
    name = :name,
    strategy = :strategy,
    intent_hash = :intent_hash,
    updated_at = now()
WHERE id = :plan_id
  AND owner_id = :actor_id
  AND version = :base_version
  AND deleted_at IS NULL
RETURNING version;
```

受影响行数必须为 1，否则不更新控制点或修订。事务中不进行地图请求、模型调用或其他慢网络操作。

首期聚合写入可以使用条件更新与唯一约束保护的 Read Committed 事务；复杂跨行规则必须锁定相应聚合根，必要时使用 Serializable 并对整个事务做有界重试。不能只先读版本、再无条件更新。[PostgreSQL 隔离级别说明](https://www.postgresql.org/docs/current/transaction-iso.html)

### 3.2 读取一致快照

- 根与控制点通过单条聚合查询，或 Repeatable Read 只读事务读取；不能在普通多语句读取中拼出不同版本。
- 保存后返回提交版本与完整回执；后续需要“最新”语义的读取走主节点，不走延迟只读副本。
- 云端目录、详情和同步状态带服务端版本，客户端丢弃比已确认版本更旧的结果。
- AI、检索、审计读取指定不可变修订，不读取随请求不断变化的当前控制点。

### 3.3 复制与故障切换

PostgreSQL 流复制默认可以是异步的；切换到落后副本可能丢失已确认事务。生产方案必须核实托管服务的复制、写入确认、切换隔离与恢复保证。[复制说明](https://www.postgresql.org/docs/current/warm-standby.html)

- 如业务要求故障切换后也不丢已确认写入，供应商的提交与复制保证必须支持此要求，并实际演练；不能靠应用重试补齐证明。
- 若预算只支持异步复制，明确记录数据损失窗口、恢复程序和剩余风险，不承诺全局强一致。
- 单主写入要求隔离旧主，防止脑裂；不自行做多地域双写或客户端任选节点写入。
- 事务隔离与复制耐久性分别验收；Serializable 不能消除异步复制损失。

## 4. 保存协议、冲突与本机状态

### 4.1 拟议 HTTP 契约

| 接口 | 契约 |
| --- | --- |
| `POST /api/route-plans` | 幂等键＋初始意图；由会话确定 owner，返回版本 1 |
| `GET /api/route-plans` | 游标分页，仅查询本人活动方案 |
| `GET /api/route-plans/{id}` | 返回单版本聚合与 ETag |
| `PUT /api/route-plans/{id}` | 内容模式＋完整意图或 ready 几何引用＋`baseVersion`＋幂等键；首期不用任意 JSON Patch |
| `DELETE /api/route-plans/{id}` | 基础版本＋幂等键；写删除墓碑 |
| `POST /api/route-plans/local-import` | 安装标识、本机方案标识、结构版本、快照哈希与明确确认；与路线解析分开 |
| `POST /api/route-imports` | 文件资产引用、链接或文本输入之一；返回本人持久解析任务 |
| `GET /api/route-imports/{id}` | 本人的解析状态、候选与警告，不把候选称为已保存路线 |
| `POST /api/route-import-candidates/{id}/accept` | 固定候选哈希＋幂等键；校验权益后事务创建本人方案 |
| `POST /api/route-plans/{id}/copies` | 明确源版本＋幂等键；检查复制权限与目标用户权益 |
| `POST /api/route-plans/{id}/forks` | 明确源版本＋幂等键；检查持久派生权并写血缘 |
| `POST /api/route-plans/{id}/trim-jobs` | 固定源几何与原始边范围，生成可预览裁剪结果 |
| `POST /api/route-trim-jobs/{id}/apply` | 同方案保存或另存模式＋基础版本＋幂等键；旧结果不覆盖新编辑 |
| `GET /api/route-plan-operations/{operation}/{key}` | 本人对应操作的最小回执，解决超时后的结果查询 |
| `POST /api/auth/sms/challenges` | 指定号码与用途；受共享限流，不暴露注册状态 |
| `POST /api/auth/sms/verify` | 原子消费指定 challenge，签发可撤销会话 |

私人响应使用 `Cache-Control: private, no-store`，不得进入公共 CDN。错误：未登录 401；不可见资源 404；已确认身份但缺少功能权益 403；版本冲突 409；输入错误 400；速率额度不足 429；依赖不可用 503。只有对已确认可访问资源才披露删除或当前版本信息。

### 4.2 本机修订与云端版本

客户端独立维护：`localRevision`、`lastSyncedLocalRevision`、`lastConfirmedCloudVersion`、`pendingOperationId`、`syncStatus`。

- `syncStatus` 至少有 `local-only / pending / syncing / synced / conflict / failed`。
- 本机暂存成功与云端同步成功分别显示，不将当前 `DraftStatus.saved` 直接解释为云端成功。
- 每次发送冻结对应快照；回执只确认该快照，不能把发送后新增编辑标记为已同步。
- 同一方案在本设备串行提交并合并尚未发送的编辑；跨设备由数据库版本条件防覆盖。
- 现有同步仓储与切换前 flush 保留本机职责；新增异步远程仓储和云同步编排，不能在页面卸载时假设网络已完成。
- 匿名本机方案与登录用户的云端缓存分命名空间；切换账户不得自动上传另一身份的缓存。登出时清除对应云端会话与受保护缓存，未同步内容先按明确产品流程保留或导出，不能因清缓存丢失用户编辑。

### 4.3 冲突行为

两个设备都以版本 7 编辑，只有一个保存能成为版本 8，另一个得到冲突。保留本机版本，展示云端版本供用户选择重新编辑、另存副本或明确覆盖最新基础版本。

不按客户端时间戳实施最后写入覆盖，不自动合并控制点顺序，不静默丢弃删除。离线操作晚于删除到达时仍被墓碑阻止；过了墓碑支持窗口要求重新同步。

## 5. 幂等与未知结果

- 幂等键作用域是认证用户＋操作；请求哈希包含规范化版本、目标、基础版本和正文，不含会变化的跟踪时间。
- 同键同请求返回原提交版本的回执；同键不同请求拒绝。数据库唯一约束协调并发，不依赖 Redis 去重。
- HTTP 超时不代表数据库回滚。客户端先查回执或使用同键重试，不能换键盲目新建。
- 幂等记录与业务变更同事务提交；失败事务没有已完成回执。外部异步任务则由持久任务状态表示执行中与结果。
- 幂等回执不保存完整私人正文；引用不可变版本，并在读取时重新校验当前访问权。
- 幂等保留窗口在上线前确定；超过窗口不能声称仍能去重。长离线导入依赖独立导入映射，删除后的旧命令还受版本和墓碑保护。

## 6. Redis 的职责与故障边界

### 6.1 原子限流

以环境、供应商账户、接口与业务主体划分限流键；使用 Lua 或等效原子操作完成检查、计数与过期设置。账号级 QPS 必须由所有使用同一供应商 Key 的工作负载共享，不能只按用户各设一个额度。

- 调用前消耗额度；重试仍计入供应商调用预算。
- Redis 不可用时，高成本/硬额度请求返回可重试错误，不回退本机计数。
- Redis 异步复制故障切换仍可能丢计数；“原子”不等于跨故障绝对不超额。严格日预算或模型费用使用 PostgreSQL 持久额度预留与核销，必要时再配供应商硬预算。
- 高程公共源还需全局最小间隔与排队控制；仅有日计数不足以保护 QPS。需要严格串行时由持久任务领取与调度承担，不能用进程 Promise 队列替代。

### 6.2 缓存与请求合并

键包含环境、上下文、格式版本、来源版本、必要输入哈希和用户作用域。私人位置及路线默认按用户隔离，不以可枚举明文坐标作为公共键。

| 数据 | 现有/建议新鲜度 | 故障策略 |
| --- | --- | --- |
| 天气 | 沿用成功缓存 30 分钟 | 只在产品允许的旧数据窗口内展示时间与状态；错误不缓存成成功 |
| 超充目录 | 沿用 6 小时新鲜、最长 24 小时旧快照 | 明确缓存时间和过期；超过上限失败 |
| 超充详情 | 沿用 30 秒新鲜 | 超期展示须标记待更新；不承诺实时可用桩位 |
| 海拔原始读数 | 在来源许可内按来源与算法版本缓存 | 缺失不补零，限流失效不继续请求 |
| 私人路线详情 | 初期不设置 Redis 正文缓存 | 直接权威读取，减少失效与越权复杂度 |

缓存是可重建投影。Redis 缓存失败可以回源，但必须仍通过供应商额度保护；无额度保护时不能无限回源。

短锁可以减少重复加载，要求唯一 token、到期和 compare-and-delete 释放。锁丢失最多造成重复缓存计算，不能据此确认业务保存、AI 建议应用或任务唯一执行。失效通知可能重复或丢失，版本化键与 TTL 提供兜底。

`ioredis` 的 TCP/TLS 连接串与 HTTP Redis 的 URL/token 不是同一配置契约；在选供应商后通过基础设施适配，不让领域层依赖具体客户端。

## 7. 异步任务与事务发件箱

1. 业务事务同时写入领域状态与 outbox，避免数据库提交后进程退出导致事件丢失。
2. 调度器用数据库原子领取、租约与领取 token，按有界批次处理；任务期间不持有业务事务。
3. 完成写入校验当前 token、状态和租约；租约过期后的旧执行者不能提交投影。需要长任务时续租并分片。
4. 消费者用 `(consumer_name, event_id)` 去重，去重记录与投影更新同事务提交。
5. 失败指数退避、有界重试；永久失败进入人工可见状态。模型等外部调用的未知结果单独核对，不能直接重放。

采用至少一次投递＋幂等消费，不承诺跨数据库、缓存与供应商的端到端恰好一次。Redis 可加速通知，任务权威状态仍在 PostgreSQL。

Vercel 调度入口必须认证，允许重复触发和运行重叠；函数有时长限制，调度能力需核对套餐与频率。未建设持久任务执行机制前，不启用依赖它的 AI 批任务。[调度管理说明](https://vercel.com/docs/cron-jobs/manage-cron-jobs)

## 8. 删除、撤权与派生数据清理

- 主事务先撤销可见性、会话或授权并写清理事件，避免因为向量库暂时不可用而继续泄露数据。
- 用户导入或裁剪后的权威几何不按缓存 TTL 清理；回收前检查本人当前方案、有效修订、已受理任务和独立派生副本的引用。源删除不级联删除合法目标内容。
- 后台清理修订正文、计算结果、知识分块、向量、AI 输入/输出引用与对象；失败可重试并可审计。
- 所有读取和检索都重新校验当前删除与权限状态，不能等待向量清理完成才停止返回。
- 已进行的外部出站请求不保证可撤回；尽力取消并按供应商保存政策处理，记录剩余边界。
- 墓碑仅保留去重和防复活所需最小标识；期限确认后清除。备份按确认的到期政策过期，恢复时重放删除/撤权清单，防止已删除内容重新可见。

## 8A. 导入、权益与短信的特殊一致性

- PostgreSQL 与对象存储不构成单一 ACID 事务。先完成私有不可变对象及清单校验，短事务提交引用；失败对象进入孤儿清理，绝不在数据库回滚后删除仍被其他有效修订使用的内容。
- fork 在源权限与删除状态上重新核验并锁定授权，目标只引用本人有权独立保存的资源。源内容读取和目标提交之间的撤权必须被发现；许可快照不等于永久访问凭据。
- 大几何准备阶段固定源版本；同方案裁剪提交检查当前基础版本，冲突时保留预览，不改变原方案。
- 权益限制验证最终聚合内容，而非每次请求片段；到期后不自动裁掉高点数路线。存量减少操作与新建超额副本分别判定。
- 短信验证码消费、号码凭据唯一性和用户创建在受控事务中完成；失败尝试数原子提交，不因返回错误而回滚计数。验证码消费不可作为跨事务重复签发会话的通行证。
- 发送短信是外部副作用；任务幂等与供应商回执降低重复，供应商不支持幂等时不承诺端到端恰好一次。发送结果未知先核对，不无限重发。

详细边界见 [路线导入与派生操作设计](路线导入与派生操作设计.md)和 [手机号登录与UGC治理设计](手机号登录与UGC治理设计.md)。

## 9. 必须执行的独立验收

| 场景 | 验收结果 |
| --- | --- |
| 两个设备用相同基础版本保存 | 恰有一个成功，另一个冲突；控制点与修订无混合版本 |
| 提交成功但响应丢失 | 同幂等键可查询原版本，不重复创建或递增 |
| 相同幂等键携带不同内容 | 拒绝，不改变业务数据 |
| 更新根后、写子表前异常 | 全事务回滚；不会出现空路线或多版本拼接 |
| 离线编辑遇到云端删除 | 本机内容仍可另存，云端删除不被自动复活 |
| 用户 A 读取/修改用户 B 的标识 | 全部拒绝，包括任务、回执、AI 和知识检索 |
| Redis 故障 | 本机编辑可用，云保存不依赖缓存，高成本外部请求保守失败 |
| Redis 切换丢计数 | 严格预算仍由持久预留保护；未具备时不开对应能力 |
| 重复发件箱消息、调度重叠、任务租约过期 | 消费去重，旧 worker 完成被拒，状态不回退 |
| 旧算路/AI 结果迟到 | 可供查看但不覆盖新控制点或自动应用 |
| 数据库主故障切换 | 验证实际 RPO、旧主隔离和确认写入行为，记录不能保证的边界 |
| 从备份恢复 | 记录实际 RTO/RPO，核对删除清单、权限和派生重建 |
| 文件/链接/文本解析成功但未确认 | 只产生候选，不覆盖或新建正式路线 |
| 重复确认候选、复制回执丢失 | 同键/同候选返回原方案，显式新复制才生成新 ID |
| 几何对象已上传但事务失败 | 源方案不变，孤儿可回收，其他有效引用不受影响 |
| 源更新/删除/撤权与 fork 并发 | 不读取漂移的最新版本；撤权提交前被发现；合法目标自有内容独立 |
| 块边界、边内、自交、闭环与中段裁剪 | 原始顺序可重现，无隐式直线连接或指标沿用 |
| 会员到期、超额复制、分批追加 | 旧内容不丢失；新增操作不能绕过当前权益与技术上限 |
