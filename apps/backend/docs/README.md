# Roadbook Web 服务端与数据架构文档

更新日期：2026-10-09。

本目录保存 Roadbook Web 的服务端与数据架构方案。文档放在 `apps/backend/docs` 是本次指定的归档位置，不表示必须部署现有 NestJS 应用。

## 1. 适用范围与状态

- 仅考虑 Web，不包含小程序适配、微信小程序登录或跨端共享改造。
- 推荐运行架构：Next.js 页面与服务端 API 部署到 Vercel，连接托管 PostgreSQL 和 Redis。
- 采用模块化单体与 DDD 分层，按限界上下文组织能力；暂不拆微服务。
- 本次交付是可评审的设计方案，尚未修改 Prisma schema、生成迁移、安装依赖、开通资源或执行部署。
- 云端账户与同步属于当前本机版 MVP 之外的新阶段；本方案描述推进方向，不改变现有产品行为。
- 后续设计已纳入文件/链接/文本导入、保存、复制、fork、自由裁剪；会员放开当前 20 点业务限制；手机号短信登录与 UGC/AI 数据治理。
- 供应商、登录方式、预算、数据保留期、备份目标仍需在对应阶段确认。

## 3. 文档使用规则

1. 表名、字段与接口均为拟议设计；以阶段验收后的代码和正式迁移确认实施状态。
2. 每个领域表由所属上下文负责写入；跨上下文通过应用用例、只读接口或领域事件协作。
3. 不以“支持 CAP”承诺三项同时成立；按操作说明分区期间的行为。
4. 不将 Redis、向量索引或大模型输出作为用户路线的权威数据源。
5. 后续实施须同步记录实际迁移、验证证据和剩余边界；涉及 Web 行为时按 Web 规范补充迭代记录。
6. 新增表与迁移必须遵守数据库规范：每环境一个 Web 业务库，库内按上下文分 schema；物理拆库、分区和分片须有证据与独立决策。

### 2026-10-09 补充决策

- 用户确认文件、链接、文本三种输入均需要；统一使用原始资产、解析任务、候选与明确确认协议。
- 用户路线支持保存、复制、fork 与自由裁剪；权威轨迹和供应商算路投影分开，血缘固定到版本。
- 用户要求未来将放开当前 20 控制点限制作为会员功能；数据库序号不写死 20，业务权益与技术硬上限分离，到期不截断存量内容。
- 用户提出未来短信与手机号登录；用户主键稳定，号码凭据单独管理，UGC/会员随 user_id 关联。
- UGC 可为 AI 提供结构化事实、来源与反馈，但公开、推理/检索、评估和训练分别治理，手机号不进入模型数据。
- 数据库规则落为专项规范：46 张拟议逻辑表归属明确，按阶段建表；同库跨 schema 保留必要事务，拆库、分区与分片须通过准入评审。
